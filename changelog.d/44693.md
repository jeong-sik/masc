### Fixed
- A keeper guest that the container runtime could not describe is no longer treated as gone. `container inspect` exits 1 both for a missing name and for an apiserver stall (`XPC timeout`), so after a restart a running microVM guest could be force-deleted or have its credential copy released. The probe now confirms absence with the runtime's own listing and returns an unknown-state error when the listing fails too; the check right after a microVM boot and after `docker run` uses the same rule and keeps the guest or container on an unknown answer. (#44693)
