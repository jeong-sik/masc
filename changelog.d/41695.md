### Fixed

- Keeper chat streams keep buffered events ahead of newly arriving live events
  when acceptance and operation execution run on separate domains. Closed
  subscriptions drop pending and late callbacks without holding a state mutex
  during transport writes. (#41695)
- Keeper chat streams isolate live subscribers and terminal accounting by
  canonical runtime base, Keeper and request ID, so reusing an ID in another
  Keeper or runtime cannot mix their direct-operation events. (#41695)
