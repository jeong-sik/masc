### Fixed

- `masc_keeper_clear` on a Keeper whose checkpoint cannot be read (a parse
  error, a later-version file, or a read error) now moves the file aside to
  `<checkpoint>.unreadable-<epoch ms>` in the same directory, under the
  checkpoint session lock, and clears as usual; the result names the archive
  path. Before, the clear refused and the only way out was deleting the file
  by hand. An unreadable checkpoint still fails the turn (#38476).
