# Board 삭제 결정과 재시작 복구

원래 삭제 대상을 기록한 뒤 글·댓글·투표·리액션을 저장하고, 네 쓰기가 확인된 뒤 결정 파일을 정리합니다. 복구는 원래 글·댓글 ID만 제거하며 나중에 다른 writer가 추가한 댓글과 그 표·리액션은 보존합니다. 부모가 달라진 원래 댓글 ID는 변경 전에 거절합니다.

소스 기준은 lower `06489cbc5c038a98f87548a4314bfa56d71c4886`, 사례를 추가한 upper `2e3ce7e7f1fd0fa68da89f91ae8b9beaaa0ffc49`입니다. base는 `d0c7affcf6c564b550c1897d921a524527dfe58d`입니다. 이 기록 이후의 evidence-only commit은 소스 기준이 아닙니다.

## 실제 실행

- 새 응답을 기존 코드에 전달한 두 프런트 회귀가 실패했습니다. API는 `applied=false/decision_pending`을 거절했고 화면은 삭제 성공을 발표했습니다. [선택한 실패 단언](baseline-failure.txt)은 경로를 가린 파생본이며 원본 로그의 해시는 보존했습니다. 최초 의존성 부재 실패와 구분합니다.
- 수정한 API와 BoardSurface의 두 파일에서 **88/88**이 통과했습니다. 결정이 불확실할 때 경고하고 선택·상세·행을 유지하며 성공 갱신을 하지 않는 흐름과 모순된 응답 거절을 포함합니다.
- 설정된 Dashboard `pnpm exec tsc --noEmit`과 변경한 네 TS 파일의 ESLint는 exit 0입니다.
- 변경한 OCaml 29개 입력은 5.5.1에서 **구문 검사만** 통과했습니다. 저장소 목표는 5.5.2입니다. 38개 store 필드의 ML/MLI 이름·순서와 immutable IO 슬롯 6개를 대조했습니다.

[검사 입력·명령·결과](validation.json)에 파일별 해시를 보존했습니다. 검사는 커밋 전 같은 바이트에서 실행했고 기록한 소스 커밋과 다시 대조했습니다.

## 작성했지만 실행하지 않은 범위

새 실제 파일 기반 백엔드 사례 **8개는 실행 0개**입니다. 초기 결정 쓰기와 정리의 unknown, known 성공 뒤 reserved cleanup, 마지막 데이터 파일 정리 실패, 결정 정리 후 새 hearth 해제를 단일 flush로 저장하는 경계, 잘못된 결정 파일, 다른 부모로 관측된 댓글을 다룹니다. 기존 회귀는 원래 결정 복구와 나중에 생긴 foreign orphan·인덱스·표·리액션 보존에 맞췄습니다.

두 로컬 독립 소스 리뷰에서 찾은 flush 누락과 잘못된 공개 API 호출은 고쳤습니다. 이 읽기 결과는 정식 GitHub 승인이나 타입·실행 성공이 아닙니다. Dune·OCaml 타입/경고·백엔드·서버 통합·CI·설치·배포는 미실행이며 삭제 pending의 브라우저 관찰도 없습니다.

[루트 #26378](https://github.com/jeong-sik/masc/issues/26378)은 계속 열어 둡니다. 부모·정책 read-set 일관성과 별도 sub-board/hearth 중단 복구는 이 기록으로 완료되지 않습니다.
