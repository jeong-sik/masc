### Changed

- A Muse Code Keeper under `native = "none"` or `"read"` approves MASC's
  tools only. The session selects `promptUnmatched`, and MASC answers each
  approval the host raises itself: a tool call named exactly like one of the
  session's MASC tools (`mcp__masc__<tool>`, from the list the MCP bridge
  serves) is allowed once, and every other call is rejected with a short
  reason; a rejection declines only that call. MASC never picks a choice that
  saves a rule in the operator's Muse Code files. `muse serve` also starts
  with `--disable-write --disable-shell`, which leave the tools in the
  model's list. `none` no longer fails as config, and the start prompt
  states the posture. A read the host's own profile allows still runs
  without asking MASC (`:unrestricted` let `read_file` read outside the
  workspace root), so Muse Code must not be assigned to a Keeper or fusion
  panel until that gap is closed. A
  `microvm` or `remote_ssh` Keeper's session works in its own private
  directory, `<base>/.masc/official-clients/muse/workspaces/<keeper>`, instead
  of the host bookkeeping bundle. Every spawn sets `MUSE_NO_AUTO_UPDATE=1` so
  the launcher does not replace the binary in the background (#39354).
