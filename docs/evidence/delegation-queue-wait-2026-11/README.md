## 이 숫자가 말하지 않는 것

- 집어 들기 재생은 상한이에요. 대상이 도착한 연산을 돌아온 도구 결과 뒤에 바로 시작한다고 가정했고, 지금 코드는 그렇게 하지 않아요. #48959 는 큐에 도착한 행을 도구 결과 뒤 요청에 보여 주기만 하고, 행은 큐에 남아 턴이 끝난 뒤 시작해요.
- 위임 연산은 대상 owner 의 `operations` 큐에 들어가요(`Keeper_owner.submit_operation`). #48959 가 보여 주는 stimulus 큐 행으로는 들어가지 않는 것으로 보여요. 위임 505개 중 대상의 reaction ledger 에 제출 시각 앞뒤 3초 안에 도착한 stimulus 가 있는 것은 3개이고 모두 `schedule_due` 예요. 연산 id 나 발신자를 담은 행은 0개예요. 코드 경로는 따로 읽지 않았어요(스크립트 밖에서 센 값).
- 줄어드는 것은 맡긴 쪽이 기다리는 시간이에요. 대상이 같은 일을 턴 안에서 하면 대상이 하던 일이 그만큼 늦어져요. 일의 총량은 줄지 않아요.
- 제출자가 표지를 보고 행동을 바꾸는지는 못 쟀어요. 바꾸지 않으면 표지는 대기를 줄이지 않아요. 배포 뒤에 같은 스크립트 틀로 `target_turn_age_s` 가 있는 제출 결과 다음의 `masc_keeper_delegate_cancel`·다른 대상 위임·상태 조회 비율을 재야 해요.
- 재생한 턴 구간은 첫 도구 호출 앞과 마지막 도구 호출 뒤의 모델 시간을 빼서 런타임이 보는 턴보다 짧아요. 런타임 표지의 재현율은 재생값 이상이에요. 정밀도는 어느 쪽으로도 움직일 수 있어요.
