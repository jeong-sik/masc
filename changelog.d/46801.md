### Changed

- The `m` memory recall form on Config > runtime.toml starts from the Keeper list a hand-switched-off file keeps (`memory_recall = false` with `memory_recall_scope` and `memory_recall_keepers` still in it), so switching recall back on writes the switch line alone. A key that already holds the chosen value is not rewritten, which keeps the comment on its line, and the same Keepers in another order count as no change. The form shows one line for what saving does (names added and dropped, a list that stays with off, a list that goes with all, or nothing) and marks a Keeper that is paused or missing from the roster. `Runtime_toml.memory_recall_declaration_of_string` returns the switch and the scope apart for this (#46801). Guide: `docs/guides/keeper-memory-recall.md`, section "From the TUI".
