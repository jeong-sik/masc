### Changed
- The keeper profile snapshot (read by the 2-second dashboard light shell, `/health` fleet, the declared roster and continuation wake) is parsed again only when a keeper TOML file is added, removed, or changes size or mtime; on a 34-keeper fleet copy a light build went from about 13 ms / 6.4 MB to about 6.5 ms / 2.05 MB. A snapshot that holds a read failure is not kept, so a transient I/O error clears on the next read. `invalidate_keeper_profile_defaults_cache` is now `invalidate_keeper_profile_snapshots`, and the per-name profile defaults cache, which no production path reached, is removed.
