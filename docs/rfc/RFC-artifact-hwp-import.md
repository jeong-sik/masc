# HWP 파일을 수동 변환 없이 편집 원고로 가져온다

상태: 구현. Task: `task-3694`. 기반: 병합된 Office 왕복 변환 #52514.

## 입력과 결과

사용자가 기존 HWP5 파일 하나를 선택하면 브라우저에서 읽고 HTML 원고를 만든다.
이후 확인·게시·표 셀과 차트 데이터 편집·HWPX/DOCX 출력은 기존 경로를 쓴다.
사용자에게 한글에서 파일 형식을 바꾸도록 요구하지 않는다.
HTML 원문이 편집 내용의 정본이며 별도의 수정 가능한 문서 저장소는 만들지 않는다.

재출력 형식은 HWPX/DOCX다. HWP3와 암호 문서는 이 변경의 입력 범위에
들어가지 않는다. 지원하지 않는 입력은 파일을 읽는 단계에서 오류로 돌려준다.
원본 파일은 읽기만 한다.

## 선택한 경로

```text
HWP5 bytes → 컨테이너·압축 입력 검사 → RHWP worker
  → HWPX bytes + 내용 손실 보고서
  → 기존 HWPX importer
    → 본문·표·그림
    → OLE의 OOXMLChartContents → 기존 Office 차트 reader
  → HTML 편집 원고 → 기존 확인·게시·편집·내보내기
```

1. 공식 `@rhwp/core@0.9.0`을 고정해 재사용한다. WASM은 HWP를 선택한 뒤
   전용 worker에서 읽는다. 로컬의 오래된 `pkg`나 새 자체 HWP parser로
   대체하지 않는다. worker를 닫으면 문서·WASM 메모리를 해제한다.
2. CFB는 물리 연결을 한 번 읽은 결과에서 필요한 stream만 복사한다.
   `cfb@1.2.2`의 손상 FAT 무한 순회를 재현했고, 정상 역순 FAT에서도
   이미 읽은 꼬리를 반복 복사하는 경로를 확인했다. 그 reader 앞에 제한값을
   더하지 않고, 검사한 FAT·MiniFAT·directory를 읽기의 정본으로 사용한다.
   패키지는 독립 테스트 입력의 writer로만 남긴다.
   원래 상대경로를 보존하고, 이름 조회와 충돌 검사는 같은 CFB 이름 index를
   쓴다. 이름 길이와 UTF-16 단위별 단순 대문자 규칙으로 대소문자를 비교한다.
   파일의 `FileHeader` stream에서 HWP
   서명·버전·속성을 읽는다. CFB 첫 바이트에 HWP 서명이 있다고 가정하지 않는다.
   암호와 배포 속성을 확인한다. 압축은 문서와 BinData 각각의 속성을 따른다.
3. 기존 Office 입력 32 MiB, 파트 16 MiB, 전체 확장 64 MiB 경계를 공유한다.
   WASM에 주기 전 압축 stream을 작은 단위로 읽어 확장 크기를 확인한다.
   CFB에서 반환할 stream 바이트와 전체 경로의 UTF-16 바이트도 합산한다.
   같은 전체 64 MiB 한도를 넘으면 경로를 합치거나 stream을 할당하기 전에 거부한다.
   문서 깊이를 임의 숫자로 자르지 않는다.
   알 수 없는 압축 속성, 잘못된 stream 참조와 손상된 컨테이너는 거부한다.
4. `exportHwpxWithReport`의 보고서를 bytes와 같은 결과로 읽는다.
   이 보고서는 모델을 직렬화한 결과이며 원본 parser의 손실을 증명하지 않는다.
   원본의 control 종류·본문 소속·UTF-16·제어 문자 참조를 먼저 읽는다.
   기존 HTML 소비자가 옮기지 못하는 요소도 오류로 끝낸다.
   표의 행·열 수도 기존 `hwpxTableLimits`로 WASM 전에 확인한다.
   후단이 거부할 표의 셀 범위를 Core가 먼저 펼치지 않게 한다.
   Core의 격자 할당 크기는 원본 보존 한도가 아니므로 표 면적 제한으로 쓰지 않는다.
   Core가 문단 하위 트리를 생략하는 실제 경계인 동시 문단 조상 64개를
   넘는 입력은 WASM 전에 거부한다. record level이나 전체 표 개수와는 다르다.
   내용 손실을 확인한 문서는 편집 원고로 만들지 않는다. 모르는 보고서도
   손실 없음으로 간주하지 않는다. 페이지·글꼴 차이는 기존 가져오기 안내로 알린다.
5. HWPX importer는 OLE bytes를 명시적으로 해석하는 작은 callback을 받는다.
   일반 HWPX/DOCX 가져오기의 OLE 정책은 자동으로 넓히지 않는다.
   HWP adapter는 CFB의 `OOXMLChartContents`만 표준 차트로 읽는다.
   종류·방향·축·숫자·서식·결측치·외부 참조는 기존 reader가 판정한다.
   지원하지 않는 OLE와 구형 차트는 그림이나 빈 문자열로 바꾸지 않는다.
6. 각 읽기 요청은 현재 문서·작업 공간에 묶는다. 새 파일을 선택하거나
   화면을 닫으면 이전 worker를 종료한다. 끝난 이전 요청이 새 원고를
   덮어쓰거나 게시할 수 없다. 실패는 이전 원고를 없애지 않는다.
   읽는 중에는 화면을 유지한 채 `가져오기 취소`를 누를 수 있다.
   취소와 닫기는 그 자리에서 요청을 무효화하고 worker를 종료한다.
   선택한 파일을 고정한 뒤 파일 입력을 비워 같은 파일을 다시 선택할 수 있게 한다.
   파일 바이트가 늦게 도착해도 취소한 요청으로 변환을 시작하지 않는다.
   HWP 읽기 API는 `AbortSignal`을 필수로 받아 호출자가 수명을 소유한다.
   정상 응답·실패·응답 오류·취소가 worker를 닫는 종단 사건이다.
   경과 시간만으로 정상 문서를 중단하는 임의 시한은 두지 않는다.
   파일·확장 크기 한도는 메모리 입력 경계이며, CPU 시간 한계로 보고하지 않는다.
7. 원본 HWP와 중간 HWPX의 표는 같은 격자 검사 함수를 쓴다.
   행 시작·끝 이벤트와 열 구간으로 겹침을 확인하고, 정수 면적으로 빈 칸을 찾는다.
   행마다 전체 셀을 다시 훑지 않는다. 임의 셀 수 제한은 추가하지 않는다.

## 검증을 먼저 고정한다

- 공개 한글 HWP의 4종 차트와 짝 HWPX를 독립적인 입력·정답지로 사용한다.
  종류·제목·항목·계열·숫자·숫자 형식·결측치 표시를 모두 비교한다.
- 실제 HWP의 표를 읽어 셀 내용·행/열 좌표·rowspan/colspan을 대조한다.
  표 전후 문장과 중첩 표, 빈 셀도 확인한다.
- HWP 가져오기 → 셀·차트 값 수정 → HWPX와 DOCX 출력 → 재가져오기에서
  수정한 값을 비교한다. 지원하지 않는 개체와 손상·암호 입력은 실패해야 한다.
- 실제 npm 패키지와 WASM으로 실행한다. worker mock 시험은 취소와 화면
  동작만 증명하며, 실제 변환 시험을 대신하지 않는다.
- 실제 브라우저 다운로드와 한컴·Word 화면은 별도 증거다. 자체 parser의
  왕복이나 데이터 일치를 전체 문서의 화면 충실도로 보고하지 않는다.
