### Fixed

- `masc_keeper_clear` on a Keeper whose checkpoint cannot be read (a parse
  error, a later-version file, or a file that is not a regular file) now
  moves the file aside to `<checkpoint>.unreadable-<epoch ms>` in the same
  directory, under the checkpoint session lock, and clears as usual; the
  result names the archive path. Before, the clear refused and the only way
  out was deleting the file by hand. An unreadable checkpoint still fails the
  turn (#38476).
- A checkpoint read that fails at the OS level (an open or read syscall, or
  the file changing during the read) is now its own `Read_failed` load error
  carrying the errno, and `masc_keeper_clear` refuses it without moving
  anything, since it says nothing about the bytes (#38476).
