# 가져온 문서의 표 너비와 화면 편집을 보존한다

상태: 구현 설계. Task: `task-3698`. 기준: `277c8f55816d`.

## 문제

공개 `table-001.hwp`의 첫 셀 너비는 14774 HWPUNIT이다.
공식 Core가 만든 HWPX에도 같은 값이 있다. 현재 HTML 가져오기는
너비를 버린다. DOCX 출력은 9개 열을 같은 폭으로 만든다.
131개 셀과 병합은 남지만, 첫 열이 좁아져 글이 여러 줄로 꺾인다.

게시된 문서에는 화면에서 글과 셀 값을 고치는 편집기가 있다.
가져온 초안과 일반 편집은 HTML 원문만 보여 준다. 공동 편집기는
텍스트 조각마다 원고 전체를 검사해 큰 원고에서 같은 작업을 반복한다.

## 정본과 단위

기존 HTML 원고를 정본으로 둔다. 너비는 표·셀의 표준 HTML `style`
속성과 `colgroup/col`에 쓴다. HWPUNIT은 1/100pt, twip은 1/20pt다.
HWPX의 정수 너비는 소수 pt로 손실 없이 표현한다.
CSS 선언은 CSS 파서로 읽는다. 문자열 부분 일치로 선언을 찾지 않는다.
HTML에서 파생한 배치 정보는 변환 호출 안에서만 쓴다.

HWPX 셀 너비는 해당 셀이 차지한 열 구간의 길이다. 표 전체 크기와
개별 셀의 크기를 각각 보존한다. DOCX의 명시적 `tblGrid/gridCol`과
셀의 `tcW`, 표의 `tblW`는 서로 다른 선호 너비다. 자동 배치가 계산한
최종 화면의 경계와 같다고 가정하지 않는다.

## 확정된 열과 확정되지 않은 열

너비를 미지정·절대값·백분율·자동 배치로 구분한다. 지원하지 않는
CSS 값은 정확한 값처럼 해석하지 않고 출력 차이를 알린다.
명시적 열 너비와 셀의 구간 너비로 열 경계 차이를 계산한다.
모든 경계가 유일하게 정해질 때만 확정된 열 너비를 사용한다.

여러 열이 항상 함께 병합돼 있으면 내부 경계는 알 수 없을 수 있다.
셀의 합계 너비는 남기고 내부 열은 미확정으로 둔다. 글자 수나
동일 분배로 원본 열 너비를 추측하지 않는다. 서로 모순된 선호 너비도
자동 배치와 구분한다. 기존에 읽던 문서를 폭이 모호하다는 이유로
거부하지 않는다. 출력에서 사용한 배치와 정확히 보존한 값을 구분한다.

OOXML이 정한 생략값은 읽는다. `w:w` 생략은 0, `w:type` 생략은
`dxa`다. 0은 양의 고정 격자로 강제하지 않는다. Word의 선호값은
유지하고 실제 배치는 자동으로 계산한다. HWPX는 양의 배치 너비를 쓴다.

DOCX의 확정된 격자는 누적 경계를 twip으로 반올림한 뒤 차이를 낸다.
표·열·병합 셀의 합이 같아야 한다. twip으로 표현할 수 없는 좁은 열은
임의로 늘리지 않고 출력 오류로 알린다. 원고는 그대로 남는다.
페이지 폭에 맞춰 늘리지 않고 명시적 폭을 쓴다.
미지정 너비에는 기존 기본 배치를 쓴다. 중첩 표는 부모 셀 안에서 배치한다.

HWPX는 정수 HWPUNIT을 쓴다. DOCX의 정수 twip을 다시 곱해 원본
너비를 복원하지 않는다. Word 블록을 만들 때 표·셀·중첩 블록의 작은
타입 구조도 함께 만든다. HWPX는 생성된 DOCX의 구조와 이 구조를
함께 확인한 뒤 원본 단위의 너비를 사용한다. 평면 인덱스로 표를
연결하지 않는다. 구조가 다르면 출력 오류로 끝난다.
문단·차트·그림은 기존 DOCX 어댑터를 계속 쓴다.
DOCX를 중간 경로로 쓰므로 HWPX도 한 twip보다 좁아 반올림하면
0이 되는 양의 열은 출력할 수 없다. 임의로 열을 넓히지 않는다.
지원하는 native Core가 너비를 `u32`로 읽으므로 HWPX 출력은 해당
32비트 범위를 확인한다. 범위를 넘겨 0으로 바뀌는 파일을 내주지 않는다.
종이·문단을 기준으로 한 HWPX 상대 표 너비와 셀 간격은 셀의 절대
너비와 출력 기본 배치로 옮기며 차이를 알린다.

## 초안의 화면 편집

HTML 초안은 기존 미리보기의 텍스트 선택과 escape를 재사용한다.
원문 보기로도 전환할 수 있다. 선택한 글·빈 셀·차트 숫자만 치환한다.
DOM 전체를 직렬화하지 않는다. 병합·너비·차트 속성은 그대로 둔다.
수정한 차트는 원래 숫자 검사로 읽는다. 빈값과 0을 구분한다.

사용자가 반영하기 전 입력은 선택 폼의 임시 상태다. 원고와 따로
자동 게시하지 않는다. 기존 초안 보관 경로에 선택 범위·예상 텍스트·
입력을 같이 남긴다. 형식·작업 공간·선택 시점이 바뀐 뒤에는 오래된
범위를 다른 셀에 적용하지 않는다. 보관된 미반영 입력도 읽고
다운로드할 수 있어야 한다. 게시 요청에는 이 UI 상태를 넣지 않는다.

공동 편집의 상대 선택은 한 동기 호출에서 문서를 한 번 검사한 뒤
모두 만든다. 외부에서 바꿀 수 있는 `Y.Doc`의 검사를 생략하거나
검사 결과를 캐시하지 않는다. 클릭 시 현재 offset으로 선택을 새로
만드는 방법은 동시 편집에서 다른 글을 고를 수 있어 사용하지 않는다.

## 반복 비용

HWPX 출력은 행마다 모든 셀을 다시 찾지 않는다. DOCX 가져오기는
행마다 지난 행 전체를 다시 훑지 않고 진행 중인 병합 범위만 쓴다.
차트 워크북의 행도 한 번 인덱싱한다. 파일별 Worker 격리와 명시적
취소를 유지한다. Worker 재사용·캐시·임의 시간 제한은 추가하지 않는다.

성능은 같은 입력·런타임에서 준비 실행 후 반복 표본과 중앙값을
남긴다. 합성 원고의 CPU 측정과 실제 브라우저의 변환·렌더 시간을
구분한다. 측정하지 않은 전체 속도나 호환성 비율은 쓰지 않는다.

## 확인할 동작

- 공개 HWP의 원본 필드 → Core HWPX → HTML → 두 출력의 셀·병합·폭을 비교한다.
- 불균등한 열, 모든 행의 병합, 일부 너비만 있는 표, 모순된 선호 폭,
  백분율·자동 폭, 중첩 표와 twip 반올림 경계를 확인한다.
- 같은 HWPX를 여러 번 왕복해 명시적 HWPUNIT 너비가 누적 변하지 않는지 본다.
- 가져온 표의 빈 셀·차트 4종의 값·결측치를 화면에서 고친 뒤 다시 읽는다.
  `<`와 `&`, 잘못된 숫자, 오래된 선택, 원고 소유권 변경을 확인한다.
- 실제 Chromium의 편집·다운로드와 독립 LibreOffice의 PDF를 확인한다.
  자체 파서 성공을 한글·Microsoft Word의 화면 검증으로 쓰지 않는다.

이 작업은 표 너비와 값 편집을 개선한다. 원본의 행 높이·셀 여백·
글꼴·페이지·머리말·도형을 모두 복원하거나 HWP 바이너리를 출력하는
작업은 아니다. HWP5 읽기와 HWPX/DOCX 출력의 기존 범위를 유지한다.
