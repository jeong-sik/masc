### Fixed

- A settled Keeper execution no longer keeps retained checkpoint files alive. A server restart or an Owner stop settles a native call and leaves its unacknowledged terminal receipt on the immutable settled row, and that receipt kept naming the call's seed and latest checkpoint, so neither a commit's release nor the startup sweep ever removed them: on 2026-10-30, 45 such rows held 90 files and 1.18 GB, all in checkpoint versions the current code cannot read. A settled record now names no checkpoint and is no longer outstanding, so shutdown reconciliation and journal preparation stop treating it as unfinished work. The receipt still records the call's identity (#44233, #46826, #46906).
