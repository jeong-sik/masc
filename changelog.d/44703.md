### Fixed

- A `BrowserGoto` call on an owned browser no longer fails output validation after the navigation has happened: the declared output now accepts the `lane`, `clientId`, `browserSelection`, `browserCapabilities` and `requiredActions` fields that every owned-browser answer carries, so compositions that navigate no longer stop with `effect_outcome_unknown`. (#44703)
- The `browser-navigate-read` composition now names the automation lane in its `BrowserGoto` node. Before, that first node was refused with `browser_binding_required` because a navigation of an observed tab needs its browser named, so the composition never reached the read. (#44703)
