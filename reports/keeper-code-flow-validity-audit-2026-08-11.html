완결성은 마지막 1미터에서 깨진다.

MASC Keeper의 부팅부터 Owner admission, durable stimulus, Runtime routing, 모델·도구 루프, Gate, checkpoint, receipt, source ACK까지 실제 호출 순서로 추적했다. 결론은 핵심 해피패스는 조건부로 충분하지만, connector continuation 자동 전달과 Runtime 설정의 한 실행 의미가 닫히지 않았다는 것이다.

2. 핵심 발견

P1

Continuation 최종 전달이 배선되지 않았다

Hitl_resolved, Fusion_completed, Connector_attention의 channel은 turn/tool context까지 간다. 그러나 finalize_response의 두 continuation 인자는 사용되지 않고 success handler에도 outbound delivery가 없다.

  • 모델이 surface_post를 선택하면 보낼 수 있음
  • 모델이 선택하지 않아도 최종 답이 자동 전달되는 계약은 없음
  • OpenClaw의 명시적 deliver + channel + to와 대비됨
P1

하나의 runtime.toml이 두 가지 reload 의미를 가진다

Dashboard raw save는 Runtime.save_config_text로 [runtime] 상태를 원자 교체하고 응답에 reloaded=true를 준다. 하지만 [turn], [heartbeat] 등 Keeper overlay는 부팅 때만 적용되고 일부 값은 frozen이다.

  • 같은 저장 요청에서 routing은 즉시 변함
  • stream/provider timeout 등은 재시작 전 변하지 않음
  • API 응답만 보면 이 차이를 알 수 없음
P1

“모든 MASC_KEEPER_*는 TOML 가능” 선언이 거짓이다

env_config_keeper.ml:1-9의 계약과 달리, 같은 모듈의 Keeper env 키 중 25개가 key_to_env에 없다. body timeout, Memory OS, media, vision, wire-capture retention 등이 대표적이다.

  • 알 수 없는 overlay 키는 조용히 무시됨
  • .mli 예시는 이미 제거됐다는 concurrency 키를 계속 제시
  • 오타와 미지원 설정을 구별할 수 없음
P2

Direct와 autonomous는 core만 공유하고 orchestration은 중복이다

둘 다 Keeper_agent_run.run_turn을 호출하지만 direct 경로는 FSM, runtime retry, lifecycle, meta commit, metrics, reply JSON을 별도로 조립한다. “Identical implementation”은 달성되지 않았고 앞으로도 drift 비용이 남는다.

P2

실제 live config가 최신 코드 능력을 억제한다

현재 코드는 winning runtime에서 checkpoint owner를 가져오고 mixed-owner lane 테스트도 허용한다. 그러나 live config 주석은 이전 결함을 현재 사실로 설명하며 Codex/Claude/Antigravity lane을 단일 후보로 축소했다.

  • 코드 fix: 4daffd8a37
  • live config 설명·가용성은 그 이전 상태
  • /api/v1/runtime/resolved가 200으로 단일-slot lane과 explicit assignment의 실제 투영을 확인
P2

관측성 receipt가 실행 성공을 실패로 바꾼다

provider/tool/checkpoint가 성공해도 execution receipt append가 실패하면 최종 turn 결과가 error가 된다. 책임성에는 유리하지만 source ACK가 보류되고 재개 비용이 생긴다. 일반 harness의 best-effort telemetry보다 강한 계약이므로 운영 가치를 명시적으로 정당화해야 한다.

P2

Schedule은 delivery 좌표가 없다

scheduled_wake에는 title/message는 있지만 continuation channel이 없다. heartbeat의 delivery-channel 선택도 HITL/Fusion/Connector만 다룬다. “예약 실행”은 가능하지만 “예약 결과를 지정한 곳에 전달”은 별도 계약이다.

P2

Live fleet는 동작하지만 durable queue가 degraded다

/health?full=1은 동일 commit의 ready server, 실행 가능 Keeper 7개, running 6개와 recovering 1개를 확인했다. 동시에 sangsu의 runnable event 10개가 stale로 남아 overall status가 degraded였다. 이는 happy path 존재와 fleet 전체의 현재 건전성이 같은 명제가 아님을 보여 준다.

9. 권고 순서

P1 · 결과 완결

Delivery intent를 terminal authority로 추가

routable continuation wake가 Completed일 때 {source identity, channel, response digest/text, state}를 내구 commit하고 connector adapter가 Pending→Attempting→Delivered|Failed|Ambiguous를 소유하게 한다. delivery 성공 전 source ACK 여부는 producer별 계약으로 명시한다.

P1 · 설정 정직성

한 파일의 reload 의미를 둘로 보이지 않게

raw config save 응답에 runtime_routes_reloaded와 keeper_overlay_restart_required를 분리하거나, Keeper overlay까지 atomic hot reload한다. 현재처럼 전체를 reloaded=true로 표현하지 않는다.

P1 · schema

Keeper overlay registry를 생성형 SSOT로

key, env, type, range, default, reload class, consumer를 한 typed registry에서 만들고 docs/schema/UI/tests를 생성한다. unknown/retired key는 save·boot에서 거부한다.

P2 · 중복 축소

Direct와 autonomous의 terminal pipeline 합치기

surface adapter는 input/stream/output routing만 소유하고, phase gate→runtime→agent run→lifecycle→terminal commit은 한 함수로 수렴시킨다. “같은 FSM event를 복제”하는 방식은 identical behavior를 장기 보장하지 못한다.

P2 · 가용성

live lane을 최신 checkpoint-owner 계약으로 재평가

4daffd8a37 이후 mixed-owner fallback이 실제 winner authority를 반환한다. live config의 단일-slot 임시 완화와 주석을 새 테스트·boot validation 기준으로 갱신한다.

P2 · 증거 계층

관측 projection의 실패 등급 명시

어떤 evidence write가 product success를 막아야 하는지 결정한다. receipt가 필수라면 checkpoint/source ACK와 같은 owner transaction 관계를 문서화하고, 아니라면 best-effort + explicit coverage gap으로 낮춘다.
