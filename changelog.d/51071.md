### Changed

- A server now boots an installation activated for multi-account use (masc
  auth bootstrap) instead of stopping: it runs the account server, which
  serves its own route table. The table holds GET /health alone, answered
  with the server name, the release version and the account mode. Every
  route of the single-user server is a 404 on that installation, and its
  owner state and Keepers are not started, so an installation that ran
  Keepers as a single user stops running them once it is activated. An
  installation whose external store does not confirm the authorization log
  still stops at boot, and the stdio runtime refuses an activated
  installation (#51071).
