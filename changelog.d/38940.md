### Changed

- One provider overload condition (HTTP 529, `CapacityExhausted`) now has one
  name. The receipt `fallback_reason`, the deferred lane suffix, the runtime
  blocker class, the event error `variant` and the terminal reason code
  (`provider_error_provider_capacity:<scope>`) all say `provider_capacity`,
  the name the failure route already used; the wire value
  `capacity_backpressure` is gone. The blocker summary no longer mentions
  client capacity, and the uncalled `blocker_class_of_core_error` is removed
  (#38940).
