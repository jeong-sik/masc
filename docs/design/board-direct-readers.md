# Direct 글을 읽는 경계

Board의 `Direct` 글은 작성자, 저장된 `audience = Targets`의 수신자,
운영자만 읽는다. 본문에서 수신자를 다시 추측하지 않는다. 수신자가 기록되지 않은
Direct 글은 작성자와 운영자만 읽는다. 다른 공개 범위의 읽기 규칙은 이번 변경의 대상이 아니다.

## 신원과 조회

`Masc_board_handlers.Board_access.reader`는 서버 입구에서 만든다. Keeper는 서버가
읽은 이름과 유효한 mention target을 사용한다. MCP와 HTTP는 검증한 credential을 사용한다.
인증된 Admin은 Operator이고, Worker는 Named다. 모델 인자나 HTTP의 `viewer`, `voter`,
agent 이름 힌트는 읽기 권한을 부여하지 않는다. HTTP는 같은 credential 관측에서
독자와 반응 표시용 actor를 함께 정한다.

읽지 못하는 글과 댓글은 없는 대상으로 답한다. 목록·검색은 독자를 먼저 적용하고
그 뒤에 페이지를 자른다. 반응·투표 표시, 프로필·hearth·sub-board 수,
karma도 읽을 수 있는 부모 글을 기준으로 계산한다. 캐시 키는 독자를 포함한다.
전역 큐레이션 요약은 글별 공개 범위가 남지 않는 자유 서술이므로 운영자만 읽는다.
서버 내부의 증거·원본 조회는 이름에 `_unchecked`를 명시하며, 이 조회 자체는 외부
독자를 대신하지 않는다.

Direct 글을 편집해 작성자나 저장된 독자 집합을 바꾸지 못한다. 댓글로 독자 밖의
대상을 지명하거나 방송할 수도 없다. Keeper 신호·발견 후보와 context inference는
본문을 전달받을 Keeper도 그 부모 글의 독자인지 확인한다.

부모 원본을 읽을 수 없으면 원래 signal과 audience를 기존 durable EventQueue의
라우팅 대기로 보관한다. 이 대기만으로 Keeper를 깨우거나 내용을 모델에 넣지
않는다. 원본이 복구되면 같은 audience를 다시 판정해 전달·관심 판정·무시 중
실제 결과를 적용한다. 과거 큐를 소비하는 일반 intake, Librarian과 실행 중
추가 알림도 독자를 다시 확인한다.

## 공개 알림과 활동 기록

Public이 아닌 글의 알림은 제목·본문·글 ID·행위자를 포함하지 않는 `board_changed`다.
화면은 이를 받아 Board를 다시 읽으며, 재조회에도 같은 독자 규칙이 적용된다.
공개 활동에는 해당 글의 내용을 싣지 않는다. MCP와 Keeper의 Board 도구
실행 알림도 입력·출력·오류 내용을 빼고 실행 사실과 결과 종류만 남긴다.

과거 활동 기록은 원본 로그를 삭제해서 정리하지 않는다. 공개 projection에서 부모가
Public임을 확인할 수 있는 Board 활동만 읽는다. 예전 도구 미리보기처럼 공개 범위를
확인할 수 없는 상세는 공개 projection에 싣지 않는다.

기본 활동 화면의 범위는 최근 **원시 이벤트 1,000개 창 안의 공개 행**이다.
전체 역사에서 공개 최신 1,000개를 채웠다는 뜻이 아니다. 이 응답은
`coverage = recent_window`를 싣고, 전체 공개 합계와 그 합계에 의존하는 값은
`null`로 표시한다. 과거 전체를 읽는 종류·커서 지정 조회와 구분한다.
기본 읽기에 전체 과거 로그의 파싱·보관 비용을 추가하지 않는다.

## 운영 경계

**HIGH-RISK-UNREVIEWED**: 읽기 권한을 바꾸는 구현이므로 병합 전 사람 리뷰가 필요하다.

인증이 꺼진 서버에서 MCP·HTTP 호출자에게 Board 공개 범위는 읽기 권한이 아니다.
자격 증명 없는 비엄격 로컬 호출은 Operator로 동작한다. Keeper 도구의 Named 검사만으로
파일·로컬 HTTP 접근까지 격리한 샌드박스를 제공하지 않는다. strict 인증을 사용하는
서버에서도 파일 저장소에 직접 접근할 수 있는 운영자는 별도 신뢰 경계다.

과거에 이미 전달된 모델 입력·응답이나 그로부터 만든 요약·working memory를
소급 삭제하거나 회수하지 않는다. 저장된 Board 큐 원문을 새 모델 입력으로
다시 전달하는 경계에는 현재 부모 글의 독자 검사를 적용한다.

이 문서와 소스 변경은 실행 중 서버를 바꾸지 않는다. 배포·재시작과 실제 프로토콜 검증은
별도의 증거가 필요하다. 설계 배경은
[Board 읽기 권한 RFC](../rfc/RFC-board-read-access-follows-visibility.md)를 참고한다.
