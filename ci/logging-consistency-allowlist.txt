# Logging-consistency allowlist (consumed by scripts/ci/check-logging-consistency.sh)
#
# Each non-comment, non-blank line is a path PREFIX. A logging violation is
# suppressed when its file path starts with one of these prefixes. Use a
# trailing "/" to allowlist a whole directory; use a full filename to
# allowlist one file.
#
# Allowlisting is for logging that CANNOT route through the canonical
# Log.<Module>.{info,warn,error,debug,routine} surface. Every entry below has a
# stated reason. Do not add entries to silence a migrate-able call site — fix
# the call site instead. See docs/LOGGING.md.

# --- The Log system itself ---
# log.ml emits the structured records; it cannot log through itself. Its
# Printf.eprintf calls are the terminal stderr sink + operator warnings for
# unparsable env vars / file-sink rotation failures.
lib/masc_log/

# --- Pre-runtime / low-level filesystem fallback ---
# fs_compat runs below the logging stack (masc_log depends on fs_compat, not the
# reverse). Its eprintf are last-resort diagnostics when even the ring buffer
# may be unavailable.
lib/fs_compat/

# --- Server boot guards + FATAL handlers + CLI subcommands (bin/main_eio.ml) ---
# eprintf here are either (a) pre-Log-init base-path guards ("[FATAL] --base-path
# points to the server's own source repo", "[FATAL] Server refused to start"),
# (b) FATAL exception handlers for Out_of_memory / Stack_overflow that must not
# allocate through the logging stack, or (c) the `login` / `init` CLI
# subcommands whose stderr/stdout is user-facing CLI output, not server logs.
# Ownership failures use Log.startup_console because runtime filtering must not
# suppress diagnostics that explain why initialization stopped.
bin/main_eio.ml

# --- Standalone CLI tools (not the server runtime) ---
# These are one-shot CLI binaries; their stdout/stderr is the tool's user
# interface, not structured server logging.
bin/masc_trace.ml
bin/trace_to_tla.ml
bin/masc_tui_loader.ml
bin/masc_cost.ml
bin/masc_compaction_audit.ml
bin/keeper_feature_proof_report.ml
bin/env_knob_catalog.ml

# --- Dynamic component (runtime variable) ---
# Log.warn ~ctx:context / Log.info ~ctx:context use a runtime-computed component
# string; there is no static module that preserves the per-call value. Migrating
# would drop the dynamic component from operator output.
lib/config_dir_resolver/config_dir_resolver.ml

# --- Runtime-computed component on Log.emit ---
# agent_sdk_log_bridge.ml uses Log.emit with ~module_name:("oas:" ^
# record.module_name) — the component is built at runtime from a per-record
# value, so no static module preserves it. The top-level Log.emit is required
# here to carry the dynamic component string.
# (keeper_event_bridge.ml previously appeared here for ~module_name:"oas:event";
#  that is a static literal and is now the Oas_event module — a module name
#  string may contain a colon even though the OCaml identifier cannot.)
lib/agent_sdk_log_bridge.ml
