# Media preparation for selected Agent Core history

Declared media readers now participate in the history an Agent Core request
actually selects. Fresh Agent Core admission preserves the original goal,
history and checkpoint media until that selection; an early text projection
cannot remove the Stored references before the producer sees them.
Retained host-tool attachments continue to use their separate frozen carrier.

Runtime admission checks the actual projected provider messages. Public build
and resume both wrap the supplied projection with the existing modality scan
and the captured capability contract, including nested tool results on later
requests. A projection-free run still checks its canonical input before agent
creation. Retaining an unsupported original therefore does not authorize sending
it to a text-only model, and validation does not invoke the projection twice.

The request first selects and materializes its canonical range. On the owning
fiber, preparation captures the runtime's modality decision and reads each
selected audio or document identity through the existing producer and Gate.
Identity includes kind, media type, source digest and byte length. Duplicate
references in nested tool results share one preparation. Every outcome is
captured, including pending approvals and unavailable results.

Signed reasoning can require the request builder to compare several argument
representations. These comparisons reuse the prepared readings. They do not
observe a newer approval, invoke a reader, or select a different modality policy.
Selected image references are also captured through the existing projector,
so rebuilding the prefix performs no image-store or vision operation. Current
goal image identities retain eager reading; other history and newly appended
tool images remain store-only. A selected duplicate of a current-goal image
shares its reading, including an older history occurrence of the same MIME and
source. This intentionally changes that historical projection from an unread
reference to the known reading. The actual prefix checks can consequently drop
signed reasoning bound to different bytes. Native continuation resumes have no
eager goal eligibility. If a custom materializer introduces an unprepared source
that requires media projection, projection
returns an error instead of starting another effect.

A later provider request prepares its own selected range. It can observe a
resolved approval or admit a newly appended tool attachment. The producer's
existing original inventory, one-shot grants and dispatch evidence remain the
authority for whether an external invocation is allowed. A new preparation is
not permission to repeat an uncertain invocation.

Success text retains the original request ID, digest and execution ID, matching
the structured reading outcome. Canonical stored history, tool-result identity,
outcome, JSON and text remain intact. Neither reading success nor request
serialization acknowledges a consumer or retires an original. Defining that
consumer lifetime remains separate work.

Native-capable requests do not prepare readings. Completion review continues
through its admitted-evidence projection without calling the history preparation
port. Official-client projections continue using the declared reader's
observation port; existing built-in extraction can still perform I/O. Some resumes
compute context projections without sending history, so activating their common
projection would admit work for unsent attachments.

Validation consists of source review, full-file syntax parsing and authored
regressions for fresh admission and selected sources, new nested tool media,
immutable outcomes, image references, and signed-prefix reconstruction. The tests have not been
executed for this change. Type checking, actual MarkItDown conversion of valid
DOCX files, SSH/microVM execution and installed runtime behavior remain unverified.
The additional runtime regressions use a local HTTP fixture through public run,
continue, build and resume entry points; they are also authored, not executed.
