# TUI 의 모든 화면이 한 가지 틀·키·표기를 쓴다

운영자 요청(2026-11-11): 목록·행·열·여백·테두리가 화면마다 다르다. 한국어와 영어가 섞인다.
날짜·숫자·기호 표기에 규칙이 없다. 화면마다 안으로 들어가는 키가 달라 외울 수 없다.
도움말은 여러 쪽을 넘겨야 한다. 화면이 출렁인다. 바닥부터 다시 짜도 된다.

화면 25장과 소스에서 센 결과는
[감사 문서](../research/2026-11-11-tui-screen-grammar-audit.md)에 있다. 이 RFC 는 그 위에서
규칙을 정한다. wire, 저장 형식, 서버 lifecycle 은 바꾸지 않는다.

## 0. 결정

1. 화면은 줄 수가 고정된 다섯 구역으로 그린다. 본문에 줄을 끼우지 않는다. (§2)
2. 이동 키는 어디서나 같다. 들어가기 `Enter`, 나오기 `Esc`, 옆 항목 `[` `]`, 보기 고르기 `v`,
   다른 화면 `Tab`. 화면은 이 키를 다시 배정하지 못한다. (§3.1)
3. 한 글자로 하는 동작은 일곱 개이고 앱 전체에서 뜻이 같다. 나머지 동작은 `Space` 로 여는
   동작 창에 이름과 함께 나온다. 되돌릴 수 없는 일은 동작 창에만 있다. (§3.2, §3.3)
4. `?` 도움말은 한 화면이다. (§4)
5. 목록은 표 부품 하나, 상세는 속성 부품 하나로 그린다. (§5)
6. 시각·기간·숫자·없는 값은 타입으로 넘기고 한 모듈이 글자로 바꾼다. (§6)
7. 상태는 낱말·기호·색을 한 사전에서 꺼낸다. 화면 글은 설정한 언어 하나로 나온다. (§7)
8. 고른 줄은 새로 읽어도 화면의 같은 줄에 있다. 열 구성은 보는 동안 바뀌지 않는다. (§8)

기존 키 배정과 화면 문구는 지키지 않는다. 옛 키를 받아 주는 호환 경로를 두지 않는다.

## 1. 원인

공용 부품은 이미 있다. 화면 틀(`surface_chrome`), 표(`Masc_tui_table`), 기간(`span_text`),
언어 선택(`ui_text`), 빈 값(`Glyph.no_value`)이 그렇다. 그런데 화면은 이 부품을 거치지 않고도
문자열을 이어 붙여 그릴 수 있다. 그래서 새 화면이나 새 줄이 생길 때마다 형식이 하나씩 늘었다.
감사에서 센 것: 위치 표시 형식 22종, 기간 사다리 10개, 없는 값 표기 13종, `%-Ns` 손 정렬
35곳, 화면마다 다시 정의한 언어 도우미 68개.

키도 같다. 키 표(`masc_tui_keys.ml`)는 화면 아래 안내와 도움말을 만들지만 키를 실제로
받는 dispatcher(`masc_tui.ml`)는 그 표를 읽지 않는다. dispatcher 의 키 갈래는 문자열
리터럴이고(`| Some "…"` 꼴 350개, 하위 처리기의 `| "…"` 꼴이 더 있다) 표의 값을 읽는 곳은
10여 곳이다. 한 화면에서 같은 글자를 두 번 쓰는 것을 막는 장치는 없다. 그 결과 `s`, `p`,
`v`, `x`, `c`, `a` 를 비롯한 스무 글자가 세 가지 넘는 뜻을 갖는다. 키퍼 화면의 `s` 는 아래
창이 닫혀 있으면 shutdown, 열려 있으면 schedules 다.

글자 수도 모자란다. 생성된 키 문서에 화면별 키가 600행 넘게 있는데 글자는 대소문자를 합쳐
52개다. 게다가 한글 입력 상태에서는 Shift 가 전달되지 않아 대문자 대부분이 소문자로
읽힌다(`masc_tui_key_ime.mli`). 한 글자에 한 뜻을 주려면 한 글자로 하는 동작의 수를
줄여야 한다.

화면을 하나씩 고치는 층은 11-05 부터 97번까지 올라갔다. 같은 원인의 수리가 반복되면
호출처 대신 구조를 고친다는 것이 저장소 규칙이다. 그래서 이 RFC 는 화면이 틀·키·표기를
직접 만들 수 없게 한다. 화면은 "무엇을 보여 줄지"와 "무엇을 할 수 있는지"를 값으로 내고,
그리고 키를 받는 일은 한 곳이 한다.

얻는 것: 형식이 한 곳에서 정해진다. 화면을 더해도 형식과 외울 키가 늘지 않는다.
잃는 것: 화면만의 동작은 키를 두 번 누른다(`Space` 와 글자). 화면이 자기만의 배치를 쓰려면
부품에 그 모양을 먼저 더해야 한다. 키퍼 그림 열, 채팅, 코드 보기처럼 고유한 본문은 본문
구역 안에서 지금처럼 직접 그린다(§5.4).

## 2. 화면 틀

모든 화면이 같은 다섯 구역을 쓴다. 구역의 줄 수는 내용과 상관없이 고정이다.

```
 운영  작업 19 ▌키퍼▐ 기능  저장소  시스템                         ◆ 조치 4  ● 연결  15:43 KST   ← 1 어디든
 키퍼 › 상태                      목록 ▌상태▐ 원인 시간 기억 나이 런타임 24h              7/29   ← 2 여기
 ─────────────────────────────────────────────────────────────────────────────────────────────
                                                                                                 ← 3 본문
 ─────────────────────────────────────────────────────────────────────────────────────────────
 ◌ 대기 목록을 다시 읽는 중 · 6.1s                                                      외 1     ← 4 알림
 c 대화   p 멈춤   e 고치기   a 새로 만들기   Space 동작                            ? 도움말      ← 5 키
 › geek-scout 에게                                                                   i 쓰기
```

| 구역 | 줄 수 | 내용 |
|---|---|---|
| 1 어디든 | 1 | 여섯 화면 이름과 배지. 오른쪽에 조치 필요 수, 연결 상태, 현재 시각과 시간대 |
| 2 여기 | 1 + 구분선 | 왼쪽에 경로(`화면 › 보기 › 고른 것`), 가운데에 이 화면의 보기 이름, 오른쪽에 위치 |
| 3 본문 | 남는 줄 전부 | 목록, 상세, 또는 둘을 나란히 |
| 4 알림 | 구분선 + 1 | 가장 급한 알림 하나와 나머지 개수 |
| 5 키 | 2 | 이 화면에서 되는 동작 키(§3.2)와 입력 줄 |

규칙:

- 제목 줄은 따로 없다. `MASC Keepers (29)` 는 구역 2 의 `키퍼 › 상태` 와 `7/29` 가 된다.
  제품 이름 `MASC` 는 화면에 적지 않는다.
- 연결 상태는 구역 1 오른쪽 한 곳에만 있다.
- 위치는 구역 2 오른쪽 한 곳에만 있다. 목록은 `고른 줄/전체`(`7/29`), 읽는 글은
  `첫 줄–끝 줄/전체`(`1–49/75`), 일부만 불러온 목록은 `1/50 · 전체 8,347` 로 적는다.
- 알림은 구역 4 에만 나온다. 본문 줄 사이에 끼우지 않는다. 알림이 없어도 그 줄은 비워 둔다.
  순위는 확인을 기다리는 동작(§3.3), 방금 한 일의 결과, 읽기 실패, 오래된 관측, 다음 일정
  순이다. 더 있으면 오른쪽에 `외 2` 를 적고 동작 창의 "알림 모두 보기"가 전부 보여 준다.
  한 줄에 관한 문제(한 키퍼의 읽기 실패)는 그 줄의 상태 칸에 적는다.
- 보내지 않고 막은 요청의 알림은 `이유 · <요청> 보내지 않음 · 남은 것` 순이다.
  이유가 앞이라 줄이 잘려도 이유는 남는다. 요청 이름이 있어 「알림 모두 보기」에 여럿 쌓여도
  어느 요청인지 가린다. 남은 것은 초안이나 대기 입력처럼 그대로 둔 것이고, 없으면 적지 않는다.
  다시 할 일이 있으면 맨 뒤에 붙인다. 요청 이름은 닫힌 variant 에서 나온다. 채팅 명령은 친
  그대로(`/copy`) 적는다. 워크스페이스 가드가 거절한 요청도 같은 모양이고, 가드를 부르는 쪽이
  요청 이름을 넘긴다.
  예: `워크스페이스 식별 미확인 · 투표 보내지 않음`,
  `Workspace identity unconfirmed · message not sent · draft retained`
- 구역 5 는 이 화면에서 되는 동작 키를 적는다. 이동 키(§3.1)는 적지 않는다.
- 본문 위에 키 안내를 한 번 더 적지 않는다.
- 왼쪽 여백은 두 칸이다. 첫 칸은 고른 줄 표시(`▌`), 둘째 칸은 빈칸이다. 열 사이는 두 칸이다
  (지금 `Masc_tui_table` 은 한 칸).
- 창을 나누는 선은 세로 줄 하나다. 상자로 두르지 않는다. 겹쳐 뜨는 창(동작 창, 도움말, 확인,
  팔레트)만 상자를 쓴다.

## 3. 키

### 3.1 이동 키

어디서나 같다. 화면은 아래 키를 다른 뜻으로 쓰지 못한다. 글자를 받는 칸(입력 줄, 찾기,
이름 칸, 답변 칸)이 초점일 때와 `$EDITOR` 는 예외다.

| 키 | 뜻 |
|---|---|
| `j` `k` `↓` `↑` | 한 줄 |
| `PgDn` `PgUp` | 한 쪽(읽던 마지막 줄 하나를 남김) |
| `Home` `End` | 처음, 끝 |
| `Enter` `→` `l` | 고른 것 안으로. 그룹 머리에서는 펼치기 |
| `Esc` `←` `h` | 한 단계 밖으로. 그룹 머리에서는 접기. 맨 바깥에서는 아무 일도 없다 |
| `[` `]` | 깊이는 그대로 두고 옆으로. 상세에서는 앞, 뒤 항목. 묶은 목록에서는 앞, 뒤 묶음 |
| `v` | 이 화면의 보기 목록을 연다. 숫자로 고른다. `v` 를 또 누르면 다음 보기다 |
| `Tab` `Shift-Tab` | 다음, 이전 화면(운영 → 작업 → 키퍼 → 기능 → 저장소 → 시스템) |
| `Backspace` | 직전에 있던 자리로 |
| `/` `n` | 찾기, 다음 결과 |
| `f` `o` | 거르기, 정렬 |
| `r` | 새로 읽기 |
| `i` | 쓰기 |
| `Space` | 동작 창(§3.3) |
| `:` | 어디로든 가기(팔레트) |
| `?` | 도움말 |
| `q` 두 번 | 끝내기 |

- 목록과 상세가 나란히 있을 때 `Enter` 는 상세로, `Esc` 는 목록으로 초점을 옮긴다. 깊이가 곧
  초점이다. 게시판과 리소스에서 창 초점을 옮기던 `Ctrl-W`, `b`, `h/l` 은 없앤다.
- `Enter` 는 닫지 않는다. 키퍼 화면의 아래 창(Story)은 높이가 넉넉하면 늘 보이고(§5.3),
  `Enter` 는 그 안으로 들어간다. 아래 창을 끄고 켜는 일은 동작 창에 있다.
- `[` `]` 는 지금도 열한 곳에서 "상세를 연 채 앞, 뒤 항목으로"다. 이 뜻으로 통일한다.
  키퍼 상세의 탭 넘기기, Features 실행 목록의 앞선 기록 읽기(`]`)는 이 키를 떠난다.
- `Esc` 의 목적지는 지금 화면마다 다르다(운영, 작업, 기능, 설정, 연 쪽 화면). 앞으로는
  구역 2 경로의 한 칸 왼쪽이다. 다른 화면으로 건너뛰지 않는다.
- `Backspace` 는 화면·보기·고른 줄을 기억한 자리 목록을 거꾸로 간다. 깊이 들어갔다가
  다른 화면으로 건너뛴 뒤 "무엇을 보던 중이었나"로 돌아오는 길이다. 지금은 `Ctrl-]` 로
  참조를 따라간 한 단계만 되돌아갈 수 있고 다른 화면으로 가면 그 기록이 지워진다.
- `Tab` 은 지금처럼 맨 위 여섯 화면을 돈다. 화면 안의 보기는 `v` 로 고른다. 보기 목록은
  이름과 번호를 보여 주므로 여덟 개여도 한 번에 간다. 지금 `v` 는 다섯 곳에서 보기 돌리기,
  아홉 곳에서 "전체 읽기"이고 투표, 거르기, DEBUG 켜기로도 쓰인다. 전체 읽기는 그 화면의
  보기 하나가 되고 나머지는 동작 창과 `f` 로 간다. 보기를 바꾸던 다른 글자(`p`, `t`, `9`,
  `z`, `h`, `1`~`4`)와 키퍼 상세의 탭(`[` `]`)도 `v` 로 모은다.
- 숫자는 이동에 쓰지 않는다. 답 고르기(승인 `1`~`9`), 첨부 고르기처럼 번호가 붙은 것을
  고르는 데만 쓴다. 지금의 `3`(키퍼로 가기)은 없앤다.
- 대문자는 한글 입력 상태에서 소문자로 읽힌다. 그래서 대문자에만 있는 키를 두지 않는다.
  `g` `G`(처음, 끝)와 `N`(이전 결과)은 영문 상태에서만 되는 별칭이다.
- 지금도 어디서나 같은 `;`(일정), `@`(응답 중), `&`(Collab), `Ctrl-B`, `Ctrl-L`, `Ctrl-W`
  (Activity 창), `Ctrl-^`, `F2`, `Ctrl-]`, `Ctrl-O`(그림 미리보기, 여섯 화면)는 그대로 둔다.
- 기호 키 세 쌍은 지금 뜻 하나로 굳힌다: `,` `.` 는 글 안의 앞, 뒤 그림, `<` `>` 는 서버가
  나눠 준 앞, 뒤 쪽, `{` `}` 는 앞, 뒤 판(revision)이다.

### 3.2 동작 키

한 글자로 하는 동작은 일곱 개다. 뜻은 앱 전체에서 같고, 그 뜻이 없는 화면에서는 아무 일도
하지 않는다. 모두 소문자라 한글 입력 상태에서도 된다.

| 키 | 뜻 | 지금 |
|---|---|---|
| `a` | 새로 만들기 | 키퍼 new, 저장소 등록, 일정 `n`, Fusion 새 실행 |
| `e` | 고치기 | 키퍼 설정, 일정 수정, Plugins 초안 |
| `c` | 고른 것에 말하기 | 키퍼 대화(`c` `m`), 게시글 답글 |
| `d` | 바뀐 것 보기 | 저장소 Git 변경, 코드 diff |
| `p` | 멈춤과 이어가기 | 키퍼 pause, 목표 일시 정지 |
| `y` | 승인, 동의 | 승인 `y`, 판정 동의 `y`, 작업 검토 `a` |
| `x` | 반려, 뒤집기 | 작업 검토 `x`, 판정 `x`, 승인 `n` |

- `x` 는 지금 키퍼 지우기, 목표 중단, 일정 취소이기도 하다. 이 셋은 동작 창으로 옮긴다.
  `x` 에는 판정의 "아니오"만 남는다.
- 지금 두 번 눌러야 하는 동작(작업 승인, 목표 동작)은 그대로 두 번 누른다. 이유를 받는
  동작(반려, 뒤집기)은 그대로 이유를 받는다. 확인 단계를 더하거나 빼지 않는다.
- 나머지 글자(`b m s t u w z`)는 한 글자 동작으로 쓰지 않는다.

### 3.3 동작 창

`Space` 는 고른 것에 지금 할 수 있는 일을 모두 보여 준다. 글자를 누르면 실행한다.

```
┌ geek-scout ───────────────────────────────────────────────────────┐
│ 보기    m 기억        s 일정       l 로그       t 호출            │
│ 실행    w 깨우기      u 모델 바꾸기                               │
│ 복사    n 이름        k ID                                        │
│ 조심    g 승인 없이 실행      q 종료      x 지우기                │
│ 화면    a 알림 모두 보기      b 아래 창 끄기                      │
└ 글자: 실행 · 조심 묶음은 한 번 더 묻는다 · Esc: 닫기 ─────────────┘
```

- 창 안의 글자는 창 안에서만 뜻을 갖는다. 이름이 옆에 적혀 있어 외우지 않는다. 같은 동작은
  되도록 같은 글자를 쓰지만 규칙으로 강제하지 않는다.
- 지금 쓸 수 없는 동작은 흐리게 적고 이유를 옆에 적는다. 빼지 않는다. 줄이 움직이지 않는다.
- 되돌릴 수 없는 일(지우기, 종료, 중단, 취소)과 권한을 넓히는 일(승인 없이 실행, Sandbox
  백엔드 바꾸기)은 `조심` 묶음에만 있다. 고르면 구역 4 가 무엇이 일어날지 적고 `y` 를 기다린다.
  다른 키는 취소다. 지금 `p`·`g`·`d`·`m`·`s` 한 번으로 실행되는 것 가운데 `g`(yolo)와
  Sandbox 백엔드 변경이 이 묶음으로 간다.
- 동작이 창 높이를 넘으면 묶음을 한 단계 더 연다(묶음 글자 → 동작 글자).
- 구역 5 는 동작 키 가운데 이 화면에서 되는 것과 `Space 동작` 을 적는다.

### 3.4 채팅의 Esc

지금은 Keeper 가 턴을 도는 중이면 첫 `Esc` 가 턴을 멈추고, 아니면 채팅에서 나간다. Claude
Code 와 Codex 도 `Esc` 로 멈춘다. 채팅은 글자를 받는 칸이라 §3.1 의 예외에 든다. 그대로 둔다.
대가는 나가려다 턴을 멈추는 실수가 남는 것이다. 지금처럼 구역 5 가 이번 `Esc` 가 무엇을
할지 적는다.

### 3.5 타입

- 이동 키와 동작 키는 닫힌 variant 다. dispatcher 가 화면 처리기보다 먼저 글자를 variant 로
  바꾸고, 화면 처리기는 variant 로 `match` 한다. 문자열 리터럴 갈래를 없앤다.
- 화면은 "고른 것에 할 수 있는 동작" 목록을 값으로 낸다. 동작 창, 구역 5 의 안내, `?`,
  `docs/guides/TUI-KEYS.md` 가 모두 그 목록에서 나온다. 안내에 적힌 키와 실제로 받는 키가
  어긋날 수 없다. 키퍼 화면의 안내는 지금 렌더러가 손으로 조립하는데 이것도 같은 목록에서
  만든다.

## 4. 도움말

지금 `?` 는 지금 화면의 키를 맨 앞에 두고 그 뒤에 전역 키, 슬래시 명령 46개, 나머지 모든
화면, 표식 풀이 아홉 묶음을 잇는다. 생성된 키 문서 기준으로 표가 600행을 넘는다. 키퍼
상세만 55행이다.

앞으로 `?` 는 한 화면에 들어가는 창 하나이고 어느 화면에서 열어도 같은 글이다.

```
┌ 키 ───────────────────────────────────────────────────────────────────────────────────┐
│ 이동                          동작                        기호                         │
│ j k       한 줄               a  새로 만들기              ● 정상   ◐ 하는 중           │
│ PgDn PgUp 한 쪽               e  고치기                   ○ 기다림 ‖ 멈춤              │
│ Enter     안으로              c  말하기                   ▲ 주의   ✕ 실패              │
│ Esc       밖으로              d  바뀐 것 보기             ◆ 사람 차례                  │
│ [ ]       옆 항목             p  멈춤 · 이어가기          — 없음   ? 모름              │
│ v         보기 고르기         y  승인 · 동의              ◌ 읽는 중                    │
│ Tab       다음 화면           x  반려 · 뒤집기                                         │
│ Backspace 직전 자리                                       더 보기                      │
│ / n       찾기                Space  이 줄에 할 수 있는   :  어디로든 가기             │
│ f o       거르기 · 정렬              일 모두              docs/guides/TUI-KEYS.md      │
│ r  i      새로 읽기 · 쓰기                                                             │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

- 화면마다 다른 것은 동작 창(`Space`)이 보여 준다. 도움말은 화면마다 달라지지 않으므로
  한 번 읽으면 된다.

화면을 옮기는 동안은 키가 아직 화면마다 다르다. 그동안 `?` 는 지금 화면의 키만 보여 주고,
`?` 를 한 번 더 누르면 모든 화면·전역 키·슬래시 명령을 보여 준다. `/` 로 찾을 때는 처음부터
전부에서 찾는다. 넓은 창에서는 지금 화면의 키를 두 단으로 나눠 한 화면에 담는다. 모든 화면이
옮겨지면 위 그림의 창으로 바꾼다.
- 긴 설명은 `docs/TUI-GUIDE.md` 에, 모든 화면의 동작 목록은 `docs/guides/TUI-KEYS.md` 에 둔다.
  슬래시 명령은 채팅에서 `/` 를 치면 나오는 완성 목록이 보여 준다.

## 5. 부품

### 5.1 목록

모든 목록은 `Masc_tui_table` 로 그린다. 칸은 종류를 갖는다.

| 종류 | 정렬 | 줄임 |
|---|---|---|
| 이름 | 왼쪽 | 끝(`…`). 줄에 남는 폭이 있으면 줄이지 않는다 |
| 글 | 왼쪽 | 끝 |
| ID, 경로, 해시 | 왼쪽 | 가운데 |
| 상태 | 왼쪽, 폭 고정 | 줄이지 않는다 |
| 시각, 기간, 수 | 오른쪽 | 줄이지 않는다 |

- 남는 폭은 이름과 글 열이 먼저 가져간다. 그 뒤에도 모자랄 때만 줄인다. 지금 Features 실행
  목록은 200열 화면에서 키퍼 이름을 16칸으로 자른다(`lane_subject_width`).
- 칸 기본값은 끝 줄임이다(지금은 가운데 줄임).
- 폭이 모자라 열을 빼면 열 머리 줄 오른쪽에 `외 2열` 을 적는다. 조용히 빼지 않는다
  (RFC-0459 §4.1).
- 고른 줄은 줄 전체 띠와 왼쪽 첫 칸의 `▌` 다. 초점이 다른 창에 있으면 띠가 흐려진다.
  `▸`, `›`, `>` 를 고른 줄 표시로 쓰지 않는다.
- 열 머리는 흐린 글자다. 화면 언어를 따른다. 대문자로만 적지 않는다.
- 그룹 머리는 `▾ 실패 7`, 접히면 `▸ 정상 17` 이다. `▸` `▾` 는 접힘에만 쓴다.
- 모든 줄이 같은 글자로 시작하면(목표 목록의 `진행 중`) 그 글자는 그룹 머리로 올린다.

### 5.2 상세

- 속성은 이름 열과 값 열 두 단으로 맞춘다. 이름 열 폭은 그 구역에서 가장 긴 이름이다.
- 구역 머리는 `── 성공 조건 ─────` 한 가지다. 대괄호 머리(`[ … ]`)를 쓰지 않는다.
- 읽는 글의 한 줄은 96칸(한글 48자)을 넘기지 않는다. 남는 폭은 오른쪽 여백이거나 옆 창이다.
  96 은 측정값이 아니라 설계 판단이다. 지금 게시판 본문은 160칸 안팎이다. 구현 층에서 두
  폭을 같은 글로 찍어 견준 뒤 값을 고친다.
- 해시는 앞 12자만 적는다. 전체는 동작 창의 복사로 얻는다.
- JSON 은 문자열 안의 `\n` 을 줄바꿈으로 풀어 보여 준다. 원문 그대로는 보기 하나다(`v`).

### 5.3 나란히 보기

폭이 넉넉하면 목록 왼쪽, 고른 것의 상세 오른쪽이다. 목록이 넓은 표라 옆에 둘 수 없으면
(키퍼) 상세가 아래 창이다. 좁거나 낮으면 목록만 보이고 `Enter` 로 상세가 화면을 차지한다.
어느 경우든 키는 같다. 폭 기준은 RFC-0459 §4.1 을 따른다.

### 5.4 고유한 본문

키퍼의 pulse 그림, 채팅, 코드, 다이어그램은 본문 구역 안을 직접 그린다. 틀(§2), 키(§3),
값 표기(§6), 상태 사전(§7)은 똑같이 따른다. 그림의 색은 §7.3 을 따른다.

## 6. 값 표기

화면은 값을 문자열로 만들어 넘기지 않는다. 표 칸과 속성 값은 `시각`, `기간`, `수`,
`없는 값` 을 타입으로 받고 한 모듈이 글자로 바꾼다.

### 6.1 시각

- 모든 시각은 운영자 컴퓨터의 시간대다. 시간대 이름은 구역 1 에 한 번 적는다.
- 오늘이면 `15:43`, 올해면 `11-11 15:43`, 다른 해면 `2025-11-11 15:43`.
- 목록의 열에서는 다른 해의 일을 날짜만 적는다(`2025-11-11`). 열 폭이 올해 형식을 넘지
  않고, 그만큼 오래된 일은 날짜로 찾는다. 시각은 그 줄의 상세에 있다.
- 초는 일의 순서를 가리는 기록 목록에만 붙인다(`15:43:07`).
- `2026-11-11T06:37:37Z` 같은 원문은 복사와 원문 보기에만 나온다. 서버 문자열을 글자 위치로
  잘라 쓰지 않는다(지금 목표 상세의 관련 기록이 그렇게 해서 UTC 가 표시 없이 나온다).
- 일정의 반복 시각도 같은 시간대로 바꿔 `매일 23:55` 로 적는다. wire 에 typed 반복 값이
  이미 있다.

### 6.2 기간

- 두 단위까지: `45s`, `3m15s`, `1h04m`, `2d03h`, `120d`. `64m`, `61s`, `24h` 로 적지 않는다.
- 걸린 시간이 1분 미만이면 `243ms`, `29.2s`.
- 좁은 열은 한 단위(`45s`, `3m`, `1h`, `2d`)를 쓴다. 한 열은 한 가지 방식만 쓴다.
- 지난 일 `3m 전`, 올 일 `8h13m 뒤`, 이어지는 일 `15:04 부터`. 영어 설정에서는
  `3m ago`, `in 8h13m`, `since 15:04`.
- 아직 이어지는 일의 길이는 값 뒤에 한 칸을 두고 `동안` 을 쓴다: `12m 동안 대기`,
  `12s 동안 새 출력 없음`. 길이로 말이 끝나면 `경과` 를 쓴다: `이 호출 12s 경과`.
  영어 단위 바로 뒤에 한글을 붙이지 않는다. `12m째` 로 적지 않는다.

### 6.3 수

- 1,000 이상은 쉼표를 넣는다: `56,274`, `8,347`.
- 줄임(`4.2k`, `1.3M`)은 열이 줄임으로 선언했을 때만 쓴다. 한 열은 한 가지 방식만 쓴다.
- 비율 `20/27`, 배수 `×164`, 하한 `≥7`, 더 있음 `외 108`(영어 `108 more`).
- 늘고 줄어든 값은 `+3`, `−2` 로 적는다. `+` 를 다른 뜻의 기호로 쓰지 않는다.

### 6.4 없는 값

| 뜻 | 글자 |
|---|---|
| 값이 없다고 확인됨 | `—` |
| 읽는 중이거나 아직 읽지 않음 | `◌` |
| 읽다가 실패함 | `✕` |
| 읽었는데 그 값이 보고되지 않음 | `?` |
| 이 줄에 해당 없음 | 빈칸 |

- `미확인`, `미관측`, `미기록`, `None`, `null`, `unknown` 을 값 자리에 적지 않는다. 왜 못
  읽었는지는 고른 줄의 상세나 구역 4 가 말한다.
- 앞서 읽은 값을 보여 주는 중이면(이전 관측) 값을 흐리게 적는다. RFC-0519 §2 의 낱말
  (조회 중·미조회·조회 실패·일부 관측·이전 관측)은 상세와 구역 4 의 문장에 쓴다.
- `…` 는 줄임에만 쓴다.

### 6.5 잇기

같은 급의 사실은 ` · ` 로 잇는다. ` — ` 로 잇지 않는다. `/` 는 비율에만 쓴다.

## 7. 낱말, 기호, 색

### 7.1 언어

RFC-0519 §2 를 모든 화면으로 넓힌다. 앱이 만든 글(화면·보기 이름, 열 머리, 상태, 키 안내,
알림)은 `[tui].language` 가 정한 한 언어로 나온다. 기본은 한국어다. 사용자가 쓴 글, Keeper
이름, 모델 ID, 경로, 설정 키는 원문 그대로다.

- 화면 글은 두 언어를 모두 가진 값으로만 만든다. 한 언어만 든 문자열은 화면 글 자리에
  넣을 수 없다. 화면마다 다시 정의한 언어 도우미와 `?(ko = false)` 기본값은 없앤다.
- typed 상태를 wire 철자로 찍지 않는다(`succeeded`, `checked`, `active`). decode 가 모르는
  값으로 남긴 상태(`Lane_run_other`)는 `? ` 뒤에 받은 글자를 그대로 적는다.
- 서버가 문장으로 보내는 대기 사유(`server_keeper_waiting_inventory`)는 이 RFC 범위 밖이다.
  wire 를 typed 사유로 바꾸는 일은 따로 제안한다.
- 낱말은 한 표에 둔다: 운영, 작업, 키퍼, 기능, 저장소, 시스템, 목표, 게시판, 기억, 일정,
  모델, 런타임. 한 개념은 한 낱말이다. `워크스페이스` 화면은 `저장소` 로 부른다.

### 7.2 상태

상태는 `기호 + 낱말` 로 적는다. 기호는 일곱 가지이고 한 기호는 한 가지 뜻이다.

| 기호 | 뜻 | 색 역할(RFC-0459 §3) |
|---|---|---|
| `●` | 정상, 끝남, 성공 | `status.success` |
| `◐` | 하는 중 | `status.info` |
| `○` | 기다림, 쉼 | `text.subtle` |
| `‖` | 멈춤, 취소 | `text.subtle` |
| `▲` | 주의, 오래됨 | `status.warning` |
| `✕` | 실패, 반려 | `status.danger` |
| `◆` | 사람 차례 | 강조(새 역할 `status.attention`) |

- 무엇을 기다리는지는 낱말이 말한다: `○ 모델 대기`, `○ 도구 대기`, `○ 외부 대기`.
- 도메인 상태를 이 일곱으로 합치지 않는다. 작업의 `검증 대기` 와 목표의 `확인 대기` 는
  서로 다른 낱말이고 기호만 같다.
- `!`, `×`, `◔`, `■`, `◇`, `↩`, `◷` 는 상태 기호로 쓰지 않는다. `◌` `?` `—` 는 없는 값(§6.4)에만
  쓴다.
- typed 상태에서 기호·낱말·색을 꺼내는 함수는 도메인마다 하나다. 화면은 그 함수만 부른다.

### 7.3 색

- 색은 상태만 뜻한다. 색 없이도 기호와 낱말로 읽힌다(RFC-0459 §3).
- `status.info` 는 "하는 중"과 초점에만 쓴다. 구역 머리, 키 글자, 모델 이름에 쓰지 않는다.
- 그림(pulse, 막대)은 기본 글자색으로 그리고 이상(실패, 밀림)만 색을 입힌다. 지금 키퍼
  화면은 정상 턴도 노랑이라 화면에서 가장 넓은 색이 "이상 없음"이다.
- 굵은 글자는 고른 것과 화면 이름에만 쓴다. 한 열 전체를 굵게 하지 않는다.

## 8. 흔들리지 않기

- 틀의 줄 수는 고정이다(§2). 알림과 일정 줄이 생겼다 사라지며 본문을 밀지 않는다.
- 새로 읽어도 고른 것은 화면의 같은 줄에 있다. 위아래 줄이 그에 맞춰 움직인다.
- 열 구성은 그 보기를 보는 동안 바뀌지 않는다. 보기를 바꾸거나 창 크기가 바뀌면 다시 잰다.
- 이름 열의 폭은 불러온 줄 전체에서 가장 긴 이름에 맞춘다. 화면에 보이는 줄만 재지 않으므로
  스크롤해도 열이 움직이지 않는다. 새로 불러온 줄에 더 긴 이름이 있으면 그때 한 번 넓어진다.
  이름보다 넓게 잡지 않는다. 남는 칸이 이름과 상태 사이를 벌리기 때문이다.
- 다시 읽는 동안 앞서 읽은 내용을 그대로 둔다. 읽는 중이라는 표시는 구역 2 오른쪽의
  `◌` 한 칸이다. 화면을 비웠다 채우지 않는다.
- 줄 순서는 정렬 키가 바뀔 때만 바뀐다. 같은 키 안에서는 이름순으로 고정한다.

## 9. 넣는 순서

스택 하나로 올리고 층은 헌법의 작업 단위(20k token)에 맞춰 나눈다. 화면 하나를 옮기는 층은
그 화면의 옛 그리기 코드와 옛 키를 같은 층에서 지운다. 아직 옮기지 않은 화면은 옛 모습으로
남는다.

1. 이 RFC 와 감사 문서.
2. 값 표기 모듈(§6)과 상태 사전(§7.2). 첫 화면 둘: Features 실행 목록(표, 영어 열 머리,
   wire 상태, 가운데 줄임)과 목표 상세의 관련 기록(UTC 로 찍히는 시각).
3. 도움말(§4)의 과도기 모습: `?` 가 지금 화면의 키만 먼저 보여 준다.
4. 이동 키(§3.1). 화면 하나씩 옮긴다. 옮기는 화면은 키 글자를 닫힌 variant 로 읽고, `Esc`
   목적지·`[` `]`·보기 목록(`v`)을 §3.1 대로 맞추고, 그 화면의 문자열 갈래를 같은 층에서
   지운다. 작은 화면부터 한다(Features 실행 목록과 그 상세). `Backspace` 자리 목록은 화면 둘이
   옮겨진 뒤 넣는다.
5. 동작 창(§3.3). 첫 판은 키 표(`Masc_tui_keys`)에 이미 있는 화면별 binding 으로 창을 만든다.
   그 뒤 화면 하나씩 한 글자 동작을 지우고 동작 목록을 값으로 낸다. `Space` 를 지금 다른 뜻으로
   쓰는 세 화면(Lanes 켜고 끄기, Items 비교, Exact 설정)을 먼저 옮긴다. 순서: 기능 → 키퍼 →
   작업(목표·검토·판정·승인) → 게시판 → 저장소 → 시스템 → 운영.

화면에 보이는 것이 바뀌지 않는 층은 따로 올리지 않는다. dispatcher 의 문자열 갈래 350개를
한꺼번에 variant 로 바꾸는 층은 위험만 있고 운영자가 볼 변화가 없다. 갈래는 그 화면을 옮기는
층에서 없어진다.

6. 틀(§2). `finish_surface` 가 다섯 구역을 조립한다. 화면 하나씩 구역 2 의 경로·보기·위치를
   값으로 내고 본문에 끼우던 알림을 구역 4 로 옮긴다.
7. 화면별로 표·상세 부품을 적용한다(§5).

층마다 증명 빌드로 고치기 전후 화면을 찍어 `docs/evidence/` 에 둔다. 넓은 창과 60열 창을
함께 찍는다. 2번 층이 가짜 서버로 감사 문서 §1 의 화면을 다시 찍어 기준선으로 둔다(운영자
캡처는 내부 글이 들어 있어 저장소에 없다).

## 10. 확인하는 법

- 화면 문구·배치·줄 순서를 붙드는 시험은 만들지 않는다(헌법 `execution_protocol`).
  지금 문구를 붙드는 시험(키 안내 줄의 완전 일치 등)은 그 문구를 바꾸는 층에서 지운다.
- 규칙은 타입이 지킨다: 표 칸과 속성 값이 문자열 대신 typed 값을 받는다. 화면 글은 두 언어를
  가진 값만 받는다. 키는 variant 에서 나온다.
- 시험은 결정만 본다: 키 → 동작, 조심 묶음의 동작이 확인 없이 요청을 보내지 않는 것,
  새로 읽은 뒤 고른 것의 identity, 기간과 수가 어느 단위를 고르는지(글자가 아니라 고른
  단위의 typed 값).
- 감사 문서 §1 의 표를 층이 끝날 때마다 같은 화면에서 다시 센다. 형식 가짓수가 목표다:
  위치 표시 3, 기간 사다리 2, 없는 값 5, 상태 기호 7, 고른 줄 표시 1, 한 글자 동작 7.

## 11. 앞선 RFC 와 다른 곳

- RFC-0519 §1 은 "화면마다 동작이 다른 키를 억지로 같게 만들지 않는다"고 적었다. 이 RFC 는
  이동 키와 동작 키 일곱을 같게 만든다. 근거는 2026-11-11 운영자 요청이다. 화면마다 다른
  동작은 동작 창 안에서 다르게 남는다.
- RFC-0459 §4.2 는 plain `i` 를 프롬프트 설정의 "마지막 입력 보기"로 두고 재배정하지 않는다고
  적었다. 이 RFC 에서 `i` 는 어디서나 쓰기다. 마지막 입력 보기는 그 화면의 보기 하나가 된다.
- RFC-0515 는 키퍼 목록의 `Enter`(Story 창 열고 닫기), Story 창의 `Tab`·`s`·`m`(쪽 넘기기),
  `V`(밀도), `W`(World)를 정했다. 이 RFC 에서 Story 창은 높이가 넉넉하면 늘 보이고 `Enter` 는
  그 안으로 들어간다. Story 창의 쪽은 보기(`v`)가 되고, 밀도와 World 는 동작 창으로 간다.
  묶음 머리로 뛰는 `[` `]` 와 그룹 머리의 `←` `→` 접기는 §3.1 과 같다.

## 12. 하지 않는 것, 열린 것

하지 않는 것:

- 새 언어 추가, 범용 번역 틀.
- 서버 wire 변경.
- 각 화면이 무엇을 보여 줄지 다시 정하는 일. 목표·작업·게시판·기억의 읽는 순서는 RFC-0519,
  키퍼 보기의 내용은 RFC-0515 가 정한다. 이 RFC 는 그 내용을 담는 틀이다.
- 화면 수와 이름을 바꾸는 일(`워크스페이스` → `저장소` 낱말 하나는 예외).
- 줄 수·형식 수를 세는 CI 검사.

열린 것(구현 층에서 화면을 찍어 보고 정한다):

- 가로로 긴 코드의 좌우 이동 키. 지금은 `h` `l` 인데 §3.1 에서 나오기·들어가기가 됐다.
- 읽는 글의 폭 96칸(§5.2).
- 강조색(`status.attention`)의 실제 색.
