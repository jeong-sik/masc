### Fixed

- A Keeper that was paused at boot now also waits out a stored provider quota
  window after its resume. Only the first cycle the lifecycle admits reads the
  rest its loop starts in, so a paused first cycle no longer uses up that check
  and the resumed Keeper does not send the refused account a request (#49248).
- A Keeper that waits at loop start records `provider_path_rest_<runtime>` as
  its skip reason in the registry, so a dashboard shows why it takes no turn
  (#49248).
