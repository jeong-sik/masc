# RFC-0477 — 승인된 관측은 저널에 있고, 확정된 사실은 흡수 상태다

## 0. 한 줄 요약

경계(Resume·Start·재생·tool-reply·중단·재시작·내보내기)를 넘을 때 승인된 관측이 사라지는
버그 클래스는 문서가 아니라 컴파일러와 저널이 막는다. 새 런타임은 만들지 않는다.

## 1. 문제

최근 500 커밋 중 fix는 202건이고, 그중 "retain/preserve/keep X across Y" 유형이
29건이다(2026-10-28 집계, 커밋 문구 정규식 기준). 이 수는 하한도 상한도 아니다.
"lost after resume" 류를 놓치고 "keep scroll" 류를 잡는다. 클래스의 존재 증거로만 쓴다.

대표 8건:

| 커밋 | 무엇이 어디서 사라졌나 |
|---|---|
| #45853 | 태스크 승인·거절 관측의 상관 키가 tool reply 뒤 재조립에서 |
| #45791 | 현재 Goal 판정·측정이 tool 요청과 held-session Resume에서 |
| #45950 | reasoning 전문이 스트리밍 경계와 재생에서 |
| #46327 | provider retry 관측이 turn 실패 처리에서 가려짐 |
| #46132 | 실행 소유권이 중단에서, 원본 판정이 회복 경로에서 |
| #46168 | 선언된(부팅 전) Apple guests가 서버 재시작에서 |
| #46169 | 확인된 저장이 잠금 해제 실패 뒤 덮어짐 |
| #46098 | 브라우저 lane 선택·대기 중 읽기가 새로고침에서 |

집계 시점에도 진행 중이다. #46595(OPEN)는 같은 클래스의 30번째다 — 제어기 실패 뒤에도
원본 작업 권한·취소·결과를 유지한다. 해결 방식이 FSM 상태(`Committing_launch`) 추가라는
점이 §8 감사의 대상이 된다.

사이트별 수정의 비용 구조: 고쳐야 할 칸 수는 관측 종류 × 경로 수다. 상태를 추가하는
수정은 행렬 자체를 키운다. 29건이 그 결과다.

## 2. 재분류

초기 분류(재구축/중단/동시쓰기/새로고침 4개)를 외부 리뷰 5건(§7)이 교차 검증해
두 근본 원인과 프레이밍 하나, 범위밖 하나로 줄였다.

- **I1 저널 갭·재유도 누락** — rebuild 원천에 사실이 없다. #45853, #45791, #46168,
  #45950의 재생 절반.
- **I2 비단조 전이** — 늦게 오거나 실패한 쓰기가 더 확정된 사실을 덮는다.
  #46327, #46132, #46169, #46595.
- **E 청크 결합법칙 위반** — #45950의 스트리밍 절반. `fold(분할)` ≠ `fold(연속)`.
- **범위 밖** — #46098은 서버 관측이 아니라 클라이언트 view 상태다. 대시보드의
  server_view/local_ui 분리 과제로 보낸다. 본 RFC가 다루지 않는다.

"중단/재시작"은 독립 메커니즘이 아니다. 재시작은 가장 극단적인 rebuild(I1)이고,
중단은 종말로 잘못 모델링된 전이(I2)다.

## 3. 불변식

**I1 (fold 동등성).** 모든 durable projection P에 대해 `P(live) = P(fold(log))`.

- **accepted의 정의: 저널에 기록되었다.** "live 상태에 있다"로 정의하면 순환이다.
  live에만 있고 저널에 없다면 그 자체가 I1 위반이다(write-ahead 갭).
- 승인 시점은 저널 쓰기 시점이다(write-before-accept). 스트리밍처럼 동기 쓰기가
  안 되는 관측은 in-flight와 accepted 구분을 명시적으로 선언한다.
  진행 중인 intent-before 패턴(#46599)을 참조한다.
- 왜 저널인가. 다른 주체(클라이언트·에이전트·사람)가 이미 그 사실에 의존했다.
  이 의존이 헌법이 말하는 durable truth 손상의 판정 기준이다.

**I2 (흡수 상태).** 확정된 사실(저장됨, 판정됨, 소유됨)은 흡수 상태다.
오직 명시적 End/retire 이벤트만 그것을 대체한다. 에러·정리·중단 전이는 덮어쓸 수 없다.

**E (결합법칙).** 어떤 분할에서도 `fold(분할된 스트림) = fold(원본)`.
절단·비식별화가 두 경로에 같이 적용되는지가 #45950의 본체였다.

## 4. 의도적 손실 등록부

"의도적으로 끝났다"는 문구에는 검사 오라클이 없다. 29건 모두 작성자에게 손실
의도는 없었다. 의도적 손실 경계는 등록부로 관리한다.

현재 아는 경계: 컨텍스트 compaction, 컨텍스트 절단(토큰 예산), TTL, 비식별화,
TUI viewport.

- 등록된 경계만 손실을 만들 수 있다.
- 등록되지 않은 경로는 기본 무손실이다.
- 의도는 발견되는 것이 아니라 감사되는 것이다.

## 5. 강제 — 컴파일러가 먼저

산문 의무는 에이전트 커밋 비중이 높은 이 속도에서 잊힌다. 컴파일 에러는 그렇지 않다.

1. 관측 종류는 닫힌 variant다. rebuild fold의 match는 exhaustive. 새 종류를
   추가하면 모든 rebuild에서 컴파일 에러가 난다.
2. 경계 생성자(Resume·Start·replay·restore)에서 `{ default with ... }`를 금지하고
   전체 record literal을 쓴다. 필드 추가 시 모든 경계에서 type error가 나고
   운반/버림 결정이 diff에 드러난다.
3. live 상태의 setter를 인터페이스에서 없앤다. 노출하는 것은 이벤트 적용 함수 하나다.
4. FSM 전이 match에 `| _ ->`를 두지 않는다. Interrupted와 Ended는 별도 생성자다.
5. 속성 테스트는 세 모양만 둔다.
   - I1: 차등 테스트. 같은 이벤트 열을 live 경로와 (저널→rebuild) 경로에 넣고
     비교한다. oracle은 live 경로 자체다. 사람이 명세한 expected는 쓰지 않는다.
   - I2: 흡수성 검사와 결정적 스케줄 위의 interleaving. Eio 스케줄러 위에서는
     flaky하다.
   - E: 분할 generator로 결합법칙을 검사한다.

기존 선례를 확장한다. `test_tui_keeper_chat_transcript`의 fold 고정이 I1 검사의
형태다. 수명 분류는 `prompt_block_id.mli`가 이미 하고 있다(post-tool/held-session
동작 선택). 경계 소유권의 타입 계약은 RFC-0099가 지목한 `tool_result.mli`(3치
failure effect disposition)와 `keeper_gate_replay.mli`다. 본 RFC는 새 권위를 만들지
않고 이 자리에 얹는다.

## 6. 런타임 변경 — 최대 하나, 삭제형

첫 실무 질문: **"로그에서 context를 만드는 함수는 몇 개인가."**

- 1개면 런타임 변경은 없다. §5의 컴파일러 게이트만 적용한다.
- 2개 이상이면 통합(`apply : state -> event -> state`, rebuild는 그 fold)이
  유일하게 승인되는 런타임 변경이다. 새 상태는 0, 코드는 줄어든다.

공용 journal을 새로 만들지 않는다. 이미 로그가 저널이고, 제2의 진실원은
journal↔log 정합성 버그라는 새 클래스를 만든다. 편입은 RFC-0412가 증명한 경로를
따른다 — 사건 하나가 필드 하나의 편입을 재원한다. 전면 이관을 예약하지 않는다.

## 7. 이력과 근거

최초 판정(단일 불변식 `rebuild ⊇ accepted` + 경로별 round-trip 의무)은 독립 리뷰
5건 전원에게 기각되었다.

- ⊇는 부활·중복·훼손·우선순위 역전을 통과시킨다(약함). 동시에 권위 있는 빈 관측의
  정당한 대체를 금지한다(강함).
- "의도적으로"에 검사 오라클이 없다.
- 트리거("경계를 바꿀 때")는 실제 재발 경로(live 경로에 관측 종류 추가)를 놓친다.
- 채택된 기각 사유와 증거는 `docs/evidence/2026-10-29-observation-retention-review/`
  에 원문으로 보관한다(GPT-Codex 저장소 직독, Anthropic Opus·Fable, GLM 2건).

## 8. 감사와 철회 조건

**감사.** 29건을 (a) derivation 수정, (b) carry-over 필드 추가, (c) FSM 상태 추가로
분류한다. (b)와 (c)의 비율이 "사이트별 수정이 맞았다" 명제의 진위를 결정한다.
저널에 이미 있던 사실을 carry-over 필드로 추가한 수정은 헌법 위반이다. #46595는
집계 후 (c)로 판정한다.

**철회 조건.** 이후 fix 100건당 이 클래스 비율을 추적한다. 제안 기간 6개월 내
감소가 없으면 본 RFC를 철회한다. 헌법의 증거 기준을 RFC 자신에게도 적용한다.
