## 1단계: Dashboard 에도 Activity 패널

다른 화면은 narrow 패널로 시작하는데 Dashboard 만 숨겨져 있었어요. 기본값을 맞췄어요

## 2단계: 빈 줄 2개 회수

바꾸려는 것: 전체 화면(Chrome_screen)의 위·아래 빈 줄을 없애고, 그 2줄을 본문이 써요.
겹창(overlay)은 진짜 테두리가 있어서 5줄을 그대로 둬요.

### 왜 한 상수만 바꿀 수 없는지

화면 틀은 5줄이에요. 위, 제목, 구분선, 아래, 푸터 순서예요(`Masc_tui_frame.chrome_rows`).
전체 화면은 위·아래가 빈 줄이고, 겹창은 테두리 줄이에요.

- `chrome_rows` 를 읽는 파일이 25개예요.
- `box_top` / `box_bottom` 을 직접 부르는 곳이 16개 파일, 104곳이에요.
- `surface_chrome` 계약으로 줄 수를 스스로 세는 화면은 12개 파일뿐이에요.
- 줄 수를 손으로 센 상수가 따로 있어요. 설정 화면은 8 또는 11, 채팅은 8, diff 화면은 7,
  최소 높이는 14예요.

상수를 3으로 줄이면 겹창이 2줄 넘쳐서 푸터가 밀려요. 그리려는 줄 수와 키 처리가
세는 줄 수가 어긋나면 화면 끝 줄에 커서가 닿지 않아요. 전에 Changes 목록이
방향키로 닿지 않던 사고가 이 모양이었어요.

### 순서

1. `screen_chrome_rows`(3)와 `overlay_chrome_rows`(5)를 한 곳에서 정의해요.
2. `surface_chrome` 계약을 쓰는 12개 파일부터 화면 틀을 3줄로 그려요. 계약은 줄을
   스스로 세서 어긋날 수 없어요.
3. 직접 `box_top` / `box_bottom` 을 부르는 화면을 `surface_chrome` 으로 옮겨요.
   화면 하나씩 PR 을 나눠요.
4. 다 옮긴 뒤 `box_top` / `box_bottom` 과 손으로 센 상수를 지워요.

### 확인 방법

화면 문구는 고정하지 않아요. 숫자로 확인해요.

- 그려진 프레임 줄 수가 터미널 행 수와 같다.
- 화면마다 본문이 쓸 수 있는 줄(`budget`)과 그려진 본문 줄이 같다.
- 겹창을 열어도 푸터가 마지막 줄에 있다.

## 3단계: Dashboard 본문을 2열로

바꾸려는 것: 본문 폭이 넓을 때 왼쪽은 결정할 일과 이어서 할 일, 오른쪽은 상태 읽기
(Health, Work, Candle)로 나눠요.

정해야 할 것:

- 2열로 바꾸는 폭의 기준. 패널이 켜지면 본문 폭이 그만큼 줄어서, 터미널 폭이 아니라
  본문 폭으로 정해야 해요.
- 오른쪽 열에 넣을 항목. 새 지표는 넣지 않고 지금 있는 읽기만 옮겨요.
- 본문이 좁아질 때 긴 줄(질문 행 등)이 잘리는 정도.

이 단계는 2단계 뒤에 해요. 줄 수 계약이 먼저 안정돼야 해서예요.
