# RFC-0515 — Keepers 목록에 보기 탭 · 한 축 줄 · Story 창을 올리고 맥박을 30분 칸으로 저장한다

- Status: **Draft.** 운영자가 2026-11-09 에 착수를 지시했다("1,2,3 전체 진행해줘"). §7 의 기본값은 이 RFC 를 병합하면서 받아들인다.
- 2026-11-09 정정: 리뷰와 시안 대조에서 나온 것을 고쳤다. §2.1 의 `known_since` 규칙을 구현(#50190)과 맞추고, 키 사실(§1.3), 기본 보기(E8), 시안과 다르게 정한 것(§2.7)과 층(§3)을 더했다.
- 2026-11-09 두 번째 정정: 운영자가 V1 을 깔고 시안과 견줬다. 시안의 보기별 칸(기억별 · 나이별 · 앞 12시간 일정 띠)과 머리 띠가 어느 층에도 없었다. §2.4 를 보기가 칸 값을 고르는 줄로 고치고 §2.8, 층 V6 · V8, 앞 12시간 띠, E16–E19 를 더했다.
- 2026-11-09 세 번째 정정: 운영자가 V6 설치본을 보고 시안과 너무 다르다고 했다. 시안을 headless 로 그려 같은 폭 캡처와 견줬다. 줄의 뼈대가 달랐다. 열 배치, `┃` 지금 선, 30분 맥박 칸 수, ▹ 의 띠 · due · lag 열, 묶음 접기, 나이 사다리 칸 수다. §2.4 를 시안 `layout(cols)` 그대로 다시 썼다. E2 · E16 · E17 을 바꾸고 E23–E27 을 더했다. 층 G1–G4 · A1 을 더했다. 앞 12시간 띠는 G3 이 올린다. 운영자는 나이 사다리를 서버 24칸으로 고르고(E17), 시안 그대로 다시 올리기를 골랐다.
- 2026-11-09 네 번째 정정: 균일 로그 눈금 24칸에는 1일 · 7일 경계가 없어서 문구가 27시간 · 9일이 됐다. 운영자가 경계를 1h · 1d · 7d · 30d 에 맞추고 문구를 세 묶음으로 줄이라고 골랐다(E28). §2.4.5 를 구간별 로그 눈금으로 고쳤다.
- 시안: `docs/research/2026-11-06-keepers-list-past-now-next-preview.html` (Artifact `Keeper Pulse` 3판).
- 앞 RFC: RFC-0511 §4 가 보기 6개 · Story 창 · `s` `m` `w` 키를 "값이 main 에 오른 뒤 별도 RFC" 로 미뤘다. 이 RFC 가 그 별도 RFC 다.

## 0. 요약

- RFC-0511 이 행 안의 값(실패 지속 시간 · 맥박 · lag · 갱신 시계 · 나이 사다리 · 일정 칸 · 사람 몫 표지)을 main 에 올렸다. 화면 틀은 그대로라서 운영자 눈에는 옛 화면이다.
- 이 RFC 는 화면 틀 넷을 올린다. 보기 탭, 한 축 줄(◂ 직전 · ● 지금 · ▹ 다음), Story 창, 그리고 이 셋을 부르는 키다. 한 축 줄은 시안의 격자(`layout(cols)`)를 그대로 쓰고, 열에 무엇을 넣을지는 보기가 고른다. 목록 위에는 묶음 수와 함대 실패 띠를 그린다.
- 그 앞에 맥박 저장을 고친다. 서버는 Keeper 마다 최근 턴 24개만 들고 있어서 바쁜 Keeper 의 12시간 칸이 `?` 로 찬다. 30분 칸으로 24시간을 저장한다. 이것이 24h 벽 보기의 재료이기도 하다.

## 1. 지금

### 1.1 운영자가 본 화면 (2026-11-09 08:2x KST)

- 설치본 `~/.local/bin/masc-tui` 는 main `9c7452c0e208` 빌드다. RFC-0511 의 TUI 층은 모두 들어 있다.
- 저장된 레이아웃이 `grouped` 였다. 둘째 줄은 `Detailed` 만 그린다(`bin/masc_tui_render_keepers.ml` 의 `entry_height`). 그래서 행 안의 값이 하나도 안 보였다.
- `Detailed` 로 바꾼 캡처(운영자 스크린샷)에서 세 가지가 보였다.
  - 맥박이 `???√√√√√√√√√` 처럼 앞쪽 칸이 `?` 다.
  - 둘째 줄 왼쪽이 첫 줄 DETAIL 칸과 같은 문장을 다시 쓴다. 오른쪽 칸들이 밀려 잘린다.
  - 보기 탭, 한 축 줄, Story 창은 없다. 열은 `KEEPER NOW Mode S AGE LIFECYCLE / RUNTIME DETAIL` 그대로다.

### 1.2 맥박의 `?` 는 저장 개수 상한에서 온다

`lib/keeper/keeper_turn_pulse.ml` 의 `max_samples_per_keeper = 24` 가 Keeper 마다 최근 턴 24개만 남긴다. TUI 는 남은 턴 중 가장 오래된 것보다 앞의 빈 칸을 `?` 로 그린다(`bin/masc_tui_keeper_pulse.ml` 의 `oldest_known_hour`). 범례도 "서버가 최근 24턴만 들고 있어서 바쁜 Keeper 의 앞 시간은 `?`" 라고 적는다(`bin/masc_tui_keeper_mark.ml` 의 `column_legend`).

2026-11-09 08:3x KST 에 `~/me/.masc/keepers/<name>.decisions.jsonl` 과 `.1` 의 `event=turn` 줄을 세었다.

| Keeper | 12시간 턴 | 24시간 턴 | 최근 24턴이 덮는 시간 | 12칸 중 `?` |
| --- | --- | --- | --- | --- |
| code-reviewer | 318 | 360 | 0.6시간 | 11 |
| sangsu | 36 | 85 | 8.2시간 | 약 4 |
| wkbl-web-leader | 48 | 84 | 8.2시간 | 약 4 |
| wkbl-data | 23 | 47 | 12.4시간 | 0 |

턴이 많은 Keeper 일수록 맥박이 비어 보인다. 맥박이 답하려던 질문("반나절째 실패하나")에 가장 바쁜 Keeper 가 답하지 못한다.

RFC-0511 D5 는 "최대 24개, 시간으로 자르지 않는다" 를 골랐다. 이유는 서버가 읽는 시각에 맞춰 세면 같은 행 JSON 이 읽는 시각마다 달라진다는 것(RFC-0481)이었다. 이 이유는 맞다. 개수 상한이 아니어도 지킬 수 있다(§2.1).

### 1.3 키

Keepers 목록에서 시안 키 일곱은 이미 다른 뜻이다.

| 시안 | 시안의 뜻 | 지금 뜻 |
| --- | --- | --- |
| `s` | 스케줄 | shutdown(두 번 눌러 확인) |
| `m` | 기억 | 대화(`c` 별칭) |
| `o` | 보기 순환 | 정렬 순환 |
| `n` | NO_COLOR | 다음 일치 |
| `t` | 테마 | 도구 호출 |
| `w` | 월드 | wake |
| `x` | 처음으로 | 영구 삭제 |

`v` 는 레이아웃 순환(compact · detailed · grouped)이고 푸터에 `v:view` 로 적혀 있다. `J` 는 고른 Keeper 의 상세를 Automation 탭(일정)으로 열고, `K` 는 그 Keeper 앞으로 쌓인 Keeper 요청을 읽는 창(동료 읽기)을 연다.

Keepers 목록은 `[` `]` 를 쓰지 않는다. `K` 창이 열려 있을 때만 그 창이 `[` `]` 로 앞 · 다음 동료를 고른다(`bin/masc_tui.ml` 의 detail reading 갈래). Work · Board · Keeper 상세 같은 다른 화면은 `[` `]` 를 앞 · 다음 행이나 탭으로 쓴다(`docs/guides/TUI-KEYS.md`).

## 2. 제안

### 2.1 맥박은 30분 칸으로 24시간을 저장한다 (RFC-0511 D5 를 고친다)

서버 저장 모양을 바꾼다.

```ocaml
type tally = { ok : int; rested : int; failed : int }
type slot = { starts_at : int; tally : tally }   (* Unix 초, 30분 경계에 맞춘 칸 *)
type pulse = { known_since : float; slots : slot list }   (* 새 칸이 앞 *)
```

- 칸은 Unix 시각을 1800초로 내린 경계에 맞춘다. 한 턴은 끝난 시각의 칸 하나에 더해진다.
- 칸을 지우는 때는 기록할 때뿐이다. 가장 새 칸보다 24시간 넘게 앞선 칸을 지운다. 그때 `known_since` 가 `가장 새 칸 − 24시간` 보다 앞이면 그 시각으로 올린다. 지운 칸이 없어도 같다. 읽을 때는 아무것도 계산하지 않는다. 그래서 행 JSON 은 턴이 기록될 때만 바뀐다(RFC-0481 조건 유지).
- Keeper 하나가 들고 있는 칸은 시간으로 정해진다. 24시간 = 48칸에 지금 칸 하나를 더해 최대 49칸이다. 턴이 몇 개든 같다.
- `known_since` 는 "이 시각부터는 턴을 빠짐없이 안다" 는 서버의 말이다. 서버가 켜질 때 결정 로그에서 다시 채우는 범위(시드)가 정한다.
  - 시드는 자율 사이클 턴(`execution_path = autonomous_cycle`)만 센다. 채팅 턴은 실시간 기록에 없어서 시드에서도 뺀다. 지금보다 뒤로 찍힌 줄은 버린다.
  - 시드는 주 로그 `decisions.jsonl` 의 꼬리를 읽는다. 주 로그가 없거나, 주 로그를 처음부터 다 읽고도 창 시작에 못 닿으면 회전 로그 `decisions.jsonl.1` 을 이어 읽는다.
  - 창보다 오래된 줄을 읽으면 창의 시작이다. 줄의 이벤트 종류는 가리지 않는다. 그 줄 뒤의 줄은 모두 읽었기 때문이다.
  - 그런 줄 없이 읽기가 끝나면 두 로그에서 읽은 줄 중 가장 오래된 시각이다. 꼬리 읽기가 4MB · 1만 줄에서 끊긴 때와 로그가 창 안에서 시작하는 때가 여기다.
  - 로그가 없거나, 시각을 읽을 수 있는 줄이 하나도 없으면 지금이다.
  - 시드가 없는 Keeper 를 처음 기록하면 그 턴 시각이다.
  - 기록할 때 `가장 새 칸 − 24시간` 보다 앞이면 그 시각으로 올라간다. 그 밖에는 바뀌지 않는다.
- 아는 틈: 쉼 턴은 결정 로그에 실패로 적히고, 결정 행 없이 끝나는 실패가 있다. 그래서 재시작 뒤 일부 칸의 결과가 바뀐다(#50211). 부팅 때 Keeper 시작이 시드보다 앞이라, 첫 턴이 시드보다 먼저 기록되면 시드를 건너뛰고 지난 하루를 잃는다. 기본 warmup 60초에서는 시드가 대개 먼저 끝난다(#50258).
- 행 JSON `recent_turns` 는 `{known_since, slots: [[starts_at, ok, rested, failed], ...]}` 이다. 옛 `{truncated, turns}` 는 hard cut 이고 읽지 않는다.
- 한 축 줄 보기는 행에 30분 칸을 `pulseW` 개(§2.4.1, 최대 24) 그린다. 칸 글리프는 §2.4.3 이다. 목록 보기는 지금처럼 벽시계 정시 1시간 칸 12개를 그린다(E2).

### 2.2 Detailed 둘째 줄은 첫 줄 문장을 다시 쓰지 않는다

`Detailed` 첫 줄의 DETAIL 칸을 뺀다. 문장은 둘째 줄에만 둔다. 첫 줄의 runtime 열이 그 자리를 쓴다. 둘째 줄 오른쪽 칸들(일정 · lag · 갱신 · stale · 맥박 · facts)이 덜 잘린다.

### 2.3 보기 탭

목록 위에 보기 이름을 한 줄로 그린다. 고른 보기는 반전으로 표시하고, 이름은 마우스로 누를 수 있다.

```
 목록 · 상태별 · 원인별 · 시간별 · 기억별 · 나이별 · runtime · 24h
```

보기마다 묶는 기준이 하나다. 모두 TUI 가 이미 decode 하는 닫힌 값으로 묶는다. 문자열로 가르지 않는다.

| 보기 | 묻는 것 | 묶는 기준(닫힌 값) |
| --- | --- | --- |
| 목록 | — | 묶지 않는다 |
| 상태별 | 누가 무엇을 기다리나 | `Keeper_list_model.attention`(지금의 `grouped`) |
| 원인별 | 왜 실패하나 | `cause_bucket`: 실패 원인(`Masc_tui_keeper_trail.cause_group`) · 원인 모름 · 회복 · 실패 없음 · 멈춤(§2.4.2 판정). 멈춤이 먼저다 |
| 시간별 | 언제 일하나 | `Masc_tui_keeper_next_run.t` 를 늦음 · 1시간 안 · 12시간 안 · 그 뒤 · 보류 · 일정 없음 · 모름 으로 |
| 기억별 | 기억이 따라오나 | `Masc_tui_keeper_memory_reading` 의 gap 있음 · 밀림(lag > 0) · 따라옴 · 거부 · 모름 |
| 나이별 | 기억이 식어 가나 | 스냅샷 `updated_at` 나이 3시간 · 24시간 · 3일 · 그 뒤 · 모름 |
| runtime | 어느 runtime 이 막혔나 | 행의 현재 runtime id |
| 24h | 반나절 동안 어땠나 | 묶지 않고, 실패한 30분 칸 수가 많은 순. 행에 48칸 맥박 |

- 묶음 안의 순서는 지금의 정렬(`o`)을 따른다.
- 시간별의 보류는 `Held_current` · `Held_as_of` 다. `Not_before` 는 그 시각이 12시간보다 뒤면 그 뒤에, 안쪽이면 실제로 깰 시각을 몰라서 모름에 둔다. 지났지만 아직 늦음으로 판정되지 않은 `Scheduled_at` 은 1시간 안에 둔다.
- 기억별의 거부는 `Refused` 다. `Gap_unmeasured` 는 gap 있음, `Lag_unmeasured` 는 모름에 둔다.
- 경계값은 가까운 칸에 넣는다. 정확히 3시간이면 3시간 칸이다.
- 나이 경계(3시간 · 24시간 · 3일)는 표시용 값이다. 서버 상태가 아니다. 나이를 `stale` 이라 부르지 않는다(RFC-0418).
- 월드 줄(RFC-0511 D2c)은 기억별 · 나이별 보기의 맨 위에만 둔다.

### 2.4 한 축 줄은 시안의 격자를 그대로 쓴다

목록 외의 보기는 Keeper 한 줄을 시안의 격자로 그린다. 격자는 시안 `layout(cols)` 를 그대로 옮긴다(E23). 열은 오른쪽 끝부터 고정하고, 남는 폭은 이름이 갖는다. 보기는 열마다 무엇을 넣을지만 고른다(E16). 시안과 다르게 정한 것은 §2.7 에 모았다.

```
  ● 이름 ……………  ◂ 맥박 │ ● 지금 │ 예약 확인  due  lag
```

#### 2.4.1 열 배치

- `cols` 는 Keepers 목록이 쓰는 폭이다. 터미널 폭이 아니다. 오른쪽에 다른 창이 열리면 그만큼 줄어든다.
- 계산은 시안과 같다.
  - `memW` 는 `cols ≥ 96` 이면 7, 아니면 0 이다. `timeW` 는 5, `bandW` 는 12 다.
  - `nameMin` 은 `cols ≥ 96` 이면 22, 아니면 18 이다.
  - `side = min 24 ((cols − 30 − extra − nameMin) / 2)` 다. `extra` 는 `memW` 가 있으면 8, 없으면 0 이다. 나눗셈은 내림이다. `pulseW = futW = side` 다.
  - 오른쪽부터 차례로 정한다.
    - `memX = cols − memW`
    - `timeX` 는 `memW` 가 있으면 `memX − 1 − 5`, 없으면 `cols − 5`
    - `futX = timeX − 1 − futW`, `slotX = futX − 1`
    - `ph2 = slotX − 2`, `nowX = ph2 − 1 − 12`, `ph1 = nowX − 2`
    - `pulseX = ph1 − 1 − pulseW`
  - 이름은 4열에서 시작해 `pulseX − 1` 앞까지다. 앞 두 칸은 여백이고 2열은 상태 표지다.
- 시안에 없는 좁은 폭의 규칙이다. `side` 가 0 이하면 맥박 · 띠 열을 그리지 않는다. 이름 폭이 1 보다 작으면 이름을 그리지 않는다. 목록 폭이 48 보다 좁을 때만 생긴다.
- 폭별 값:

| 목록 폭 | 이름 | ◂ 맥박 | ┃ ● ┃ | ▹ 띠 | due | 오른쪽 열 |
| --- | --- | --- | --- | --- | --- | --- |
| 171 | 85 | 24 | 12 | 1 + 24 | 5 | 7 |
| 120 | 34 | 24 | 12 | 1 + 24 | 5 | 7 |
| 80 | 18 | 16 | 12 | 1 + 16 | 5 | 없음 |

- `ph1` · `ph2`에 흐린 `│`를 긋고 지금 상태의 원래 색을 유지한다. 별도 열 배경을 칠하지 않고, 목록이 끝난 뒤의 빈 줄에는 선을 이어 그리지 않는다. 선택한 줄은 터미널 팔레트에서 구한 중립 배경을 쓴다. 팔레트를 모르거나 색을 끈 터미널에서는 반전 선택을 유지한다.
- 이름이 열보다 길면 끝을 `…` 로 자른다.
- 고른 줄은 줄 전체를 고른 배경으로 칠한다.
- 값이 없는 칸은 비운다. 따로 정한 곳만 `—` 이나 낱말을 쓴다.

#### 2.4.3 보기별 열 값

| 열 | 상태별 · 원인별 · 시간별 | 기억별 | 나이별 |
| --- | --- | --- | --- |
| 상태 표지 색 | 실패 Keeper 는 경고, 쉬는 중이면 흐림. 회복은 흐린 정상. 정상은 정상. 그 밖(멈춤 · `Health_offline`)은 흐림. 표지 앞에는 여백 두 칸을 둔다 | 같음 | 같음 |
| 표지(2열) | `!` 실패 Keeper · `○` 멈춤 · `●` 그 밖. 원인별만 회복에 `✓` | 같음 | 같음 |
| ◂ 맥박(`pulseW`) | 30분 맥박. 오른쪽이 지금 칸 | 같은 맥박 | 사실 나이 사다리(§2.4.5) |
| ● 지금(12) | 지금 표지와 낱말. 사람 몫 표지도 여기 쓴다(E27) | Librarian 패스 끝 낱말 | `+ <마지막 갱신 나이>`, 스냅숏이 없으면 `— no snapshot` |
| 예약(1 + `futW`) | 상태별은 확인한 예약 수와 일부 미확인 여부를 요약한다. 원인별·시간별은 앞 12시간 깰 시각 띠다(§2.4.4) | lag 막대 | lag 막대 |
| due(5) | 가장 이른 깰 시각 `HH:MM`, 늦었으면 `late` | 마지막 digest 나이, 없으면 `—` | stale 수 `×N`, 0 이면 비움 |
| 오른쪽(7) | lag 수와 단계 글리프 | gap 수(`1.2k` 꼴), 0 이면 비움 | facts 수와 단계 글리프 |

- 맥박 칸은 30분 칸 하나다. 시안 범례와 같다.
  - 아는 빈 칸은 공백이다. 턴이 없고 칸 시작이 `known_since`보다 앞이면 흐린 `─`다. 전부 모르는 창은 `기록 미확인`(영어 `history unknown`) 한 번으로 쓰고, 좁으면 `?` 하나로 줄인다.
  - 실패 칸이 아니면 `▁` 다.
  - 실패 칸이고 ok 가 0 이면 `█`, ok 도 1 이상이면 `▄` 다(같은 30분 안에 실패한 뒤 성공).
- 단계 글리프는 `▁▂▃▄▅▆▇█` 여덟 단계다. 값 ÷ 분모의 비율로 고른다(시안 `levelChar`). 분모는 쓰는 곳마다 다르다.

| 쓰는 곳 | 분모 |
| --- | --- |
| Keeper 줄 오른쪽 열의 lag · facts | roster 의 모든 Keeper 중 가장 큰 값 |
| Keeper 줄의 lag 막대 | 같음(가장 큰 lag) |
| 나이 사다리(Keeper · 묶음 · 월드 줄) | 그 줄의 가장 큰 칸 |
| 묶음 제목 줄의 맥박 합 | 그 묶음의 Keeper 수 |
| 묶음 제목 줄의 띠 합, 머리 띠 둘째 줄 | 그 줄의 가장 큰 칸 |

- lag 막대는 바탕이 `·` 다. lag 이 0 보다 크면 앞에서부터 `█` 를 `round(lag ÷ 분모 × 폭)` 개 그린다. 적어도 1개다. lag 을 모르면 띠 첫 칸에 `?` 를 쓴다.
- Librarian 패스 끝 낱말은 `mkh_librarian.mlh_state` 에서 온다(V6). 기억 스냅숏이 없으면 `no data`, librarian 이 없으면 `no librarian` 이다.
- 지금 낱말은 `Keeper_list_model.primary_activity_of_row` 의 낱말 하나다. 도는 턴은 기존 running 표지(`◐◓◑◒`, 150ms 걸음)를 그대로 쓴다. 새 움직임은 만들지 않는다.
- Mode · S · AGE · LIFECYCLE 은 Story 창으로 옮긴다.
- runtime 보기는 V5 전까지 상태별과 같은 열 값을 쓴다.

#### 2.4.4 앞 12시간 깰 시각 띠

- 띠는 지금 칸 하나와 그 뒤 30분 칸 `futW` 개다. 지금 칸은 지금이 든 30분 칸이다. 칸 경계는 맥박과 같은 1800초 경계다.
- 상태별의 Keeper 줄과 묶음 줄은 띠 대신 같은 구간에서 확인한 깰 횟수를 쓴다. 예를 들어 `72회 예약 확인`, `72회 확인 · 일부 미확인`이다. 아는 수만 더하며, 미확인 칸을 0으로 세지 않는다. 전부 모르면 `일정 미확인`, 아는 빈 구간은 `구간 내 예약 없음`이다. 좁은 폭의 일부 미확인은 `? 72+`처럼 미확인 표지를 앞에 둔다. 시간별에서 칸별 배치를 본다. 다음 due 열은 그대로 유지한다.
- Keeper 줄은 칸에 아는 깰 시각이 하나라도 있으면 낮은 막대 `▁`, 모르는 칸이면 가는 선 `─`, 아는 빈 칸이면 공백이다. 연속된 예약은 하나의 낮은 막대로 이어진다.
- 모든 칸이 모르면 칸마다 기호를 반복하지 않고 `일정 미확인`으로 쓴다. 모든 칸이 아는 빈 칸이면 `구간 내 예약 없음`이다. 영어는 `schedule unknown`, `no runs in window`다. 문장이 들어가지 않는 폭에서는 각각 `?`, `-` 하나로 줄인다. 일부만 모르는 띠는 원래 칸 위치를 유지한다.
- 깰 시각은 일정의 반복(`Schedule_domain.recurrence`)을 펼쳐 구한다(E19). 시안은 일정마다 다음 시각 하나만 찍는다(§2.7).
  - 첫 시각은 행의 다음 due 다. `Interval` 은 그 뒤로 주기를 더하고, `Daily` · `Cron` 은 `Schedule_domain.first_due_after` 를 되풀이한다. `One_shot` 은 첫 시각 하나다.
  - 만료 시각 뒤의 시각은 세지 않는다.
  - 지났지만 아직 늦음으로 판정되지 않은 시각은 지금 칸에 센다. §2.3 의 시간별 규칙과 같다.
  - 늦은 일정과 보류된 일정은 언제 다시 깰지 몰라 그 일정 몫 칸이 모두 모름이다. due 열은 `late` 로 말한다.
  - 반복을 디코드하지 못한 일정은 첫 시각만 세고, 그 뒤 칸은 모름이다. 일정 읽기가 실패했으면 모든 칸이 모름이다.
  - 잘린 일정 쪽(`scs_truncated`)은 받은 쪽의 마지막 due 뒤 칸을 모름으로 둔다. 서버 agenda 가 due 순인지 G3 에서 확인한다. due 순이 아니면 잘린 쪽의 모든 칸이 모름이다.
- 묶음 제목 줄과 머리 띠 둘째 줄은 펼친 깰 시각 수를 단계 글리프로 그린다. 합이 0이고 모르는 칸이 하나라도 있으면 `─`다. 합이 1 이상이면 아는 수만 센 단계 글리프다. 전체 미확인·전체 빈 구간의 문장 표시는 Keeper 줄과 같다.
- TUI 는 반복을 닫힌 값으로 든다. `sch_recurrence` 는 `Schedule_domain.recurrence_of_yojson` 으로 디코드한 결과다. 디코드하지 못하면 행은 남기고 `Error` 로만 든다. 수정 폼은 `Error` 반복이면 편집기를 열지 않는다.

#### 2.4.5 사실 나이 사다리

- 서버가 Keeper 마다 사실의 `first_seen` 을 24칸 로그 사다리로 센다(E17, E28).
  - 경계 넷 1h · 1d · 7d · 30d 는 칸의 시작과 정확히 같다. 칸 1 은 1h, 칸 9 는 1d, 칸 17 은 7d, 칸 23 은 30d 에서 시작한다.
  - 칸 0 은 1시간 안이다. 1h~1d 는 8칸, 1d~7d 는 8칸, 7d~30d 는 6칸으로 그 구간의 로그 눈금을 고르게 나눈다. 칸 23 은 30일 이상이다.
  - 구간 `[lo, hi)` 를 s 칸으로 나누면 j 번째 칸(0 ≤ j < s)은 `lo × (hi ÷ lo)^(j ÷ s)` 에서 시작한다. 나이는 그 나이가 닿은 가장 오래된 칸에 든다.
  - 미래 시각은 나이 0 이다.
  - 경계와 칸 수는 `Keeper_memory_age_bins` 한곳에서 정한다. TUI 의 눈금 · 색 · 문구는 그 값(`edge_span` · `edge_bin`)을 읽고 경계를 따로 들지 않는다.
- 행 JSON `age_bins` 는 길이 24 의 정수 배열이다. i 번째가 칸 i 이고, 새 칸이 앞이다. 합은 facts 수와 같다. 옛 `{under_hour, under_day, under_week, older}` 는 hard cut 이고 읽지 않는다. TUI · dashboard · Memory 화면이 같은 값을 쓴다.
- TUI 는 오래된 칸을 왼쪽에, 새 칸을 오른쪽에 그린다. 맥박과 같은 방향이다.
  - 합치는 수 `merge` 는 `pulseW ≥ 24` 면 1, 12–23 이면 2, 6–11 이면 4 다. 칸 수 `cells = 24 ÷ merge` 다. 6 미만이면 그리지 않는다(E25).
  - 그린 칸 c(오른쪽이 0)는 서버 칸 `c × merge` 부터 `merge` 개의 합이다. 칸들은 열의 오른쪽에 붙인다. 왼쪽 `pulseW − cells` 칸은 비운다.
  - 빈 칸은 `·`, 그 밖은 단계 글리프다.
  - 색은 칸의 가장 새 서버 칸으로 정한다. 하루 안(칸 0–8)이면 청록, 1~7일(칸 9–16)이면 기본색, 7일 넘음(칸 17–23)이면 흐림이다. 시안 범례와 같다.
  - 합치면 그린 칸이 1d · 7d 경계에 걸칠 수 있다. 2칸씩이면 칸 8–9 와 16–17 이, 4칸씩이면 칸 8–11 과 16–19 가 한 칸이다. 그 칸의 색도 가장 새 서버 칸을 따른다.
- 열 머리는 눈금 `30d 7d 1d 1h` 를 쓴다. 눈금은 그 경계가 시작하는 서버 칸 k 에 놓는다. 열 안 위치는 `(pulseW − cells) + cells − 1 − floor (k ÷ merge)` 다. 새 눈금부터 놓고, 열을 넘거나 앞 눈금과 겹치는 눈금은 뺀다(시안 `ladderTicks`).
- 기억 줄 문구는 색과 같은 세 묶음으로 센다. 새 묶음부터 `하루 안 · 1~7일 · 7일 넘음`(`under 1d · 1–7d · over 7d`)이다. Story 기억 줄, Memory 의 Keeper 줄과 fleet 줄, Detailed `facts` 칸 막대가 같은 묶음을 쓴다. 막대는 사다리처럼 오래된 묶음이 왼쪽이다.

#### 2.4.6 두 줄

- 두 줄 밀도에서 둘째 줄은 상태별 · 원인별 보기의 실패 Keeper 에게만 있다. 시안은 원인별에만 둔다(§2.7).
  - 이름 열에 실패 시작을 쓴다. `Failing_since t` 면 `◂ since <t>` 다. 이름 열이 좁으면 `since` 를 빼고 시각만 쓴다. `Failing_unrecorded` 면 `◂ <마지막 실패 턴 나이> ago` 이고, 그 나이도 모르면 비운다.
  - 맥박 열부터 그 턴의 시도 사슬 `✗━✗`(최대 넷, 넘으면 `…`)과 실패 낱말을 쓴다. `ph1` 앞에서 자른다.
  - 띠 열부터 다음 경로를 쓴다. 다음 후보면 `▹ <runtime id>`, 쉬는 중이면 `◌ wait <runtime id>` 다. 줄 끝에서 `…` 로 자른다.
- Keeper 줄의 ▹ 에는 runtime id 를 쓰지 않는다(E24).

#### 2.4.7 묶음 제목 줄과 처음 접힘

- 묶음 제목 줄은 같은 격자를 쓴다.
  - 앞 두 칸은 여백이고, 2열은 펼침 `▾`, 접힘 `▸`다. 이 표지는 묶음 색을 쓰고 제목은 기본 전경색의 굵은 글씨다. 상태별 제목은 `Active 5`, `Waiting 19`처럼 쓰며 상태 아이콘을 한 번 더 붙이지 않는다. 4열부터 제목을 쓴다.
  - 기억별 · 나이별이 아니고 `pulseW ≥ 20` 이면, 맥박 열 오른쪽 12칸에 칸마다 실패 칸인 Keeper 수를 단계 글리프로 그린다. 0 이면 `·` 다. 이때 제목은 그 12칸과 한 칸 앞에서 자른다.
  - 나이별은 `pulseW` 조건 없이 묶음 Keeper 의 사다리 합을 그린다. 제목은 이름 열에서 자른다.
- ● 열과 ▹ 쪽은 보기마다 다르다.

| 보기 · 묶음 | ● 열 | ▹ 쪽 | 오른쪽 열 |
| --- | --- | --- | --- |
| 원인별 실패 묶음 | `! N failing` | `▹ retry R  ◌ wait W`(쉬지 않는 수 R, 쉬는 수 W, 0 인 쪽은 뺀다) | 비움 |
| 원인별 회복 · 실패 없음 · 멈춤 | `✓ N` · `● N` · `○ N` | 깰 시각 합의 띠 | 비움 |
| 상태별 · 시간별 · runtime | `N` | 깰 시각 합의 띠 | 비움 |
| 기억별 | `N` | `Σ lag L` | gap 합(`1.2k` 꼴), 0 이면 비움 |
| 나이별 | `N`, 오래 쉰 자율 Keeper 가 K 명이면 `N · K!` | `Σ <facts> facts · lag L` | 비움 |

- "오래 쉰 자율 Keeper" 는 나이별 `그 뒤`(3일 이상) 묶음에 있고, 멈춤이 아니며, Mode 가 autonomous 인 Keeper 다(시안 `oddDormant`).
- 원인별 묶음은 실패 원인 묶음(`Cause_named` · `Cause_unnamed`) 뒤에 회복 · 실패 없음 · 멈춤을 둔다(§2.3, G4).
- 처음 열 때 접힌 묶음은 시안을 따른다(E26).
  - 원인별: 회복, Keeper 가 넷보다 많은 실패 없음, 멈춤
  - 시간별: 일정 없음
  - 기억별: 따라옴 · 모름
  - 나이별: 24시간 · 모름
  - 상태별 · runtime: 접지 않는다
- 월드 줄은 같은 격자를 쓴다(시안 `paintWorld`). W1 이 올린다.
- 월드의 absent는 현재 읽힌 ordinary 사실 중 장부에 등록되지 않은 사실 수다. Keeper ID와 claim 원문의 SHA256을 함께 비교하고, 같은 Keeper의 같은 사실은 한 번 센다. claim · conflict · excluded 어느 처분이든 장부에 있으면 absent가 아니다. 총 사실 수에서 claim 수를 빼지 않는다.
- absent 집계는 가벼운 inventory 응답에 싣는다. 모든 ordinary 저장소를 읽었으면 정확한 수, 일부를 못 읽었으면 읽힌 사실에 대한 하한, Keeper 발견 자체가 실패했으면 미확인이다. 없는 저장소는 알려진 빈 상태이며, 없는 장부는 별도 상태를 유지한다. source-bound 저장소의 실패는 ordinary 집계를 흐리지 않는다. 왜 장부에 없는지, 언제 들어갈지는 추측하지 않는다.
- 고른 Keeper 의 초상은 목록 보기의 두 줄에서만 그리고, 전신으로 그린다(E20).

### 2.5 Story 창

목록에서 `Enter` 를 누르면 고른 Keeper 의 Story 창이 목록 아래에 열린다(시안의 dock). 화면 높이가 모자라면 목록 위에 겹쳐 연다.

- 쪽은 셋이다. story · 일정 · 기억. 창 안의 `s` 는 일정 쪽, `m` 은 기억 쪽, `Tab` 은 다음 쪽이다. 창이 열려 있으면 `Tab` 은 창이 먼저 받는다(E15). 창이 닫히면 `Tab` 은 다시 다음 화면이다.
- story 쪽 줄: ◂ 직전(맥박 · 지난 턴 · wake · digest 를 시간순으로 한 줄씩 적은 피드) / ● 지금(활동 문장 · Mode · S · AGE · LIFECYCLE) / ▹ 다음(일정 · 경로 · lag) / 실패 사슬.
- 일정 쪽은 이 Keeper 로 거른 일정이다. `J` 가 여는 상세 Automation 탭과 같은 값이다. 기억 쪽은 이 Keeper 의 나이 사다리와 기억 줄이다.
- 창 안의 키: `→` 는 지금의 상세(탭 11개), `Esc` 는 닫기. 목록의 `s`(shutdown)와 `m`(대화)은 창이 닫혀 있을 때만 받는다.
- wake 는 일정 응답의 `last_wake` 를 창이 열릴 때 읽는다(시안 B 단계). 첫 Story 층에는 넣지 않는다.
- 시안의 시간순 피드(지난 턴 · wake · digest 를 한 줄씩)는 S3 가 두 층으로 나눠 다룬다.
  - S3a 는 지난 턴 3개를 past 에 한 줄로 그린다. 값은 Memory 가 이미 읽는 `GET /api/v1/keepers/<name>/turn-records` 에 `limit=3` 을 준 응답이다(E21). 턴의 시각은 레코드의 `ts` 다. 멈춘 이유는 영수증이 적은 `finish_reason` 을 그대로 보여 주고, 이유가 없는 레코드는 이유가 없다고 적는다. 이유 문자열을 ok 나 failed 로 가르지 않는다.
  - S3b 는 S3a 의 한 줄을 이 목록으로 바꾼다. 이 턴, S2 가 읽는 일정 행의 wake, 기억 건강 행의 `digest_at` 을 시각 오름차순으로 한 줄씩 그리고, 가장 새것이 목록의 끝에 온다(E22). 창 높이가 모자라면 오래된 사건부터 빠진다. 읽지 않았거나 읽기에 실패한 출처는 사건 자리를 비우지 않고 목록 끝에 출처마다 줄 하나로 말하고, 읽기에 실패한 줄은 읽기가 남긴 사유로 끝난다. 이 줄들은 창이 모자라도 남고, 모자라면 실패한 읽기의 줄이 나머지보다 오래 남는다. digest 는 첫 past 줄에서 목록으로 옮겨 간다.

### 2.6 키

| 키 | 뜻 | 바뀌는 것 |
| --- | --- | --- |
| `v` | 보기 순환(§2.3 순서) | 지금은 레이아웃 순환이다. 푸터 글자 `v:view` 는 그대로다 |
| `V` | 한 줄 / 두 줄 전환 | 새 키. 지금의 compact · detailed 가 여기로 온다 |
| `V` 의 뜻 | 두 줄이면 모든 보기에서 둘째 줄을 그린다 | 목록 보기는 지금의 detailed 둘째 줄, 한 축 줄 보기는 실패 사슬과 원인 줄이다 |
| `[` `]` | 앞 · 다음 묶음으로 이동 | 새 키(Keepers 목록에서만). `K` 창이 열려 있으면 그 창이 먼저 받는다 |
| `Enter` | Story 창 | 지금은 상세. 상세는 `→` 로 간다 |
| `←` `→` | 묶음 제목 줄에서 접기 · 펼치기 | 새 뜻(제목 줄에서만). 묶는 보기에서는 `j` `k` 가 제목 줄에도 선다. 제목 줄에서는 접기가 `←` 의 "뒤로" 보다 먼저다. 행 위의 `←` `→` 는 그대로다 |
| `J` `K` | 지금 뜻 | 그대로. `J` 는 상세 Automation 탭을 연다. Story 일정 쪽은 그 탭과 같은 값을 그린다 |
| `W` | 월드 창 열기 | 모든 Keepers 목록 보기에서 받는다. 기억별 · 나이별에서는 보기를 유지하고, 다른 보기에서는 나이별로 옮긴 뒤 월드 줄을 고른다. Keeper 작업 대상은 고르지 않는다 |
| `o` | 정렬 순환 | 그대로 |
| `s` `m` `w` `x` `n` `t` | 지금 뜻 | 그대로. 시안의 뜻은 Story 창 안의 `s` `m` 만 받는다 |

- 설정 파일 `tui-keepers.toml` 의 `layout` 키는 hard cut 이다. `view` 와 `density` 를 새로 쓴다. 옛 `layout` 을 읽어 옮기는 코드는 만들지 않는다.
- 옛 `layout` 줄이 남은 파일은 오류 없이 읽고, 그 줄은 쓰지 않는다. 처음 켜면 기본값(E8)이다. 이 사실은 changelog 한 줄로 알린다. 화면 안 안내는 만들지 않는다.
- 시안의 시뮬레이션 키(`f` `r` `u` `c` `d` `D` `x`)와 `[sim]` 표시는 시연 장치라서 올리지 않는다.

### 2.7 시안과 다르게 정한 것

| 시안 | 이 RFC | 이유 |
| --- | --- | --- |
| 보기 순환 `o` | `v` · `V` | `o` 는 정렬이다(E3 · E4) |
| 목록에서 `s` `m` 으로 dock 쪽 열기 | Story 창 안에서만 | 목록의 `s` 는 shutdown, `m` 은 대화다(E6) |
| 월드 열기 `w` | 대문자 `W` | 소문자 `w` 는 Keeper wake다. 월드 창은 Keeper를 깨우지 않는다 |
| 시뮬레이션 키와 `[sim]` | 올리지 않는다 | 시연 장치다 |
| runtime 교차표(실패 Keeper × runtime) | V1 은 runtime id 로 묶고, V5 가 교차표로 바꾼다 | 묶기는 V1 의 묶는 함수로 바로 된다. 교차표는 `Masc_tui_keeper_trail.attempts_of_runtime` 을 읽는 새 그리기다 |
| 24h 벽의 세 묶음(실패 · 그 밖 · 정상)과 시간 눈금자 | V4 에 넣는다 | 48칸 맥박과 같은 층의 그리기다 |
| 월드 행을 골라 월드 창(Keeper 기억 → 원장 → 브리핑) | W1 | 월드 줄(RFC-0511 D2c)이 고를 수 있는 행이 되어야 한다 |
| 실패 Keeper 둘째 줄의 짧은 runtime 이름(`sonnet·acct-c`) | runtime id 를 줄 끝에서 자른다 | 시안의 이름은 시안 데이터에 손으로 적은 라벨이다. TUI 는 id 만 받는다. id 를 갈라 짧게 만들면 문자열 분류가 된다 |
| 보기 여섯(cause · time · memory · age · runtime · 24h) | 여덟. 목록 · 상태별을 앞에 둔다 | E7 |
| 나이별 머리 띠의 `stale events/day` · `changed` · `gone` | 그리지 않는다 | 무효화 시각은 약 3MB 인 `workspace-memory-context` 응답에만 있다(E18) |
| 깰 시각 띠는 일정마다 다음 시각 하나(`futCounts`) | 반복을 펼쳐 12시간 안의 깰 시각을 모두 찍는다. 묶음 합과 머리 띠도 펼친 수를 센다 | E19. 10분 간격 일정이 띠에 표시 하나로 보이면 다음 12시간 동안 거의 쉬는 Keeper 와 구별되지 않는다 |
| 둘째 줄은 원인별 실패 행에만 | 상태별 · 원인별 실패 행 | 상태별은 시안에 없는 보기이고, 실패 묶음을 둔다 |
| 맥박 칸이 넷(없음 · ok · 실패 · 실패 뒤 ok) | 같다. rested(쉼 턴)는 실패 칸에 센다 | 시안에는 쉼 턴이 없다. 쉼 턴은 결정 로그에 실패로 적힌다(§2.1) |
| 좁은 폭에서 나이 사다리 축을 칸 수에 맞게 다시 나눈다 | 서버 24칸을 2 · 4 칸씩 더한다 | E25 |

### 2.8 머리 띠와 묶음 제목 줄

시안은 목록 위에 두 줄 띠를 둔다. V8 이 띠와 고른 Keeper 줄을 올린다. 묶음 제목 줄은 G4 가 올린다.

- 띠 첫 줄은 보기의 묶음이 아니라 고정된 넷을 그린다(시안 `stripGroups`). 묶음마다 표지 · 수 · 이름을 쓰고 Keeper 하나에 글리프 하나를 잇는다. 빈 묶음은 뺀다. 줄에 다 들어가지 않으면 이름을 빼고 `!2` 꼴로 쓴다. 고른 Keeper 의 글리프는 굵게 칠한다.
  - 나이별이 아닌 보기: `! N failing`(쉬는 중 `▫`, 그 밖 `▪`), `✓ N recovered`(`▪`), `● N ok`(`▪`), `○ N paused`(`·`)
  - 나이별: `█ N fresh` · `▆ N today` · `▃ N cooling`(모두 `▪`), `▁ N dormant`(오래 쉰 자율 Keeper 는 경고 `▪`, 그 밖 `▫`). 경계는 §2.3 나이별의 3시간 · 24시간 · 3일이다
  - 예: `! 2 failing ▫▫  ✓ 20 recovered ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪  ○ 14 paused ··············`
- 띠 둘째 줄은 열 머리와 같은 격자를 쓴다. 맥박 열에는 30분 칸마다 실패(failed · rested)한 Keeper 수를, ▹ 띠 열에는 멈추지 않은 Keeper 의 깰 시각 수를 단계 글리프로 그린다. 이름 열에 `fleet fail/30m max N` 을 쓴다(이름 열이 21칸보다 좁으면 `fleet max N`). due 열에는 `max N` 을 쓰고, 5칸에 안 들어가면 `N` 을 `1.2k` 꼴로 쓴다. 띠 열 값은 G3 의 값이다. 나이별 보기는 둘째 줄을 그리지 않는다(E18).
- 묶음 제목 줄은 §2.4.7 을 따른다. G4 가 올린다.
- 맨 아래의 고른 Keeper 줄은 지금의 `selected ·` 줄을 세 칸 요약으로 바꾼다. 예: `ocaml-agent-ic ○ idle 77m · since 11-05 18:51 · ◷ 13:33 every 10m · lag 1`. 실패 Keeper 면 다음 경로의 runtime id 도 쓴다(E24). 반복 표기(`every 10m`)는 G3 이 디코드한 닫힌 반복 값으로 쓴다.
- 고른 Keeper 줄은 Story 창이 닫혀 있을 때만 그린다. 창 story 쪽의 ● 지금 · ▹ 다음이 같은 값이라서다(시안도 창이 열리면 이 줄 대신 창을 그린다). 창과 이 줄은 목록 끝과 푸터 구분선 사이 같은 자리를 쓴다.

- `docs/guides/TUI-KEYS.md` 는 생성 문서다. 키나 범례를 바꾼 층이 생성기 출력과 맞춘다.

## 4. 하지 않는 것

- 서버의 권위(결정 로그 · 원장 · 영수증)를 바꾸지 않는다. 맥박은 결정 로그를 다시 읽어 만드는 투영이다.
- 칸 저장을 행동을 막거나 고르는 게이트로 쓰지 않는다.
- 화면 문구 · 배치 · 행 순서를 확인하는 시험을 만들지 않는다(`docs/constitution.xml` 의 `execution_protocol`). 증거는 캡처다.
- Schedules · Memory 전체 화면을 없애거나 합치지 않는다.
- 옛 `recent_turns` 모양, 옛 `layout` 설정을 읽는 호환 코드를 만들지 않는다.
- Failing 의 색(빨강 → 노랑 · 흐림)은 바꾸지 않는다. 다른 세션이 색 층을 다루고 있다.
- NO_COLOR · 테마 전환 키를 Keepers 목록에 더하지 않는다. 둘 다 화면 전체 설정이다.

## 5. 확인 방법

1. **타입.** 로컬 dune 빌드를 하지 않는다. PR 의 `type-check` 가 판정한다. 실행을 인용할 때 workflow 이름, run id, head SHA, 결과를 같이 적는다.
2. **동작 시험.** P1 은 서버 저장(칸 경계 · 24시간 지우기 · `known_since`)과 디코더의 닫힌 갈래를 본다. V1 은 보기마다 묶는 함수가 닫힌 값만 쓰는지 본다. G3 은 반복(`Interval` · `Daily` · `Cron` · `One_shot`)마다 띠 칸 값을 고르는 함수와 수정 폼의 `Error` 반복 거절을 본다. A1 은 칸 경계(1시간 · 30일 · 미래 시각)와 칸 합이 facts 수와 같은지를 본다. G4 는 원인별 묶는 함수가 닫힌 판정(§2.4.2)만 쓰는지 본다. 격자 계산과 화면 글은 시험하지 않는다(헌법 354-355).
3. **실측.** P1 은 §1.2 표를 같은 로그로 다시 센다. 바쁜 Keeper 의 맥박 칸 중 `?` 는 서버 기록 범위(`known_since`) 앞에서만 나와야 한다.
4. **캡처.** TUI 층은 120x35 와 80x24 전 · 후 tmux 캡처를 남긴다. 절대 경로 · 토큰 · 계정 이름을 가린다.
5. **시안 대조.** 시안 HTML 끝에 `buildScreen()` 결과를 글로 적는 스크립트를 붙인다. headless 브라우저로 `#qa` 를 열어 보기마다 같은 목록 폭의 글 화면을 얻는다. 같은 폭 캡처와 열 단위로 견준다. 재는 것은 `┃` 열 위치, 맥박 · 띠 칸 수, 이름 폭, 열마다 쓰는 글리프 집합이다. 결과는 PR 본문에 표로 남긴다. 낱말이 있는지만 세는 비교는 뼈대 차이를 못 본다(세 번째 정정). CI 시험이 아니다.
6. **적대적 리뷰.** 층을 올리기 전에 새 맥락의 읽기 전용 에이전트가 diff 를 읽는다. 독립 승인은 따로 받는다.

## 6. 위험

- 행 JSON 크기. 칸 하나는 숫자 넷이고 Keeper 하나는 최대 49칸이다. 2026-11-09 결정 로그로 같은 규칙을 계산하면 Keeper 39명의 `recent_turns` 합이 23,504바이트(최근 24턴)에서 13,852바이트(30분 칸)로 준다. 가장 큰 행은 861바이트다. 쉬는 Keeper 는 칸이 적어서 작아진다.
- 맥박과 띠는 30분 경계마다 보이는 행 거의 전부가 한 칸 민다. 30분에 한 번이라 다시 그리는 비용은 작다(시안 「끊김 없이 움직이나」 표).
- `Enter` 의 뜻이 바뀐다. 상세로 바로 가던 손버릇은 `→` 로 옮겨야 한다.
