### Changed

- **Keeper addressing**: a workspace broadcast mention now reaches a Keeper
  that a Board post to the same name reaches. A Keeper whose `mention_targets`
  leave its own name out no longer receives a broadcast by that name; another
  Keeper that lists the name receives it. When none does, the broadcast fails
  like one to an unknown name: the mention is rejected as
  `Target_not_configured`, the sender gets that rejection, and the message is
  not shown in other Keepers' windows. The broadcast path, the chat lanes and
  the Board router now read one rule, `Keeper_lane_mentions.effective_target_ids`,
  so the delivered row's mentions are that Keeper's addresses instead of its
  name plus its list (#55533, #46853).

### Fixed

- **Keeper addressing**: a broadcast mention written with capitals (`@Alice`)
  now finds the Keeper by its lower-case name, as the Board does. On a
  case-sensitive filesystem it used to be rejected for a Keeper with no
  `mention_targets`; on a case-insensitive one it was accepted under the
  capitalised name and never reached the Keeper's queue (#55533).
