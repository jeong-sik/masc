### Fixed

- A BiDi host started with `--firefox-profile` that ends a session because the Firefox on its port runs another profile now records why: `bidi-host.json` gains `ended.because` (`profile_not_kept` with the expected profile and the one Firefox named, or `reason_only`), and its layout goes to 2. `masc doctor`, the connection list, a Keeper's rejection and the TUI then say that another Firefox holds the port and is quit first, instead of telling the operator to check that a Firefox answers there. A Keeper's hover or drag whose start meets that Firefox is answered `operator_needed` instead of `start_failed`. A record of layout 1 reads as unreadable; `scripts/install-local-build.sh` leaves a running BiDi host on its old copy, so restart the BiDi host once after deploying this, and the new host keeps a copy of the old record beside its own (#42227).
