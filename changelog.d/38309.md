### Added

- The Memory health payload carries a `Librarian_stalled` alarm per keeper, `librarian.stalled` (`null` or `{gap_start_atom, gap_end_atom}`, end exclusive): the atoms the next request skips because the Librarian point stands behind the start the provider last accepted (RFC librarian-lifecycle §4.10). It is computed from the keeper's small files alone -- meta, continuity snapshot, read position and turn records, never the checkpoint -- through the shared gap rule `Keeper_carried_front.librarian_gap` (`Keeper_next_request_forecast.librarian_gap`), so it counts only atoms the Librarian has not read and shows on a server that just started, clears once the Librarian reaches the accepted start, and is not raised by a turn that ended on a size refusal. The TUI Memory screen draws it on its own row under the Librarian line and the dashboard Memory health table as a badge; both decoders require the key (#38309).
