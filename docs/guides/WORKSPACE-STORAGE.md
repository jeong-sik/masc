# Repository documents and run output

[한국어](WORKSPACE-STORAGE.ko.md)

Choose a location by what the file is for. All paths in this table are relative
to the MASC repository, except the explicitly marked runtime paths.

| Content | Location | Treatment |
| --- | --- | --- |
| Reusable contributor and operator knowledge | `docs/guides/` | Maintained instructions, checked against current behavior |
| Proposals still in flight | `docs/rfc/`, `docs/design/` | Deleted once the change lands; the decision lives in code and `docs/constitution.xml` |
| Proof for a change: logs, measurements, screenshots | PR body and CI artifacts | Not committed to the repository |
| Input a test reads | `test/fixtures/`, or a `fixtures/` folder beside the dashboard test | Source; only what a test opens |
| Dashboard reproduction fixture source | `dashboard/fixtures/<topic>/` | Source, with dashboard dependencies; output goes under `artifacts/dashboard/` |
| New local measurements, screenshots, generated reports and scratch output | `artifacts/<topic-or-run>/` | Git-ignored working output; captured Dune rules are not evaluated; no automatic deletion |
| Keeper runtime records | `<base-path>/.masc/` | Owned by the running product; use its tools and APIs |
| Published report catalog | `<base-path>/.masc/published_artifacts/` | Managed publication metadata; bodies use the blob store |

The repository keeps no research notes, reports, audits or evidence bundles.
Put the findings a change depends on in its RFC or PR body. Do not create a
repository-local `knowledge/` tree. An operator's independent workspace
knowledge base is outside this repository's ownership.

## Capture and prove

1. Write a new run into `artifacts/<topic-or-run>/`. Keep distinct runs separate
   when comparing before and after results.
2. Select the proof needed for the change. Check for credentials, private
   conversations and host-specific data before including it in a PR.
3. Write the source head, environment, commands, observed results and
   unverified scope in the PR body. Attach captures to the PR or upload them
   as CI artifacts (`actions/upload-artifact`). Do not commit them.

Git ignores common capture extensions such as logs. Do not force-add them.

`artifacts/` is a local output directory, not the dashboard's publication catalog.
Publish a report explicitly through `keeper_artifact_publish` or the published
artifact API. The product does not recursively index arbitrary folders. See
[report publication](../design/report-artifacts.md#storage-and-authority).

Existing benchmark datasets and package fixtures keep their documented input
contracts.

Release proof generated by `scripts/release-evidence.sh`, `make release-evidence`
and the Keeper lifecycle runner goes under `artifacts/release-evidence/` by
default. Explicit output arguments still select another destination. Feedback
loop measurements go under `artifacts/feedback-loop/` in the script's repository,
including when the script is invoked from another working directory.

## Clean local folders

Inspect tracked files, current script/configuration references and active use
before removing a folder. An ignored path can still contain runtime state or
unsubmitted work. In particular, repository `logs/` holds supervisor recovery
records.

Remove known disposable caches and genuinely empty folders. Tools may recreate
their caches. Preserve run records, source edits and old dashboard copies under
`artifacts/<cleanup-run>/` when clearing their old locations; record each original
and new path. Keep the active `assets/dashboard/` bundle in place.

For a finished worktree, confirm its PR merged and inspect both tracked and
untracked changes. Preserve needed ignored output before `git worktree remove`.
Do not force removal of an unfinished checkout or clean another active worktree.

## Runtime boundary

Resolve the runtime root from the server's effective base path. With base path
`/path/to/workspace`, it is `/path/to/workspace/.masc`, regardless of the checkout's
current working directory. Runtime `evidence/`, blobs and published artifacts are
different owned stores, not aliases for repository documentation. Do not rename
or merge them as a repository cleanup.

At startup the original-request body inventory preserves live bodies even when
no live owner record names them. The startup log reports the count and logical
bytes of live bodies not protected by the digests of the live records it read,
or reports the inventory as unavailable. Settled owner records are not read, so
a live body that only a settled record names is counted too. The count is not a
complete count of missing owners: a digest protects matching bodies in every
scope, and archived bodies and incomplete staging files are excluded. These
retained bodies can accumulate and the startup inventory hashes them again on
each start; the reported elapsed time helps show that cost. A preserved body
alone does not establish its original owner or whether its request was
dispatched.
