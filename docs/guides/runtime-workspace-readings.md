# 작업공간별 공유 Runtime 조회

Dashboard의 공유 provider/model catalog와 resolved runtime 목록은 현재 확인된
작업공간에 속한다. Keeper 설정·상세·사이드바 등 여러 화면은 같은 조회를 공유한다.
작업공간을 바꾸면 이전 목록을 즉시 숨기고 이전 요청을 취소한 뒤 새 작업공간을 읽는다.
이미 열려 있는 화면도 이 변경을 받는다. A → B → A로 돌아와도 첫 A 요청의 늦은
결과나 오류를 새 A 조회로 받아들이지 않는다.

작업공간 확인이 끊기면 조회를 보내지 않고 확인이 필요하다는 오류를 표시한다.
연결을 다시 확인하면 앞서 요청한 목록을 자동으로 읽는다. 새 작업공간의 조회가
실패했을 때 이전 작업공간의 결과로 대신 표시하지 않는다. Fleet의 런타임 후보 표도
조회 실패를 후보 없음과 구분한다.

같은 작업공간에서는 화면이 다시 그려질 때마다 재시도하지 않는다. 실패한 조회는
기존 새로고침 동작으로 다시 요청한다. 명시적인 새로고침이 실패하면 호출 화면에도
실패를 전달하므로 설정 저장 후 화면 갱신이 끝난 것으로 오인하지 않는다.

이 동작은 두 공유 목록을 대상으로 한다. Overview의 별도 usage/metrics 조회,
ConfigResolutionPanel의 probe와 Keeper 설정 문서 자체는 독립적인 상태를 가진다.
이 가이드는 그 모든 조회의 작업공간 격리나 실제 모델 동작을 보증하지 않는다.
