### Added

- A `muse-serve` runtime protocol: a runtime.toml provider with
  `protocol = "muse-serve"` runs Keeper turns on Muse Code through
  `Keeper_muse_runtime`, and fusion panelists run one `muse serve` turn.
  Muse Code reads `max-prompt-bytes` and installs through
  `masc prerequisite-actions muse-code`. It takes no output schema, so no
  exact-output lane may list it: the lane writers and first-run setup leave it
  out, and a runtime.toml whose `cli_slots` names it does not load. A Muse Code
  session the host reports on another model than the configured one is
  refused. The seed declares `muse_code.muse-code-spark-1-3` without
  assigning it (#39272).
