0.2 Continuous Keeper 계약

최상위 liveness 불변식. 명시적 operator stop, sandbox/security boundary 침해, transcript·durable authority 손상, 이미 발생했을 수 있는 외부 효과의 중복 위험만 Keeper 또는 해당 effect lane을 멈춘다. Provider·connector·projection·개별 work 실패는 Keeper 전체를 멈추지 않는다.
병렬의 정확한 의미. 같은 Keeper의 state-changing turn을 동시에 여러 개 commit하지 않는다. Owner 직렬화는 중복 효과 방지 권위로 유지한다. 대신 Schedule·Task·Board·Goal·IDE·Comment·Fusion은 같은 Keeper의 도구·비동기 source로 동시에 열려 있고, active queue가 공정하게 interleave된다. Fusion·Schedule·IDE ingest 같은 외부 작업은 비동기로 병행되며 결과 commit만 Owner에서 직렬화한다.

1. 이 시스템이 하려는 일

Product mission

일회성 챗봇을 장기 실행되는 책임 주체로 바꾼다

Keeper는 사람·스케줄·보드·HITL·Fusion·connector가 만든 입력을 받아 적절한 모델/CLI runtime과 도구를 실행하고, 중단·재시작·provider 장애가 있어도 무엇을 시작했고 어디까지 효과가 발생했는지를 보존하는 MASC의 resident agent control plane이다.

제품이 사용자에게 약속해야 하는 결과는 단순한 “모델 호출 성공”이 아니다. 입력 수락 → 권한 있는 실행 → 외부 효과 통제 → 내구 상태 갱신 → 원 요청자에게 결과 전달이 한 상관관계로 설명돼야 한다.

해야 한다
한 Keeper의 실행 직렬화, durable intake, provider failover, Gate/HITL, restart-safe continuation, source settlement, 결과 전달.
동일해야 한다
Owner, typed input identity, checkpoint/effect boundary, terminal schema, task completion authority.
달라도 된다
direct latency 정책, autonomous cadence/ACK, Codex·Claude native session, provider 내부 tool loop.
목표가 아니다
LLM 생성의 global exactly-once, 모든 projection의 원자적 동일성, provider 내부 구현의 MASC식 복제, 무한 항상성.

2 · AuthorityOwner가 turn을 직렬화하고 durable source가 exact input을 소유
3 · ExecutionRuntime lane → Agent Core/official client → tool/Gate/checkpoint
4 · Settlementresponse, receipt, Owner meta, FSM, source ACK/terminalize
5 · User outcome원 dashboard/Slack/Discord/schedule destination으로 최종 답 전달 — 브랜치 authority 반영, 실제 connector 완주 미증명

2. 핵심 개념과 소유권

Keeper

persona·policy·memory·runtime assignment를 가진 장기 실행 actor의 제품 단위.

intent: keepers/*.toml · state: Owner meta

Owner

같은 Keeper의 direct/autonomous turn과 operation을 한 번에 하나만 실행시키는 authority.

Keeper_owner_registry + operation store

Stimulus

Board, Schedule, Fusion, HITL, Connector 등 비동기 입력의 closed typed value.

durable keeper event queue + pre-state WAL

Runtime lane

Keeper가 사용할 모델/CLI 후보와 순서를 정한다. 실제 winner가 checkpoint owner도 결정한다.

runtime.toml loaded_state Atomic.t

Agent execution

prompt/history를 받아 모델과 도구를 반복 실행한다. MASC Agent Core 또는 official-client native session을 사용한다.

Keeper_agent_run + Runtime_execution

Gate

외부 효과에 대한 승인·보류·재실행 가능성을 exact request와 effect outcome으로 관리한다.

Gate journal + approval queue

Checkpoint

재시작·resume의 실행 위치와 effect boundary. provider retry 가능 여부를 가른다.

Agent Core checkpoint or official-client session store

Receipt / projections

실행 사실을 audit·metrics·timeline·usage 표면으로 투영한다. command authority가 아니다.

execution receipt → manifest/TurnRecord/activity/metrics

Delivery obligation

최종 response와 원 채널 좌표를 결합해 사용자에게 전달하고 결과를 durable하게 정산해야 하는 제품 계약.

Keeper_continuation_delivery_intent/store/publisher · live acceptance 대기
