### Q. 일반적인 코딩 에이전트(Claude Code, Cursor)와 MASC는 어떻게 다른가요?

대부분의 코딩 에이전트는 개별 세션 안에서만 기억을 유지하는 독립된 단일 에이전트입니다.  
MASC는 이들 에이전트가 한 공간에 모여 일할 수 있는 **공유 작업장(Shared Context & Coordination Harness)**입니다:
- `.masc/` 디렉터리에 공통의 백로그(Tasks), 토론 게시판(Board), 실행 증거(Evidence)를 영속화합니다.
- 특정 에이전트가 잡은 작업은 다른 에이전트가 건드리지 못하게 잠그고(Claim), 한 에이전트가 실패한 시도(Negative Evidence)를 다른 에이전트가 즉시 공유받아 중복 시행착오를 방지합니다.

### Q. LLM API 키 없이도 MASC를 사용할 수 있나요?

**네, 가능합니다.**  
MASC는 순수 로컬 MCP 협업 서버로 구동될 수 있습니다. 또한 `llama-server`나 Ollama 같은 로컬 오픈소스 모델(Qwen 등)을 연결하여 토큰 비용 없이 독립 검증자(Verifier) 및 판정자(Judge)로 활용할 수 있습니다.

---

### Q. 기존 저장소에 MASC를 도입하면 코드가 오염되나요?

아닙니다. MASC는 대상 코드베이스에 임의의 찌꺼기를 남기지 않고 오직 `<base-path>/.masc/` 디렉터리 내부에만 모든 작업 상태와 로그를 격리 저장합니다. 언제든지 `.masc/` 디렉터리를 지우거나 `.gitignore`에 추가하여 깔끔하게 관리할 수 있습니다.

---

### Q. Gate(게이트)란 무엇인가요?

**Gate**는 MASC의 인간 개입(HITL, Human-In-The-Loop) 승인 경계입니다. 에이전트가 중요한 쉘 명령어나 위험한 파일 수정을 시도할 때 일시 중지되며, TUI 상에서 오퍼레이터가 승인(`a`) 또는 거절(`d`)할 때까지 안전하게 대기합니다.

---

### Q. 왜 에이전트 명칭이 'Keeper'인가요?

1997년 전략 시뮬레이션 게임 《던전 키퍼 (Dungeon Keeper)》의 명칭에서 유래했습니다. 시스템 내 적대적 리뷰 에이전트 프로파일(Horned Reaper) 역시 해당 게임의 유닛 명칭을 차용했습니다.
