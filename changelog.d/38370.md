### Fixed

- `POST /api/v1/keepers/<name>/config` refusals now report `config_applied` from what the update actually left on disk, not a value written at the call site. A refusal before the write (an unknown `network_mode`, a shutdown preflight failure) answers `503 keeper_config_update_refused` with `config_applied: false` and `runtime_sync: "not_attempted"` instead of `keeper_runtime_sync_failed` with `true`. A publication exception that was rolled back answers `keeper_config_publication_rolled_back` with `false`. The `keeper_config_write.applied` receipt is derived from the same value (#38370).
