# RFC: 관전 화면의 surface 경유와 포커스 모드

- 상태: 1단 머지(#35007). 이 문서는 2026-09-10 정정본 — 초안이 "관전은
  조작 전달 불가"로 오기록한 것을 바로잡고 2단을 재정의했다.
- 관련: RFC-0439 §6.2 (실시간 티커), PR #34727 (InteractiveSurface 계약),
  PR #34892 (masc_msx_step_until_change), PR #35007 (1단), 보드 스레드
  p-af39e1cc
- 날짜: 2026-09-10 (정정)

## 문제

공유 MSX를 보는 방식이 둘인데 계약으로 묶여 있지 않다.

1. **관전 뷰** (`bin/masc_tui_msx.ml` + `masc_tui.ml`): TUI가 프레임을
   폴로 받아 ANSI 로 그린다. **관전자는 이미 머신을 몬다** — 화살표·
   스페이스·인쇄문자는 `msx_server_key` 정규화를 거쳐 `POST
   /api/v1/msx/press` 로 가고(RFC-0439 §3.3), press 직후 프레임을 다시
   받아 자기 결과를 즉시 본다. `consume` 의 "a spectator does not drive
   the machine" 주석은 이 매핑 밖의 키가 리페인트에 그친다는 뜻이었다 —
   초안은 이 주석만 읽고 "관전은 조작 전달 불가"로 오기록했다(정정).
2. **게임 패드** (`Masc_tui_interactive.msx ~fetch ~press`): #34727 이
   만든 S 계약의 첫 백엔드. 머신 키를 press 로 보내고 esc 로 닫힌다.
   계약을 부르는 소비자가 없었다 — 1단(#35007)이 렌더(픽셀)를
   계약 경유로 옮기면서 소비자 1호가 생겼다.

키퍼(msx-retro-mania)가 게임을 플레이하는 동안 사용자가 같은 화면을
보고 같은 키로 끼어들 수 있다. 키퍼 인계는 이미 사건으로 존재한다 —
press 는 주체와 함께 서버에 기록되고 관찰의 `msx_players` 로 양쪽에
보인다; 키퍼 지시서의 "다른 사람이 입력하면 관찰자로 물러난다" 규칙이
그 사건을 소비한다.

남는 갭은 소유권뿐이다: 그림은 surface 계약을 경유하지만(1단) **입력은
아직 직접 press**다. 관전 뷰의 드라이빙 입력이 `handle_input` 을 거치면
surface 는 렌더와 입력을 모두 소유하게 된다.

## 제안

관전 뷰에 **조작 모드**를 만들고, 조작 입력을 surface 계약 경유로
보낸다. 3단계로 나누고 각 단계를 따로 증명한다.

### 1단 — 관전 렌더가 surface 프레임을 그린다

`masc_tui_msx.render` 가 폴로 캐시한 프레임(`state.msx_frame`)을
그리는 대신, surface 의 `current ()` 가 돌려주는 `frame` 을 그린다.
백엔드는 `msx ~fetch ~press` 를 그대로 쓴다 — `fetch` 가 기존 폴을
감싼다. 렌더러(TUI)는 계약의 `Pixels` 만 알고 `Masc_tui_types.msx_frame`
을 직접 모른다.

- 증명: 기존 `test_tui_msx_*` 시나리오가 그대로 green (그림이 바뀌지
  않는다), 새 테스트가 `current ()` 를 거친 프레임 픽셀 수를 단정.
- 위험: `msx_frame` 이 footer/타이틀 조합(`render` 내부)에도 쓰인다.
  렌더 시그니처를 `frame option` 받는 쪽으로 좁히는 편집이
  `masc_tui.ml` 14k 줄의 여러 지점(11869-11879, 14707 부근)에 닿는다.

### 2단 — 드라이빙 입력이 `handle_input` 을 거친다

초안의 "조작 모드 진입(`i`)/모드 구분" 은 취소한다. 실제 UX 는 이미
**관전=조작 통합**이고 그대로 둔다 — 별도 모드를 만들면 있는 것을
두 번 만든다. 이 단이 남는 일은 소유권 이동뿐이다:

- `masc_tui.ml` 의 press 블록(`msx_server_key` 정규화 → `post_msx_press`
  → 재취득)이 surface 백엔드의 `press` 클로저로 들어간다. TUI 분기는
  정규화된 키를 `handle_input` 에 넘기고 반환 bool 로 press 성립 여부를
  안다. 백엔드의 `machine_key` 집합은 TUI 정규화(space/화살표/인쇄문자)
  를 커버하도록 맞춘다.
- esc/F6-F8(닫기·퀵세이브·디스크)은 surface 바깥 로컬 키로 그대로 —
  이관 후에도 같은 키가 같은 곳에 간다.
- 실행 시점: 3단 티커와 같은 PR 이 자연스럽다. `focus_changed` 를 물
  주체가 생기는 그때 입력도 같이 건드리면, 지금은 실변화가 "press 블록
  이동"뿐인 이관을 리뷰 비용 없이 태울 수 있다.
- 키퍼 인계 문서화는 이 정정으로 완료: press 는 이미 주체 기록 +
  `msx_players` 노출 + 키퍼 규칙 소비의 사슬로 되어 있다.

### 3단 — 실시간 티커가 `tick` 을 두드린다

RFC-0439 §6.2 의 티커가 Executor pool 문제를 해소하면, 프레임 폴을
`tick ~dt` 안으로 옮긴다. `focus_changed false` 로 티커가 멈추고,
surface 를 `stop` 하면 백엔드가 구독을 정리한다. 이 RFC 의 범위 밖,
계약의 `tick`/`stop` 이 이 단을 위해 존재한다.

## 하지 않는 것

- 렌더러 교체(ANSI → Kitty/Notty): 계약이 `Pixels` 로 이미 길을 열어
  두었다. 프레임의 소유권이 surface 로 옮겨진 뒤 별도 작업.
- 키퍼 도구의 변경 없음. `masc_msx_press` 등 키퍼 경로는 그대로.
- 게임 시작/디스크 교체 UI 없음 — 조작 모드는 이미 돌고 있는 머신의
  키를 전달할 뿐이다.

## 증명 계획

- 1단(#35007, 완료): 그림 불변 — 기존 단정 그대로 green + "메타 픽셀은
  그리지 않는다" 단정.
- 2단(입력 이관, 3단과 동반): 이관 후에도 같은 키가 같은 곳에 간다 —
  (a) 정규화된 머신 키 → `handle_input` 참 → press (b) 로컬 키(esc,
  F6-F8, +/-) → press 안 감 (c) press 거부 → 리페인트 폴백.
- 3단(티커): 폴 대비 같은 프레임 도달 + `focus_changed false` 로
  폴 정지, `stop` 이후 재개 없음.
- 실행 증명: 키퍼 캠페인 화면에서 사용자가 직접 한 키를 넣고
  `msx_players` 에 주체가 나타나는 것으로 인계를 확인.

## 리스크

- `masc_tui.ml` 대파일 편집 — 1단에서 `render` 시그니처를 좁힐 때
  호출 지점 전수 확인(rg `Masc_tui_msx.render`) 후 기계적으로 교체.
- 입력 분배의 우선순위가 기존 뷰 조작 키와 겹치면(예: 한 글자 키)
  배율 조작을 조작 모드에서 비활성화하는 규칙이 필요하다.
- 티커 전(3단 이전)엔 조작 모드가 "프레임이 안 움직이는 조종간"일 수
  있다 — 폴 주기가 느려 체감 지연이 크면 2단 완료 판정에 상호작용
  체감(press → 다음 폴 프레임 반영)을 포함시킨다.
