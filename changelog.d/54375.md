### Fixed

- The `openai-responses` replay guard now decides identity by the item's own non-blank `id`, not by the key each capture path happens to use. The `response.output_item.done` frame keys by the event's `output_index` while the terminal `response.completed` echo keys by array position, and a blank `id` was exempt from the identity check, so two different reasoning items could be compared as one delivery and fail a whole turn with `responses_replay:conflicting_reasoning_item`. Ciphertext is now compared only when both deliveries carry the same non-blank id; otherwise the stored done item — the one OpenAI names as authoritative for replay — is kept. The terminal echo reuses the index recorded for its id and is captured in index order, and `SSEParseFailed` records the output index, item id, byte length and a ciphertext digest prefix instead of an empty `raw`, so the next failure is diagnosable without copying ciphertext, prompt or reasoning text.
