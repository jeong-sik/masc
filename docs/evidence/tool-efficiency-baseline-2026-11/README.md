# 도구 호출 낭비 기준선 (개선 전, 2026-11-04)

도구 호출 원장(`<base-path>/.masc/tool_calls`)에서 시간과 컨텍스트가 어디로 새는지 잰 값이에요.
이후 도구 개선이 배포되면 같은 스크립트를 새 기간에 돌려 이 값과 비교해요.

## 재는 방법

- 도구: `scripts/measure-tool-efficiency.py` (이 묶음을 넣은 PR의 코드)
- 원장 상태 시각: 2026-11-04T16:57Z. 이 시각에 `11-04` UTC 일 파일은 아직 쓰이는 중이에요.
- 작업 위치: `~/me` 가 base path 인 개발 머신 한 대. 이 시각 서버는 0.67.0, 커밋 `b7a4aa5a81f` 이에요.

```bash
scripts/measure-tool-efficiency.py --base-path <base> --from-date 2026-10-05 --to-date 2026-10-31 \
  --json-out before-2026-10-05_10-31.json
scripts/measure-tool-efficiency.py --base-path <base> --from-date 2026-11-01 --to-date 2026-11-04 \
  --json-out before-2026-11-01_11-04.json
```

## 읽을 때 주의

- "같은 결과를 다시 받은 호출"은 같은 Keeper 가 같은 도구에 같은 입력을 1시간 안에 다시 보내 결과 바이트가 같았던 호출이에요.
  Official client 레인(Codex 등)은 턴마다 새 컨텍스트로 시작할 수 있어서, 이 중 일부는 그 레인에 필요한 재조회예요.
  줄일 수 있는 양의 상한이 아니라 "새 정보가 없었던 호출의 수"예요.
- sleep·폴링 대기는 명령 문장에 `sleep N`, `until`, `--watch` 같은 말이 들어 있는지로 가른 값이에요. 이 보고서에서만 쓰는 휴리스틱이고 런타임은 읽지 않아요.
- 빈 입력 실패는 입력이 비어 있고 기록된 결과가 실패인 호출이에요. 인자 없이 부르는 도구가 성공한 경우는 세지 않아요.
- 같은 날 안의 회전 세그먼트는 이어서 읽지만 UTC 날짜가 바뀌는 경계의 재조회는 놓쳐요.
