# 요청한 결과를 검증하기

일상적인 읽기 작업에 전체 실험 절차를 강제하지 않는다. 반복 실측이나 동작 증명을
요청받았을 때 필요한 항목을 선택한다.

## 실행과 결과를 연결한다

| 주장 | 필요한 관측 예 |
|---|---|
| 검색했다 | 관측한 검색란에 입력·Enter/제출 호출, 실제 결과 URL·제목 읽기 |
| 링크·히스토리를 사용했다 | 관측한 링크 대상과 click, back/forward/reload 뒤의 페이지 |
| 탭을 조작했다 | open_tab 전후 목록, 실제 id, 특정 탭 close 뒤 남은 목록 |
| 화면을 판독했다 | 캡처 artifact와 그 artifact를 사용한 이미지 분석 호출 |
| 파일을 전송했다 | 실제 입력 파일과 수신 파일의 바이트·해시, 제출 호출과 수신 시점 |
| 브라우저를 종료했다 | 자신의 close 결과와 후속 세션/driver 상태 |

실측에서는 source commit·실행 파일 hash·runtime instance를 기록하고 도중 변경을
구분한다. model tool call의 시작·종료·실제 인자·오류·artifact를 연결한다.
운영자의 별도 HTTP 캡처는 모델이 생략한 screenshot 호출을 대신한 것으로 세지 않는다.
도구 호출 성공 수, 기대한 웹 결과, 전체 요청 완료 여부를 각각 보고한다.

보완 지시가 필요했던 실행과 최초 실행을 나눠 보존한다. 같은 입력의 실패를 반복해
숫자를 늘리기보다 새 관측이나 수정된 조건에서 필요한 부분을 다시 확인한다.
실행하지 않은 단계는 실패 원인과 함께 미완료로 남긴다.

## TUI와 이미지

브라우저 PNG, Keeper artifact, TUI가 내보낸 이미지 bytes를 해시로 연결할 수 있다.
실제 PTY의 이미지 프로토콜 출력 검증과 물리 터미널 화면의 렌더링 검증은 별개다.
어느 것을 측정했는지 명시하며 unsupported terminal에서도 표시된다고 확대하지 않는다.

## 종료와 자원

Keeper의 `Finalized`만으로 sandbox VM이 사라졌다고 판단하지 않는다. 종료 전
자신의 정확한 VM 식별자를 기록하고, 종료 후 같은 식별자가 목록에 없는지 확인한다.
목록 API가 실패하면 부재 미확인으로 남긴다. 수동 stop/delete가 필요했다면 자동
정리와 구분하며, 다른 Keeper나 공유 container service를 함께 정리하지 않는다.

## 증거 보존

공개 보고서는 필요한 URL·제목·호출 메타데이터·해시·허용된 화면을 중심으로 만든다.
인증 토큰과 개인 세션 자료를 포함하지 않는다. 원문 페이지 본문이나 모든 로그를
통째로 공개하지 않는다. 오래된 실패 기록은 현재 기능의 부재를 증명하지 않는다.
이번에 실제로 사용한 버전·모델·사이트·동작 범위와 미측정 항목을 표시한다.
