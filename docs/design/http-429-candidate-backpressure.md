# HTTP 429 candidate backpressure

The provider transport maps HTTP 429 through `Provider_failure_attribution.core_error_of_http_error` to `Error.Api (Retry.RateLimited ...)`. The Keeper driver previously observed only `Provider.RateLimit` and `Provider.HardQuota`; its purported transport fixture manually converted 429 into the former, hiding the production variant gap.

The driver now observes actual `Api.RateLimited` and coarse `Provider.RateLimit` as unknown-scope candidate backpressure. Their optional usable `Retry-After` survives; neither establishes a credential quota. True `Provider.HardQuota` and `Api.PaymentRequired` retain the shared credential quota path. Ordering performs one stable partition across both observation classes before a fresh walk and after failures, preserving resolvable candidates ahead of missing rows. Every candidate remains eligible, even when all have observations. No wait, retry budget, synthetic cooldown, or new admission gate is added. Existing checkpoint/effect retry fences remain authoritative.

Candidate observations live in `Runtime_lane_preference` cells attached to materialized `Runtime.t` values. Normal catalog lookups return the existing snapshots. Catalog publication reuses a cell only when the runtime ID, declared provider/model/binding, and frozen opaque `Agent_core.Binding_identity` agree. Unchanged reloads preserve observations; changed endpoint/model/credential bindings do not inherit an old response. The driver captures the cell before dispatch. Secret values and full digests are neither exposed nor serialized. HTTP identity construction failures retain their reason in a separate typed state from official CLI runtimes. Neither can establish equality across materializations, and neither adds a dispatch gate.

A usable provider delay expires the candidate observation at its stated boundary. Without a hint, no expiry is fabricated. An actual successful attempt clears candidate backpressure even with an unexpired hint; the separate hard-quota window retains its existing semantics. Observations are process-local and removed bindings are collectible with their last in-flight snapshots.

Regression cases use the actual transport error projection to cover same-credential sibling eligibility, disjoint fallback, repeated resolution and unchanged reload, changed credential reference, credential rotation under the same reference, retained body/header hints, all-demoted fallback, and successful clearing. Pure state cases cover exact hint expiry, absent and invalid hints, and older observations. Existing hard-quota sharing, frozen scope, overflow, deferred shaping, and effect fencing cases remain in the driver suite.

Validation at source submission: OCaml parser and `git diff --check` only. Behavior tests and builds have not run locally; remote targeted suites are `test_keeper_turn_driver_failover`, `test_runtime_lane_preference`, `test_runtime_quota_window`, and `test_runtime_per_keeper_routing`. This source correction does not establish a deployed fix or a measured reduction in live 429s. It does not infer account exhaustion or concurrency limits from the coarse response, and does not redesign lower provider-specific `complete_sync` error flattening.
