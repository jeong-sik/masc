# Tools 화면 "도구 실행 통계" 실패율 그래프 (2026-11-09)

호출 수 그래프에 실패 선을 같이 그리면 실패 선이 바닥에 붙어 평평해요. 7일 · 시간별 창에서 호출 축은 0 ~ 3,137회이고 시간당 실패는 최대 46회라서, 실패 선의 가장 높은 점이 축 높이의 1.5%예요. 실패가 몰린 시간을 찾으려면 구간마다 실패의 몫을 따로 그려야 해요. 그래서 「구간별 실패율」 그래프를 더했어요.

## 바뀐 것

- `ToolSeriesCharts` 가 그래프 넷을 2×2로 놓아요. 위쪽은 호출 수와 실패율이고 아래쪽은 실행 시간 합계와 지연 p50 / p95예요. 폭 768px 미만에서는 한 줄에 하나예요. 전에는 그래프 셋을 한 줄에 놓았어요.
- 실패율은 구간의 실패 수를 구간의 호출 수로 나눈 값이에요. 호출이 없던 구간은 0%가 아니라 끊김이에요(`failureRatePercent` 가 null 을 돌려줘요). 처음과 끝의 덜 찬 구간은 다른 그래프처럼 빼요.
- 호출 수 그래프의 실패 선은 그대로예요. 실패율 그래프와 호출 수 그래프는 같은 줄에서 가로 시간축이 같아서, 실패율이 튄 시간의 호출 수를 바로 옆에서 봐요.
- 서버 응답(`/api/v1/tool-metrics/series`)은 바뀌지 않아요. 실패율은 응답의 구간별 `call_count` 와 `failure_count` 로 화면에서 계산해요.

## 어떻게 찍었나

1. 합성: `pnpm --dir dashboard run test:e2e:tool-series`(`scripts/harness_dashboard_tool_series_e2e.sh`)가 vite 를 띄우고 `dashboard/e2e/tool-series.mjs` 를 돌려요. 이 시험에 실패율 그래프의 존재, 선 1개 이상, 호출 없던 구간이 끊김(선 2개로 갈라짐)인지 보는 검사를 더했어요.
2. 장부: 같은 vite 와 같은 브라우저(Playwright 1.61.1, 시간대 Asia/Seoul)에서 서버 응답만 로컬 장부(`~/me/.masc/tool_calls`, 11-02 ~ 11-09)로 계산한 값으로 바꿔 내줬어요. 실패는 장부의 `disposition == "failed"` 예요. 서버 메트릭 저장소(`tool-metrics.sqlite3`) 값과는 조금 다를 수 있어요. 이 계산 스크립트는 저장소에 넣지 않았어요(장부를 읽는 일회용이에요). 로그인과 토큰은 쓰지 않았어요.

## 읽는 법: 실측 예

- 7일 창에서 호출 수 그래프만 보면 실패는 평평해요. 실패율 그래프는 시간마다 다른 값을 보여 줘요.
- 11-08 18시와 19시(KST)는 호출이 많은 시간이에요. 18시는 836회 중 43회(5.1%), 19시는 623회 중 26회(4.2%)가 실패했어요. 24시간 창의 맨 앞 구간(4.2%)이 이 19시예요. 18~20시의 호출 1,459회 중 실패 69건을 장부에서 세면 `remote_ssh_disk_low` 가 53건(리뷰 endpoint 셋, 22건 + 18건 + 13건, Execute 51건과 Grep 2건)이에요.
- 호출이 적은 시간의 비율은 크게 흔들려요. 7일 창에서 가장 높은 9.6%는 11-03 19시이고 호출 73회 중 7회예요. 그 시간의 호출 수 그래프는 골이에요. 최소 호출 수 기준선은 두지 않았어요. 기준선 값을 정할 근거가 없어서 호출 수 그래프를 옆에 놓는 쪽을 택했어요.

## 못 본 것

- 로그인한 실서버의 Tools 페이지. 로그인과 번들 설치는 사용자 몫이에요.
- 그래프 점의 툴팁에는 실패율만 나와요(`7/73` 같은 개수는 없어요). 개수를 넣으려면 공용 `ObservedMetricChart` 의 점 모양을 바꿔야 해서 이 변경에 넣지 않았어요.
- 이 폴더의 사진은 이 변경을 넣은 소스를 vite 개발 서버로 띄워 찍은 것이에요. 서버에 설치된 번들(`~/me/assets/dashboard`)에는 이 그래프가 없어요.
