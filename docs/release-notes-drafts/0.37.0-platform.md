## Added

- The awaiting verification endpoint (`GET /api/v1/verification/requests?view=awaiting`)
  now reports the intended verdict type (`intent: "complete" | "cancel"`). Previously,
  awaiting items joined only by request ID against the backlog without distinguishing
  cancellation requests from completion requests. Because cancellation requests can
  only be resolved by an operator's verdict, this left operator-needed cancellations
  indistinguishable from ordinary verification flows in dashboard views (#37970).
- The Xiaomi MiMo-V2.6 model (`mimo-v2.6`) is registered in the model catalog
  (1.02T total / 42B active MoE, 1M context, `openai_chat` wire, `thinking_object_only`
  control, matching sibling `mimo-v2.5-pro`).
  UPGRADE: `mimo-v2.6` is added as a catalog-only definition; runtime router bindings
  remain unassigned until vendor endpoint routing is established (#38123).

## Changed

- The operator Attention overview list removes the repetitive `needs operator attention: `
  prefix from each line, displaying entries formatted as `[warn] — <keeper>: <reason>`.
  This recovers 27 columns of horizontal space on narrow screens so operators can
  see the actual underlying cause before truncation (#37876).
- Server boot now handles an unreadable goal store (`goals.json`) gracefully. Rather than
  aborting startup or corrupting existing goals, the server logs a single `INFO` line
  via `Goal_store.unavailable_to_string` and continues boot, keeping the existing
  file intact for manual recovery (#37889).

## Fixed

- Dashboard test suite reliability restored on `main`: 8 failing `vitest` tests across
  dashboard components and integrations were fixed by partially mocking `api/core` via
  `importOriginal`, updating mock imports for lane-addons menus, and fixing checkbox
  label selectors (#37886).
- HTTP/2 request body processing enforces the standard 20MiB limit (`MASC_MAX_BODY_BYTES`)
  matching HTTP/1.1 behavior, rejecting oversized payloads with HTTP 413 Payload Too Large.
  Additionally, `POST /graphql` now verifies client authentication before reading request
  bodies, immediately returning HTTP 401 Unauthorized for unauthenticated requests rather
  than buffering unauthenticated payloads into memory (#37893).
  UPGRADE: HTTP/2 requests exceeding 20MiB are rejected with 413, and unauthenticated
  `POST /graphql` requests over HTTP/2 are rejected with 401 immediately prior to body ingestion.
- Categorical reasoning-effort contracts (`low`, `medium`, `high`) are now properly
  matched for native model providers (such as `[[providers]] id = "claude"`). Previously,
  configured providers only looked for provider-tagged catalog rows and ignored bare
  catalog entries like `claude-fable-5`, causing requests with effort parameters to be
  erroneously rejected (#37924).
- Reliable Change G1 goal run observation decoding introduces `Usage_malformed of Yojson.Safe.t`
  to represent non-object `usage` fields. Corrupted or unexpected usage values are no longer
  coerced into empty association lists (`Assoc []`), preventing corrupted observations from
  masquerading as valid flat-format fallback usage records (#37932).
- Strict chat store loading (`load_all_result`, used by the Librarian) now halts with a
  file path and line number error when encountering an unparseable `surface` row, preventing
  messages from external platforms (such as Slack or Discord) from being misattributed to
  direct channels (#37934).
- Deployment preflight checks (`deployment_preflight_helper validate-stores`) now validate
  per-keeper Librarian range commit receipt files (`<config>/keepers/<keeper>.librarian-range-commit.json`),
  preventing deployments with unreadable receipts that would subsequently block all keeper
  memory write operations (#37938).
- Tool execution runtime fallback sends original text content when unsupported modality
  filtering (`strip_unsupported_modality_blocks`) strips all media blocks. This prevents
  sending literal `"[]"` when `content_blocks` evaluates to `Some []` (#37939).
- HTTP/2 response streaming flushes pending data across client flow-control window updates
  before closing the stream. Previously, responses larger than the client's initial window size
  (65535 bytes) were truncated by immediate stream closure despite returning HTTP 200 (#37942).
- Boundary module registry `docs/rfc/RFC-0086-keeper-namespace-boundary-modules.txt` adds
  `antigravity_input_frame`, restoring compliance with the RFC-0086 keeper namespace invariant
  test suite (#37950).
- Human-in-the-loop (HITL) gate resolution distinguishes execution occasions (`First_commit`,
  `Boot_replay`, and `Same_request_resubmitted`). Only `First_commit` records audit ledger
  `resolved` entries, logs, and notifications, eliminating redundant ledger writes when
  unconsumed deliveries are replayed across server reboots (#37981).
- Replaced live keeper identity `sangsu` with fictional name `yeongsu` in `operator_digest.mli`
  doc comment examples to comply with the concrete keeper identity test invariant (#38020).
- Operator decision endpoints (`POST /api/v1/keepers/ask-answer`, `POST /api/v1/keepers/tool-approval`,
  and `POST /api/v1/keepers/turn/interrupt`) now record the authenticated principal (`ctx.caller`)
  in audit records, responses, and ledgers rather than trusting caller-provided `actor_id` values
  in request bodies (#38038).
  UPGRADE: Operator decision endpoints attribute actions to the authenticated caller identity.
  Caller-supplied `actor_id` values in request payloads are disregarded and no longer override
  the authenticated identity.
- MCP schedule tools (`masc_schedule_create`, `masc_schedule_update`, `masc_schedule_cancel`,
  `masc_schedule_note_add`) enforce authenticated actor binding. Actor IDs are bound to the
  authenticated caller (`ctx.caller`). If an argument provides an actor ID that does not match
  the authenticated caller, the request is rejected with an `actor_mismatch` error. The default
  fallback of `"operator"` for `requested_by` has been removed (#38054, #38087).
  UPGRADE: MCP schedule tools reject calls where `*_by_id` contradicts the authenticated caller
  identity. Anonymous callers must explicitly declare their identity rather than defaulting to `"operator"`.
- Verification prompts (`verification.md`, `goal_verification.md`) removed references to
  non-existent tools (`keeper_skill`), clarified web fetching evaluation standards for `masc_web_fetch`,
  and aligned goal lookup guidance with the schemas actually available during verification (#38099).
