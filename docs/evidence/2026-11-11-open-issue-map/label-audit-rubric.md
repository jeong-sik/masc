# 이슈 영향 등급 다시 매기기 (눈가림)

`sample.json` 에 GitHub 이슈의 번호·제목·본문이 있다. 기존 라벨은 지웠다. 이슈마다 두 가지를 판정한다. 본문에 적힌 사실만 근거로 쓴다. 이 폴더의 두 파일만 읽는다. GitHub, 저장소, 다른 폴더, 웹을 보지 않는다(기존 라벨이 보이면 눈가림이 깨진다).

## 1. observed (일어난 일인가)
- `true`: 본문이 실제로 일어났다고 적었다. 로그 줄, 횟수, 시각, 라이브에서 본 값, 재현한 명령과 결과 같은 것이 있다.
- `false`: 코드를 읽다 찾았거나 리뷰·감사에서 "그럴 수 있다"고 지적한 것이고, 일어난 기록이나 재현 결과가 없다. 본문이 "재현하지 않았다", "라이브 0건"이라고 적은 것도 여기다.

## 2. impact (일어났을 때의 결과. observed 와 따로 매긴다)
저장소의 라벨 설명 그대로다.
- `breaks-continuity`: 1순위. 턴이 멈추거나 앞 내용을 기억 못 한다. 이러면 제품이 아니다.
- `breaks-collab`: 2순위. Keeper 끼리 말이 안 통하거나, 결과가 엉뚱한 곳으로 간다.
- `blinds-operator`: 3순위. 동작은 하는데 사람이 상태를 볼 수 없다.
- `degrades`: 4순위. 느리거나, 불편하거나, 결과가 덜 정확하다.
- `internal`: 5순위. 개발할 때만 불편하다. 쓰는 사람은 모른다.

`impact` 는 본문이 적은 결과가 일어났을 때 가장 무거운 등급으로 고른다. 일어났는지 아닌지는 `observed` 에만 적고 `impact` 를 낮추는 데 쓰지 않는다. 둘 사이에서 망설여지면 가벼운 쪽을 고르고 `unsure` 를 true 로 적는다.

## 출력
이 폴더에 `relabel.json` 으로 JSON 배열을 쓴다. 항목은
`{"number": 12345, "observed": true, "impact": "<등급>", "unsure": false, "why": "한 문장 근거"}` 이다. 모든 이슈를 판정한다.
