Iteration 1 — Baseline (2026-08-15, 코드 변경 전)

판정 4줄.

  1. 실제 폴백 체인 3단(SearXNG → DuckDuckGo → Bing RSS) 중 안정적으로 결과를 주는 provider는 0개다. 유일한 정식 provider인 SearXNG는 40분 사이 20건 → 10건 → 0건 전면 붕괴로 퇴행했고, 그동안 HTTP는 계속 200이었다.
  2. SearXNG의 붕괴는 Docker와 무관했다 — 컨테이너는 Up 2 hours 상태에서 빈 결과를 반환했다(상류 엔진 소진). 즉 실패 층이 둘이다: 컨테이너 다운, 그리고 컨테이너 생존 중 상류 소진. 어느 쪽이든 도구는 빈 성공으로 보고한다.
  3. 무자격 폴백 둘 중 DuckDuckGo HTML은 3회 전부 봇 차단(202, 결과 앵커 0), Bing RSS는 1건→10건→10건으로 쿼리·시점에 따라 요동한다. 폴백이 아니라 도박이다.
  4. 외부 MCP surface(:8935/mcp)에는 web 도구가 노출되지 않는다(40개 전부 coordination 도구). WebSearch/WebFetch는 keeper 내부 전용이므로, 도구 레벨 검증은 외부 호출이 아니라 CI feature test + keeper 턴 경유로만 가능하다.

Iteration 2 — 재기동 직전 베이스라인 (2026-08-16 01:33 KST, r5)

원본 증거: docs/evidence/web-tools-bench-2026-08-16-r5.json. 측정 시점의 main에는 PR-1(본문 1회 적재 + TTL 900s)~PR-4(Brave LLM Context)가 병합돼 있었으나 서버(:8935)는 재기동 전 옛 바이너리(0.22.0)다. 즉 이 측정은 코드 반영 전 런타임의 마지막 관측이며, 재기동 후 Iteration 3의 대조군이다.

판정 3줄.

  1. SearXNG는 0건 / 0건 / 0건 (HTTP 200, 2196/538/1865ms) — Iteration 1에서 관측한 붕괴가 하루를 넘겨 지속된다. 회복 없음. "컨테이너 생존 + 상류 소진 = 빈 성공" 상태가 일시 장애가 아니라 기본 상태임을 시계열이 확정.
  2. 무자격 폴백도 동결 상태 그대로: DuckDuckGo HTML은 봇 차단 지속(HTTP 202, 결과 앵커 0), Bing RSS 계측기는 10건 — 상류 웹은 살아있고 SearXNG 층만 죽어 있음을 분리 확인.
  3. MCP 외부 surface는 도구 40개, web 도구 0개로 불변(재기동 전이므로 예상과 일치). 이중 적재 제거의 payload 수치는 외부에서 잴 수 없고, CI에 배선된 runtest-test_tool_misc_coverage가 page_content = `Null 핀과 grounded envelope 계약으로 고정한다 — 이 스택의 CI green이 그 실행 증거다.

Iteration 3 — 스택 전체 반영 후 (2026-08-16 02:37 KST, r6)

원본 증거: docs/evidence/web-tools-bench-2026-08-16-r6.json. RFC-0381 스택 8개 PR(#28747, #28760, #28753~#28758)이 main에 전부 병합됐고, 서버(:8935)는 재빌드된 바이너리(main HEAD 4f3cf7ae7d = PR-7)로 재기동된 상태의 측정이다.

판정 3줄.

  1. 새 바이너리 정상 서빙 — initialize·tools/list 성공, 외부 MCP surface는 coordination 40개 그대로 (web 도구 비노출은 설계 유지). 스택이 외부 표면을 바꾸지 않았다는 무회귀 확인.
  2. SearXNG 상류는 여전히 0건 × 3 (HTTP 200) — 다만 새 코드에서 이 상태는 더 이상 "빈 성공"으로 조용히 흡수되지 않는다. 자격 없는 provider는 체인에서 배제되고 빈 체인은 Config 실패로 드러난다는 계약은 CI feature test(Tool_misc.dispatch 실경로, runtest-test_tool_misc_coverage)가 고정하며, 이 스택의 CI green이 실행 증거다.
  3. DuckDuckGo 202 차단·Bing RSS 7건 — 무자격 폴백 2종은 코드에서 척살됐으므로(PR-2) 이 수치는 이제 도구 경로가 아니라 상류 시계열 계측기로만 남는다.

원본 증거: docs/evidence/web-tools-bench-2026-08-16-r7.json. OLLAMA_API_KEY 발급·검증 후 서버 재기동(프로세스 env 상속 확인). bench 스크립트에 Ollama 직접 프로브를 추가했다 — 서버의 fetch_ollama와 같은 endpoint·인증 헤더·body 형태로 호출하므로 유사품이 아니라 실제 dispatch 대상 provider의 수치다.

  1. 강제 적재가 98.8% 줄었다 — 검색 1회가 keeper 컨텍스트에 밀어넣는 도구 응답이 중앙값 29,433자 → 348자. 본문(3문서, 80,193바이트)은 .masc/artifacts/web-fetch/<sha256>.md로 오프로드됐고(도구 호출과 같은 초에 생성 확인), 내용은 검색 주제와 일치하는 실제 웹 문서다.
  2. 선택적 재적재가 실제로 일어났다 — 8초 뒤 sangsu가 keeper_artifact_read(sha256, offset, max_bytes)로 65,536바이트 한 페이지만 읽었다. "무조건 전부 밀어넣기"가 "필요한 문서를 페이지 단위로 골라 읽기"로 바뀐 것이 로그로 증명된다.

  4. "전"의 실패 모드가 로그에 실존한다 — 옛 바이너리 시절 sangsu의 검색 4연발이 148,330바이트 대화 원자를 만들어 입력 예산(135,852바이트)을 초과, Hook model_input_projection failed ... newest atom does not fit으로 턴 자체가 죽었다. 새 구조에서는 같은 4연발이 ~1,400자다.

품질 하네스 Q1 — 고정 쿼리셋 첫 실측 (2026-08-16, web-quality r1)

계측기: scripts/bench-web-quality.py (신규) · 원본 증거: docs/evidence/web-quality-2026-08-16-r1.json. 고정 8쿼리(공식문서 2·레퍼런스 1·기술QA 1·니치 1·최신성 1·한국어 2)에 기대 도메인 포함 여부를 순위로 채점(hit@1/hit@5), 한국어는 반환 본문의 한글 비율로 채점. 채점은 결정론, 변하는 것은 provider 뒤의 웹뿐 — 그 drift를 시계열로 추적하는 것이 목적이다. 임계값·게이트 없음: 측정기다.
