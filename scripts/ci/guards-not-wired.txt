# Check scripts that nothing CI runs reaches.
#
# The list ratchets down. Wiring one into scripts/ci/run-lint-suite.sh means
# deleting its line here; a new name arriving means a guard was written and
# then left where nothing calls it.
#
# It is not an approval. Some of these are developer or operator tools that
# belong outside CI, and some are guards that should be wired and are not.
# Which is which is #34018, along with the state each was measured in on
# 2026-09-07:
#
#   red    -- run on untouched main and failed
#   green  -- run on untouched main and passed, so wiring it costs nothing now
#
# 2026-09-08: a "report" note here was first written from a grep for `exit 1`,
# which is not how a shell script says no. audit-dashboard-prompt-keys exits 2
# on its verdict and is wired now; the rest were re-read and say what their
# non-zero exit actually is.
#
# 2026-09-08: "green" turned out to be weaker than it reads. Six of the
# fifteen so marked were re-run with a violation planted and failed, and are
# wired now. Three others exit 0 no matter what they find -- there is no
# failing exit in them at all -- so passing was not evidence of anything, and
# they are marked report. Two more need the OCaml toolchain, which the lint
# job does not have; wiring them there fails on a missing binary rather than
# on the thing they check. Both are in the build job now, where the switch is.
#   report -- prints findings and exits 0 either way; wiring it enforces
#             nothing, so the work is to give it a verdict first
#   tool   -- takes arguments or a mode, or reads the operator's live .masc
#             store rather than this repository; not a standalone check
#   (unmarked) -- not run
#
# 2026-09-07: the name pattern above used to read (lint|check|guard|ratchet),
# which is every guard in this repository except the twenty-two named
# audit-*. They were not passing this check, they were not in it. Counts went
# 76/23 to 103/45.
#
