### Documentation

- RFC `a-keeper-takes-every-waiting-message-in-one-turn` proposes that a Keeper's
  chat operation claim takes every waiting message, in arrival order and each in
  its own envelope, and answers each request on its own route. The queue knows no
  work kinds. A first stage fixes four paths that stop the queue (a failed run left
  `Running`, a runtime retry keeping its old place, chat always taking a freed slot
  first, delivery holding the slot) and records run segments as observation. The
  evidence bundle `docs/evidence/chat-queue-wait-2026-11-16/` measures 934.8 queue
  hours in 2026-11-13~16 against 14.2 the three days before (#52398).
