### Changed

- Background refreshes that an HTTP read starts but does not wait for now run as background work: the `Dashboard_cache` and operator snapshot cache stale-while-revalidate refreshes, the namespace-truth shell refresh, the runtime git and probe refreshes, the briefing sections refresh and the provider usage read. Before, they inherited the read's lane and could hold a read-pool domain for their whole compute budget. A compute the read waits for (empty cache, or a refresh run inline because no root switch exists) still runs as a read. `Pool_lane.with_background` marks such work. (#46385)
