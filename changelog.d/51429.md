### Added

- A Keeper can end a chat turn to wait for the receipt of a background `Execute` run with the new `keeper_receipt_wait` tool. The next run of the same conversation starts with that receipt, and no other run reads or deletes it while the wait is pending. A request whose run ended without leaving a receipt is settled with one `Unfinished` receipt that echoes the arguments its request record kept, and a `Source_lost` resolution. The tool is offered only to runs that serve a chat execution. 가이드 없음(문서 없음) (#51429).

### Known issues

- A wait whose request has no record, or a record that is not a background `Execute` run's, is not settled: no receipt is written, the wait stays pending, and each maintenance pass logs the request. The receipt format has no way to say the arguments are unknown (#51429).

### Internal

- `Keeper_client_tool_outbox_wake.create` takes `~settle_lost_waits`, which `server_bootstrap_maintenance` binds to `Keeper_receipt_wait_sweep.settle_lost`. The wake module cannot call `Keeper_execute_background` directly because that module calls `notify` (#51429).
- `Keeper_run_tools_setup.descriptors_for_run` drops the wait tool from the descriptors of a run that serves no chat execution (#51429).
