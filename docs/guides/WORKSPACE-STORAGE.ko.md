# 저장소 문서와 실행 산출물

파일을 **무엇에 쓰는지**에 따라 위치를 정한다. 아래 경로는 런타임 경로로
명시한 항목을 제외하면 MASC 저장소 루트 기준이다.

| 자료 | 저장 위치 | 관리 기준 |
| --- | --- | --- |
| 조사, 선행 기술, 비교와 설계 분석 | `docs/research/` | 출처와 불확실성을 기록한다. 제안과 확정된 결정을 구분한다. |
| 보존할 검증 기록과 캡처 | `docs/evidence/<주제 또는 실행>/` | 필요한 자료를 선별해 버전 관리한다. 출처와 관측 범위를 보존한다. |
| 발견한 문제, 결과와 남은 작업을 설명하는 보고서 | `docs/reports/` | 사람이 읽을 결론을 적고 원자료를 복사하는 대신 검증 기록에 연결한다. |
| 반복해서 사용할 개발·운영 지식 | `docs/guides/` | 현재 동작과 맞는 절차로 유지한다. |
| 확정된 설계와 인터페이스 결정 | `docs/design/`, `docs/rfc/` | 기존 설계·RFC 절차를 따른다. |
| 대시보드 재현용 fixture 소스 | `dashboard/fixtures/<주제>/` | 대시보드 의존성을 사용한다. 실행 결과는 `artifacts/dashboard/`에 쓴다. |
| 새 측정 결과, 스크린샷, 생성 보고서, 임시 작업 결과 | `artifacts/<주제 또는 실행>/` | Git에서 제외하며 내부 Dune 빌드 규칙은 해석하지 않는 작업 산출물이다. 자동 삭제하지 않는다. |
| Keeper 런타임 기록 | `<base-path>/.masc/` | 실행 중인 제품이 관리한다. 해당 도구와 API를 사용한다. |
| 발행한 보고서의 목록 | `<base-path>/.masc/published_artifacts/` | 발행 메타데이터는 제품이 관리하며 본문은 blob 저장소를 사용한다. |

조사 문서에서 측정 결과를 해석할 수 있지만, 보존할 실행 기록은
`docs/evidence/`에 두고 링크한다. 특히 `docs/evidence/research/`는 조사를
뒷받침하는 실행 기록과 출처를, `docs/research/`는 그 분석과 결론을 담는다.
결론을 정리한 보고서는 `docs/reports/`,
재사용할 절차는 `docs/guides/`에 둔다. 저장소 안에 별도의 `knowledge/`
트리를 만들지 않는다. 운영자의 저장소 밖 개인 지식 베이스는 이 규칙의
관리 대상이 아니다.

## 캡처하고, 보존하고, 설명하기

1. 새 실행 결과를 `artifacts/<주제 또는 실행>/`에 쓴다. 전후를 비교할 때는
   각 실행을 별도 디렉터리에 보관한다.
2. 변경을 뒷받침하는 자료를 선별한다. PR에 넣기 전에 인증 정보, 비공개 대화,
   호스트 고유 정보가 포함됐는지 확인한다.
3. 선별한 자료를 `docs/evidence/`에 보존한다. README에 소스 head, 환경,
   명령, 관측 결과와 미검증 범위를 적는다. 새 실행으로 이전 캡처를 덮어쓰지
   않는다. 재현 도우미를 함께 보관해도 출력은 별도 작업 경로에 쓴다.
4. 이를 해석하는 조사 문서, 보고서나 PR에서 검증 자료를 연결한다. 익명화하거나
   재생성한 파일은 파생 자료라고 명시한다. 원본 digest를 수정된 파일의 해시로
   오해하게 만들지 않는다.

캡처 당시의 경로·해시 매니페스트는 원본 바이트를 보존한다. 파일을 옮겼다면
묶음 README에서 별도 `current-locations.json`을 연결한다. 이 색인은 보존
캡처나 편집 가능한 재현 소스의 현재 위치를 알려 준다. 옛 해시가 현재 편집본의
해시를 증명하는 것은 아니다. `scripts/check-evidence-locations.py`에 검사할
색인을 명시해 현재 위치, 보존 캡처의 바이트와 역사적 Git 객체를 확인한다.

로그 등 일부 확장자는 Git에서 제외된다. 의도적으로 보존할 개별 파일을
확인한 뒤 `git add -f -- <경로>`로 추가한다. 작업 산출물 디렉터리 전체를
강제로 추가하지 않는다.

예를 들어 대기 도구의 대안을 비교한 글은 `docs/research/`, 실제 실행의
JSON·로그는 `docs/evidence/`, 결과와 후속 작업을 정리한 글은
`docs/reports/`에 둔다. 조사 → 검증 → 보고서는 서로 링크한다.

`artifacts/`에 파일을 넣는 것만으로 대시보드에 보고서가 발행되지는 않는다.
`keeper_artifact_publish` 또는 보고서 발행 API를 명시적으로 사용한다.
임의 디렉터리를 자동으로 순회해 등록하지 않는다.
[보고서 발행 계약](../design/report-artifacts.md#storage-and-authority)을 참고한다.

기존 benchmark 데이터셋과 패키지 fixture는 각자의 입력 계약을 유지한다.
다운로드한 CI artifact 내부의 출력 폴더는 그 압축 묶음의 경로이며,
저장소 안에 또 다른 evidence 루트를 만드는 규칙이 아니다.

`scripts/release-evidence.sh`, `make release-evidence`와 Keeper 생명주기
검사기의 기본 출력은 `artifacts/release-evidence/`다. 출력 경로를 명시하면
그 위치를 사용한다. 반복 측정 로그는 다른 작업 디렉터리에서 스크립트를
호출해도 해당 저장소의 `artifacts/feedback-loop/`에 쓴다.

## 로컬 폴더 정리

폴더를 지우기 전에 추적 파일, 현재 스크립트·설정의 참조와 사용 여부를 확인한다.
Git에서 제외된 경로에도 런타임 상태나 미제출 작업이 있을 수 있다. 특히 저장소의
`logs/`에는 supervisor 복구 기록이 있고, `.tmp/`에는 검사기가 읽는 RFC 호출
문맥이 있을 수 있다.

용도가 확인된 일회용 캐시와 실제로 빈 폴더는 제거한다. 도구가 캐시를 다시 만들
수 있다. 실행 기록, 수정한 소스와 오래된 대시보드 복사본은 기존 위치를 정리할 때
`artifacts/<정리 실행>/`에 보존하고 원래 경로와 새 경로를 기록한다. 현재 사용하는
`assets/dashboard/` 묶음은 유지한다.

완료된 worktree는 PR 병합과 추적·미추적 변경을 모두 확인한다. 필요한 Git 제외
산출물을 먼저 보존한 뒤 `git worktree remove`를 사용한다. 미완료 체크아웃을
강제로 지우거나 다른 활성 worktree를 정리하지 않는다.

## 런타임 경계

실행 중인 서버의 유효 base path에서 런타임 루트를 구한다. base path가
`/path/to/workspace`이면 런타임은 `/path/to/workspace/.masc`다.
저장소의 현재 작업 디렉터리와는 별개다. 런타임의 `evidence/`, blob과
발행 자료는 각각 제품이 관리하는 저장소이며, 저장소 문서의 별칭이 아니다.
디렉터리 정리를 이유로 합치거나 이름을 바꾸지 않는다.

[검증 자료 출처 안내](../evidence/README.md), [조사 문서 목록](../research/README.md),
[보고서 목록](../reports/README.md)을 참고한다.
