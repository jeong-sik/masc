### Fixed

- A Keeper `Execute` call whose sandbox guest could not be started, adopted or replaced now fails with `code = sandbox_guest_unavailable` and `failure_stage = sandbox_guest_prepare`, not `github_identity_snapshot_unavailable`. `prepare_github_identity_secret_files` returns a typed `Sandbox_unavailable | Identity_unavailable` error, so a guest failure no longer reads as a missing `gh` permission. Execute results and errors also carry `network_mode` and, for a microVM with a backend, `microvm_backend`. (#46774)

### Documentation

- The Keeper user manual (English and Korean) lists the limits each sandbox backend enforces and adds placement examples: one Apple microVM Keeper, one Docker Keeper, and three Keepers on one SSH endpoint. The SSH endpoint runbook links to them. (#46774)
