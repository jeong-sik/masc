### Fixed

- The boot asset sync retires a dropped prompt, tool or MCP file only after every current asset holds its embedded copy (a failed write or a reset that failed after a promotion holds retirement back), so a release that moves a prompt's text into another file never leaves neither when that write fails. A retired file whose bytes differ from its recorded digest is kept beside it as `<file>.operator-edit-<hash>` before it goes, and a retired file the pass could not delete stays in `managed-assets.json` so the next boot retires it (#41572).
