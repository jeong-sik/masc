## 다음 순서

1. **협업 파일 전달 완료:** PR #35364의 같은 head에 대한 CI 결과를 확인하고, 검증된 CI 바이너리를 격리 서버에 반영한다. 디자이너의 실제 포스터를 편집자가 `received/designer-poster.png`로 받아 바이트 수·SHA256을 일치시키고, 이미지 검수와 Board 보고까지 확인한다. 기존 Goal 산출물은 보존한다.
2. **Goal 검증 재개:** 현재 exact verifier의 후보와 이미지 지원을 확인해 가용한 실행 경로를 준비한다. 같은 Kimi 쿼터 실패를 반복하지 않는다. 원래 5개 기준을 유지하고 실제 도구 사용·판정·Dashboard 표시를 확인한 뒤 사람의 최종 확인 단계로 간다. 수동 모델 전환과 자동 failover는 구분한다.
3. **공동 기억의 재사용:** 로컬 통합안의 출처 의미 오류를 검토하고, 실제 Keeper가 그 내용을 다음 작업에 활용하는지 확인한다. 제안 생성만으로 공간 기억 완성을 선언하지 않는다.
4. **실제 작업을 UI까지 연결:** 앞선 협업을 기준으로 통계, 파일 전달, diff, 설정 반영과 기억을 같은 실행에서 브라우저로 확인한다. Tools/Skills 렌더 문제와 LSP·IDE 잔여 항목을 이어서 다룬다.
5. **다른 시나리오와 지속성으로 확장:** 비코드 연구·창작과 다른 런타임으로 넓히고 10턴 및 1/2/4/24시간 연속성, 자연스러운 failover를 별도 측정한다.

다음 단계의 우선순위는 이미 시작한 협업 한 건을 실제 전달·검수·완료까지 연결하는 것이다. CI를 기다리는 동안에는 다음 의존성이 없는 조사나 구현을 진행한다.
