### Added

- A Keeper lane that runs one turn through `muse serve` (`Keeper_muse_runtime`).
  The Keeper's MASC tools reach the session through the loopback MCP bridge,
  the official-client session store records the Muse Code session under the
  new `muse` client kind, and `turn/completed` usage is reported as a turn
  total. Once the host has taken a turn in, a failed attempt is not run again
  on another candidate: `denyUnmatched` lets the host's own saved rules allow
  a built-in write, and MSP gives MASC no way to state a rule. When the
  host's own policy closes an approval before MASC's decision lands, its
  `-32051` `approvalAlreadyResolved` answer is read as the host's resolution
  and the turn goes on; only the decisions the host accepted are counted. A
  decision still unanswered when the turn completes is reported, and an
  approval answer that cannot be written fails the turn. The session's
  workspace root and the host process's working directory are the Keeper's
  playground, not the base path that holds `.masc` and its auth tokens, so
  Muse Code's file tools stay inside the playground. Its shell reaches what
  the host's own sandbox profile allows. For a `microvm` or `remote_ssh`
  Keeper the playground on this host is the bookkeeping bundle, not the tree
  MASC's file tools read on the endpoint. A changed model or playground starts
  a fresh Muse Code session. An operator interrupt ends the turn as an owner
  stop and keeps the settled session, as on the other official clients
  (#39298). No runtime selects the lane yet (#39241).
