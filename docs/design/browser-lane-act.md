# Browser Lane Act — HITL 게이트 아래 쓰기 동사 설계 (초안)

2026-09-07. browser-lane(#33768) 후속. 승인 전.

## 목적

live 레인은 읽기 전용으로 출범했다(`tabs.list`, `page.read`; 이동 동사는
거부). 이 설계는 **운영자의 실제 세션에서 클릭·타이핑을 수행하는 act
동사**를 추가하되, 사람 승인(HITL) 아래에서만 실행되게 한다.

## 원칙 — 왜 게이트가 전제인가

**읽기는 자유, 쓰기는 허가.** 운영자 로그인 세션에서의 조작은 토큰 기반
쓰기보다 폭발력이 크다: 무엇이 클릭되는지가 곧 "운영자가 했다"이다.

2026-09-07의 kinobot 사고가 이 원칙의 근거다 — keeper 지시문으로 "보내지
마세요"를 적어도 그건 **소프트 억제**였고, 토큰이 있는 부팅 창에서
스레드 답장이 나갔다. 교훈: **지시문은 잠금이 아니다. 쓰기는 경로
수준의 게이트로만 통제된다.** act 동사는 그 게이트를 통과한 요청만
실행 경로에 놓는다.

## 구조

```
keeper                    masc 서버                     운영자
  │ act 요청               │                             │
  │ page.type{tab,셀렉터,텍스트}                          │
  ├───────────────────────▶│                             │
  │                        │ 승인 카드 생성 (typed)        │
  │                        │ ├─ keeper_approval 감사 이벤트│
  │                        │ └─ 승인 큐 (ask 인프라 재사용) │
  │                        ├────────────────────────────▶│ TUI 승인 화면 /
  │                        │                             │ dashboard
  │                        │◀───────── 승인 / 거부 ───────┤
  │                        │ 승인됨: 명령을 lane 큐에 발행   │
  │                        ├──▶ 확장이 DOM에 실행           │
  │◀── 결과 receipt ───────┤                              │
```

- 승인 큐와 카드는 `masc_ask`/`masc_ask_status` 패밀리와
  `lib/keeper_approval`의 typed 이벤트·receipt 위에 얹는다. 새 승인
  상태를 만들지 않는다.
- 거부·시간초과는 실행 경로에 명령을 절대 놓지 않는다(소프트 억제가
  아닌 경로 부재).

## 동사와 분류

| verb | 도구 | 분류 | 비고 |
|---|---|---|---|
| `page.click` | masc_browser_act | **act** | 셀렉터 + 휴먼 리더블 설명 필수 |
| `page.type` | masc_browser_act | **act** | 입력 텍스트가 승인 카드에 그대로 |
| `page.goto` (live) | masc_browser_act | **act** | 이동도 내 세션의 상태를 바꾼다 |

`Browser_lane.verb_is_read` 분류에 act 등급을 추가하고, act는 act
budget을 소모한다 — 읽기 도구와 같은 "무료" 묶음에 두지 않는다.

## 승인 카드에 반드시 뜨는 것

1. 어느 탭(제목·URL)
2. 무엇을(셀렉터의 사람 말 설명 + 입력할 텍스트 원문)
3. 되돌림 가능성 여부(keeper가 판단한 근거 1줄)

텍스트 원문이 카드에 그대로 보이지 않는 승인은 만들지 않는다.

## 증분

1. **게이트 뼈대**: act 요청 → 승인 큐 → 승인/거부 → 실행/폐기의
   왕복을 ask 인프라 위에서 완성. 동사는 `page.click` 하나만.
   automation 레인(keeper 소유, 자격증명 없는 프로필)에서 먼저 —
   폭발력이 다르므로 게이트 검증의 시험장이 된다.
2. **live 레인 act**: 같은 게이트를 운영자 세션에 적용. automation에서
   게이트가 증명되지 않으면 live로 옮기지 않는다.
3. **시퀀스 승인**: 폼 채우기처럼 여러 동사를 하나의 승인 카드로 묶는
   단위와 취소 규칙.

## 열린 질문

- 승인 단위: 동사별 승인은 폼 하나에 여러 번 승인 뜬다. 시퀀스 승인의
  상한(동사 수? 시간 창?)은 얼마인가.
- automation 레인은 게이트 완화가 가능한가 — 자격증명 없는 프로필이라
  폭발력이 다르다. 완화한다면 분류는 어디에 두나.
- 승인 대기 중 탭이 닫히거나 DOM이 바뀌면: 거부로 처리하고 재요청.
  stale 셀렉터 실행 금지.
- act budget의 단위와 회복 규칙.
