# Tools 화면: 도구 실행 통계 카드를 맨 위로 옮긴 전·후 화면 (2026-11)

웹 대시보드 Lab › Tools 화면에서 `도구 실행 통계` 카드(시간별·일별 호출 수, 실행 시간 합계, 지연 p50·p95, 시간을 가장 많이 쓴 도구 표)가 화면 어디에 있는지 같은 라이브 데이터로 쟀어요.

## 결과

`24시간 · 시간별` 칩의 위쪽 끝이 스크롤 컨테이너(`.dashboard-main-scroll`) 맨 위에서 몇 px 아래인지예요.

| | 카드 위치 | 화면 전체 높이 | 화면 |
|---|---|---|---|
| 이전 | 24,889 px, 25,239 px (두 번 쟀어요) | 26,284 px, 26,634 px | [before-top.png](before-top.png) |
| 이후 | 304 px | 26,634 px | [after-top.png](after-top.png) |

- 이전에는 카드가 `시스템 도구 목록`(도구 인벤토리) 아래, 화면 맨 끝에 있었어요. 첫 화면에는 설정 경로·런타임 진단이 보이고, 통계를 보려면 스크롤을 25,000 px쯤 내려야 했어요.
- 이후에는 제목과 `인벤토리`·`도구 실행기` 버튼 바로 아래에 카드가 있어서, 첫 화면에 호출·실패·실패율·실행 시간 합계·지연 p50·p95와 차트 세 개가 들어와요.
- 카드 안의 내용은 그대로예요. 위치만 옮겼어요.
- 두 화면의 숫자(호출 21,211회와 21,224회 등)가 다른 건 라이브 데이터가 그 사이에 늘었기 때문이에요.

## 같이 확인한 것

서버가 지금 서빙하는 번들(`/dashboard/assets/lab-DUTf1DA6.js`, 81,430 B)에는 `tool-metrics/series`도 `도구 실행 통계`도 없어요. 서버는 `~/me/assets`의 옛 번들을 읽어서, 새 번들을 설치하기 전에는 이 카드가 화면에 뜨지 않아요. 이 PR은 카드 위치만 고치고, 번들 설치는 따로 해야 해요.

## 못 잰 것

- 좁은 화면(모바일 폭)에서의 배치.
- 차트 숫자가 맞는지. 이 확인은 #48248의 시험이 맡고 있어요.
- 웹소켓. 로컬 프록시가 `/ws`를 넘기지 않아서 머리말에 `재연결 중`이 찍혀요. 카드의 숫자는 `/api/v1/tool-metrics/series` 응답이라 영향이 없어요.

## 화면에서 가린 것

이전 화면에는 계정 이름이 든 절대경로가 세 곳(`CONFIG ROOT`, `EFFECTIVE BASE`, `EFFECTIVE .MASC`) 찍혀 있어서 그 글자 위에 사각형을 덮었어요. 이후 화면에는 경로가 없어요.

## 다시 만드는 법

1. `dashboard/`에서 `pnpm install --frozen-lockfile`, `pnpm build`를 돌리면 `assets/dashboard`에 번들이 만들어져요.
2. 번들 디렉터리를 `127.0.0.1`에서 서빙하고 `/api/` GET만 서버(`127.0.0.1:8935`)로 넘기는 로컬 프록시를 띄워요. 이 프록시는 저장소에 넣지 않았어요. 서버 토큰은 프록시 안에서만 쓰고 화면에는 나오지 않아요.
3. 브라우저에서 `/dashboard/#lab?section=tools`를 열고, 칩 `24시간 · 시간별`의 위치를 재요. 빌드를 바꾼 뒤에는 주소 뒤에 `?fresh=…`를 붙여 다시 불러와야 해요. 같은 주소의 해시만 바꾸면 이전 번들이 그대로 남아요.
