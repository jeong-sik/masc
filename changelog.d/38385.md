### Fixed

- The TUI approval detail draws a stored input object key by key, so a
  command line or a message body is carried whole instead of ending at the
  server's 200-byte flattened preview; an input that is not an object keeps
  the preview under a label that says it is the flattened preview (#38385).
- The whole-input fields are drawn unredacted on purpose: the approval is
  computed over the whole input, so the screen reads the same bytes the
  approval covers, and a key's own drawing pipeline escapes control
  characters instead of reapplying the queue's redaction (#38385).
