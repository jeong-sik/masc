### Performance

- `Keeper_fs.ensure_dir` no longer holds a process-wide mutex while it checks that a cached directory still exists. The check is a stat on a system thread, and `keeper_meta_path` ensures `.masc/keepers` on every Keeper meta read, so one slow stat queued every caller on every domain behind it: a fiber trace on 2026-10-28 found 1,020-2,972 s of waiting on that mutex in 180 s, and `/api/v1/gate/keepers` spending 95% of its time waiting. The directory cache is an atomic immutable set and the check and `mkdir_p` run without a lock; a directory removed outside is still made again (RFC-0474 L4g, #46681).
