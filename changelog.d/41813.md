### Changed

- A BiDi live browser connection serves `BrowserRead mode=elements` and the `browser_document` source. Its peer runs the automation lane's element script and document helper in the requested tab, so a control that appears only under a trusted hover can be found, seen and pressed on one connection. A BiDi connection still refuses `activate_tab` (#41813).

### Fixed

- An element inventory cuts a control's text at 500 characters by code point. The cut used to fall inside an emoji's two UTF-16 units, and on a BiDi connection the half character made the whole inventory fail as `invalid BiDi script JSON` (#41813).
- A BiDi connection survives a page answer too large for one socket message. The page script measures its answer and the command is refused as `page_answer_exceeds_bidi_reply_limit` with the size; before, an inventory over 8 MiB left the host answering every later command with `message exceeds maximum size` while it stayed listed as connected (#41813).
- A BiDi element inventory is refused while the document is still being parsed, as the document source already was, instead of listing the controls parsed so far as the whole page (#41813).
