### Fixed

- A BiDi browser host that takes a workspace now appends the previous host's unacknowledged results to `bidi-host-unacknowledged.jsonl` before it replaces `bidi-host.json`. Starting a host again, by hand or by the server, used to erase that list, which records actions that may have taken effect without the server confirming them. A previous record the host reads and cannot load is first copied to `bidi-host.json.unloadable-<pid>-<time>`. The host does not start, and the previous record stays, when that record cannot be read at all, when the archive or the copy cannot be written, or when its own record cannot be written (#42150).
