### Fixed

- A single-user boot no longer creates `.masc/auth` or a lock file next to `authz.jsonl`: the account-mode judgment opens the authorization log and the external store only when their file is there, so a read-only `.masc/auth` or a missing parent of the external store no longer refuses the boot (multi-account A2 follow-up, #48206).
- An account-mode refusal now logs `[FATAL] the account mode refuses this boot: ...` with every reason before the boot stops (#48206).

### Upgrade notes

- A relative `XDG_CONFIG_HOME` is now ignored when masc looks for its config directory, and `~/.config/masc` is used instead, as the XDG Base Directory Specification asks; the default base path record and the install record are both read from that one directory (#48206).
