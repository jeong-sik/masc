### Changed

- Keep the last confirmed workspace on screen when a TUI `/health` read fails or the server is booting. Keepers, Gate rows, approvals, Item accounts and the open detail stay visible and are marked unconfirmed; decisions, writes and new reads wait for a read that names the workspace again. While the server boots, Keeper run state and Item accounts still clear as before. A read that names a different workspace, including a booting server's, still withdraws everything (#41622).
