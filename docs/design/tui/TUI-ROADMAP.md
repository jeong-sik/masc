# TUI 제품 개선 순서

TUI는 Keeper에게 맡긴 일을 따라가고, 원본 결과와 증거를 읽고, 필요한 결정을 내리는 작업대다.
[제품 계약](../../constitution.xml), [운영자 홈 결정](../../rfc/RFC-tui-measured-operator-home.md),
[전체 화면 목록](SCREENS.md)을 기준으로 한다.

## 먼저 읽혀야 할 것

| 질문 | 목적지 |
|---|---|
| 내 결정과 답을 기다리는 것은 무엇인가 | Dashboard, Work의 Requests·검증·Goal 확인 |
| 이 Keeper가 지금 무엇을 하고 어디서 막혔나 | Keepers의 목록·대화·호출·예약 |
| 무엇을 보냈고 무엇을 돌려받았나 | 원본 요청·도구 결과·Context·Changes |
| 완료 조건을 충족했나 | Work의 Task·제출 증거·판정 |
| 어떤 기억과 근거를 갖고 있나 | Memory·Context·Board |
| 누가 어떤 자원을 보고했나 | Usage의 범위·시각·미보고 상태 |
| 설정이 무엇이고 실제 무엇이 연결됐나 | System의 설정·Runtime·Features·Plugins |

## 개선 순서

1. **중복 탐색과 잡음 제거.** 주요 목적지를 먼저 보여 주고 상세는 검색과 원래 화면에서 연다.
   같은 동작의 팔레트 행, 반복 제목·키 안내·기본 상태 배지는 줄인다.
2. **읽을 대상과 상태 보존.** 선택한 Keeper·요청·Task·revision을 끝까지 유지한다.
   지연이나 읽기 실패를 빈 목록·성공으로 바꾸지 않고 입력 초안을 보존한다.
3. **원본까지 연결.** 대화에서 정확한 호출·변경·제출 증거·판정을 읽고 같은 자리로 돌아온다.
   일부만 수집한 결과와 현재 Git 상태를 구분한다.
4. **상세 가독성 개선.** 현재 값과 조치가 먼저 읽히게 하고 기술 식별자·원본 설정·설명은 상세로 둔다.
   좁은 화면에서도 선택한 대상·실패 이유·입력·종료 키가 남게 한다.
5. **흐름 실측.** 같은 소스와 바이너리로 실제 이동·입력 보존·원본 읽기를 확인한다.
   소스 병합이나 타입 검사만으로 설치된 TUI의 동작을 완료 처리하지 않는다.

새 화면을 늘리기 전에 기존 화면의 원천·대상·권한·사용 사례와 진행 중인 PR을 비교한다.
목록이 비어 있다는 이유만으로 필요한 기능을 지우거나 새 요약 화면을 만들지 않는다.

공통 조작의 제안과 운영자 결정은 [작업대 설계](../../rfc/RFC-tui-operator-workbench.md),
현재 Keeper 개선 범위는 [RFC-0511](../../rfc/RFC-0511-the-rest-of-the-keeper-pulse-sheet-lands-as-four-independent-stacks.md)을 따른다.
