## 확인한 범위 — (b) 요건을 못 채운 지점

계약 1의 (b)는 "run 목록에서 스위트명으로 대조해 마지막 녹색 run과 첫 red run 확인(녹색이 없으면 '녹색 없음' 기록)"을 요구한다. 이걸 다음 범위까지만 했다.

1. **시험 도입 커밋 head 의 run 전수** — `gh api "repos/jeong-sik/masc/actions/runs?head_sha=1e5740024c6cd84b6e75cfe40b21fd91b2fa0cdc&per_page=100"`
   ```

   41567478107 Main minimal build schedule failure 2026-11-03T02:39:35Z
   41565389744 Main minimal build schedule failure 2026-11-03T02:19:29Z
   ```
   두 run 의 로그를 열어 `grep -aE 'TARGET_SUITES|play_invite'` → **양쪽 다 0건**. 그 워크플로는 이 스위트를 실행하지 않는다.

2. **최근 test.yml 300건에서 head 로 필터** — `headSha` 가 `1e5740024c` 로 시작하는 run **0건**.

3. **`test_play_invite` 를 실제로 돌린 다른 run** — 이 스위트는 `TARGET_SUITES` 로 지정해야만 도는 타깃 실행이고, 전체 회귀에서도 돈다. 전체 회귀 run 은 schedule 3건(41493891921, 41686990273, 41879986062)을 확인했으나 **그 셋 다 이 스위트가 실패한 뒤의 head** 이며, 도입 커밋 이후 이 스위트가 녹색이었던 run 을 찾지 못했다. 다만 **workflow_dispatch run 이 2,500건**이라 로그를 전수 스캔하지 않았다.
