## What

Aligns two test suites with the intentional fail-open behaviour introduced in #29610 ("a store this binary cannot read is absent, not fatal").

### ① test_keeper_meta_invalid_recovery (issue-28844 cases 2·3)

- Case 2: WARN count 2 → 1 — the reader emits one WARN naming the loss; the keepalive scan no longer adds a second one.
- Case 3: Rewritten from `fails_loud` (expects `Error`) to `fails_open_as_absent` (expects `Ok None` + 1 WARN + file untouched). Test name and assertion updated.

### ② test_keeper_reaction_ledger (ledger 13)

- Rewritten from `surfaces_durable_event_queue_parse_error` (expects `unknown` status + read error fields) to `treats_unreadable_durable_queue_as_empty` (expects `empty` status, no operator action required, zero read errors, zero backlog).

### ③ test_keeper_tool_schema_bytes

Already fixed by codex-mcp-client in #29681 (trimmed 13 unused tools). This PR does NOT touch the ceiling.

## Why

#29610 deliberately changed both readers to fail open (return `Ok None` / start from empty queue + WARN) instead of surfacing fatal errors. The old test assertions encoded the pre-#29610 fail-loud contract. This PR updates them to match the new contract.
