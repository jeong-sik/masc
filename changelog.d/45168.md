### Added

- When a Keeper volume records ext4 errors, the server repairs it the next time the Keeper is idle: it removes the Keeper's guests, clones the image to `<image>.pre-repair`, runs `e2fsck` in a one-shot helper, and reads the superblock again to decide the outcome. An existing backup, an unknown helper image or a failed clone stops the repair before anything changes. Each repair writes a `masc.keeper.volume_repair.v1` receipt and a start and a result post in the `sandbox` hearth, and Keeper status shows the backup under `sandbox_live.volume_filesystem[].repair_backup` (#45168).
