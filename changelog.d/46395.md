### Changed

- Fresh state required: each browser source now has its own Lane Add-on package and worker: `browser-automation`, `browser-stagehand`, `browser-firefox`, `browser-ego` and `browser-external`. A failure of one source ends only its own worker. The `browser` package that served every source in one worker is removed, and `browser_backend` is required in a browser package's `lane.toml`. Before deploying, detach the old `browser` instance and confirm `released`, remove `browser.toml` and `.masc/packages/browser`, and move `[runtime.addon_exact_lanes.browser.locate]` to `browser-automation.locate` and `[runtime.addon_exact_lanes.browser.stagehand]` to `browser-stagehand.stagehand`. Old native cleanup descriptors are not read. (#46395)
- `masc browser-lane-setup` declares one browser Add-on per source the workspace runs: automation, the owned Firefox and ego when runtime.toml has their table or the run writes it, Stagehand when `[browser.stagehand]` is present, and external hosts when the run installs a native host or one is installed. A source whose table the run writes is declared once that table is written; a refused table leaves out only that source. Under `--mode addon` a runtime.toml that does not parse is refused; other modes report it and go on. The server starts a source from its table while its lane is not switched off, and the package row of one that does not start says which of the two it is. (#46395)
- The deployment preflight refuses a workspace where two enabled declarations serve the same browser source, since the host uses neither. (#46395)
