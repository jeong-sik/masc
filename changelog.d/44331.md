### Documentation

- The glossary's **Composition** and **Composition Skill** entries now address an async composition correctly: `keeper_composition_prepare` returns a durable draft reference whose `sha256` goes to `keeper_composition_run`, `keeper_composition_status` and `keeper_composition_cancel` take the durable `request_id`, `composition_run_id` is the logical run id passed back only as `resume_run_id` with the same draft, and an async composition skill's receipt carries `request_id` and `composition_run_id` plus a `result_wait` binding for `keeper_composition_result` — not a `run_id` handle, and the execution mode comes from the declaration, not from a call argument. The **Composition** entry's third link pointed at `lib/keeper/keeper_composition_run_registry.mli`, a path that exists nowhere in the tree, and now points at the durable async request store and the composition dependency module (#44331).
