fix(stdio): a machine tool without its worker answers the admission refusal (#42711)

#42001 moved MSX and DOS tools onto lane addon workers and dropped the
stdio activation path #41199 installed, so a workspace with no
lane-addons declaration lost the machine tools entirely: masc_msx_step
and masc_dos_step fell through to -32601 "not available on this MCP
endpoint" (whole-regression run 38343086724, MachineStdioAdmission 4/4).

An unexported machine tool now answers through the regular
handle_call_tool_eio path with the typed refusal the attached worker
would give -- activity off, or no machine loaded -- as
Workflow_rejection and Proven_pre_effect. Managed-agent and
operator-remote profiles and non-machine names keep the unknown-tool
refusal. No container starts and no emulator runs in this path.
