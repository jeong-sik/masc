- An open Keeper chat in the TUI reads its history again on that Keeper's `keeper_skill_activations_changed`, so the exact Skill evidence on its turns follows the ledger (RFC-0483 L5, originally #48210, fragment removed by #48230) (#48531).

### Internal

- The Gate replay store can record an operator's typed settlement for a replay no process could confirm: `Keeper_approval_queue.record_operator_settlement` stores "the effect applied" (bounded artifact reference), "the effect failed" (bounded detail reference) or an explicit final abandonment, fenced by keeper and resolution sequence. `admitted_revision`, `source_post_id` and `stage` are stored with it, and the fence check re-derives only keeper and sequence from the delivery. A settlement never overwrites the machine's outcome; it is written beside it in the replay sidecar's `settlements`, and the record reaches memory only after fsync. A resubmission of the same verdict is idempotent, a different verdict is an explicit conflict, and a different keeper or sequence is a typed refusal. This layer stores the verdict; it does not yet expose a tool or UI surface that calls it (originally #48131, fragment missing) (#48531).
