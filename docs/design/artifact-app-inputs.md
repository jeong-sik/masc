# HTML 아티팩트의 입력 저장

관련 목표: #45940. 서버의 개인 입력 저장 API와 읽기 화면의 HTML 입력창,
문서 안에서 쓰는 입력 저장 SDK를 연결합니다. 게시 원본은 바꾸지 않습니다.

## 저장 범위

작업 공간, 아티팩트 ID, 게시 버전, 인증된 사용자마다 JSON 객체 하나를
저장합니다. 서로 다른 사용자·문서·게시 버전은 같은 입력을 덮어쓰지
않습니다. 게시한 HTML과 공동 편집 원고는 이 저장으로 바뀌지 않습니다.
다음 게시 버전에 이전 입력을 자동으로 옮기지 않습니다.

사용자는 기존 HTTP 인증에서 정합니다. 요청 본문에 `actor`를 넣을 수
없습니다. 같은 인증 주체를 공유하는 창은 같은 개인 입력을 읽습니다.
이 API는 기존 아티팩트와 같이 `CanAdmin` 권한이 필요하며, 문서별 권한을
대신하지 않습니다. 인증 정보나 다른 사용자 입력을 HTML에 주지 않습니다.

## API

`GET /api/v1/artifact-app-data/<artifact-id>?revision=<게시 버전>`은
해당 사용자의 입력을 읽습니다. 아직 저장하지 않은 경우 `version: 0`,
`data: {}`, `receipts: []`를 반환합니다. 존재하는 HTML 게시 버전만 받습니다.
손상된 상태를 빈 입력으로 바꾸지 않습니다.

`POST /api/v1/artifact-app-data`는 다음 객체를 받습니다.

```json
{
  "target": {"artifact_id": "artifact-…", "revision": 1},
  "id": "<canonical UUID v7>",
  "expected_version": 0,
  "data": {"memo": "다음 회의에서 확인", "answers": [true, 3]}
}
```

`data`는 UTF-8 문자열, 유한한 숫자, 불리언, null, 배열, 객체를 포함할 수
있습니다. 정수는 JavaScript에서 정확하게 표현할 수 있어야 합니다.
중복 키·알 수 없는 필드·빠진 필드는 거절합니다. 객체 키 순서는 요청
동일성에 영향을 주지 않습니다.

성공 시 `schema: masc.artifact_app_data.v1`, `target`, `actor`, `version`,
`data`, `receipts`를 반환합니다. 저장할 때 버전이 하나 증가합니다.
`expected_version`이 달라졌으면 HTTP 409와 `current`를 반환합니다.
클라이언트는 기존 입력을 보관하고 충돌을 보여줘야 합니다. 새 버전으로
조건만 바꿔 덮어쓰거나 자동 재시도하지 않습니다.

이미 저장한 `id`와 같은 요청은 현재 입력을 반환합니다. 그 뒤에 다른
요청이 저장됐어도 이전 값으로 되돌리지 않습니다. 같은 `id`로 다른
입력이나 조건을 보내면 HTTP 409를 반환합니다. `receipts`는 요청 ID,
기준 버전, 정규화한 입력의 SHA-256, 저장 시각을 기록합니다.

기존 workspace 읽기 헤더 검사를 통과해야 하며, POST의
`expected_workspace`도 저장 전에 검사합니다. 저장 API가 만드는 응답에는
`Cache-Control: private, no-store`를 붙입니다. 이 API에 진입하기 전의
공통 인증·작업 공간 거절 응답은 기존 HTTP 진입점에서 만듭니다.

## 파일과 실패

`<effective MASC root>/artifact_app_data/`의 private 파일에 저장합니다.
파일명은 문서 ID·게시 버전·인증 주체의 SHA-256으로 정합니다. 파일을
읽은 뒤 저장된 문서·버전·사용자도 대조합니다. owned-path와 stable lock,
cursor 조건부 atomic rewrite를 사용합니다. 다른 창이 먼저 저장하면
그 상태에서 버전 조건과 요청 이력을 다시 확인합니다.
저장 전 owned 파일 검사 도중 다른 요청이 파일을 교체했거나 잠금을
얻지 못하면 HTTP 503 `artifact_app_data_unavailable`로 거절할 수도
있습니다. 이때 클라이언트는 입력을 보관하고 다시 읽어 확인합니다.
데이터와 잠금 파일의 관측 권한은 0600이어야 합니다. 권한이 달라진
기존 파일을 읽거나 저장하지 않으며, 권한을 바꿔 신뢰 가능한 파일로
취급하지도 않습니다.

rename 이후 fsync나 잠금 해제가 실패하면 HTTP 503
`artifact_app_data_commit_uncertain`과 `attempted`를 반환합니다. 서버는
다시 쓰지 않습니다. GET으로 실제 저장 상태를 읽은 뒤 같은 요청의
receipt를 확인합니다. 손상된 파일, 안전하지 않은 소유권·권한, symlink는
거절하며 기존 바이트를 보존합니다.

검사: `scripts/dune-local.sh build test/test_artifact_app_data.exe` 후 해당
실행 파일을 실행합니다. 전체 빌드·브라우저·운영 배포 검사를 대신하지
않습니다.

## 읽기 화면과 HTML 앱

읽기 화면은 작업 공간과 인증 상태를 확인한 뒤 해당 사용자의 저장
입력을 읽습니다. iframe은 저장 입력을 복원한 뒤 표시합니다. 초기
읽기가 실패하면 원본을 유지하고 다시 읽는 동작을 제공합니다.

정적인 input·textarea·select에는 HTML 파서가 읽은 원래 시작 위치를
표시용 사본의 식별자로 붙입니다. 게시 버전이 바뀌면 저장 범위도
바뀝니다. 입력 이름이나 문장을 검색해 비슷한 다른 칸으로 옮기지
않습니다. password·file·버튼은 자동 저장에서 제외합니다. 같은 식별자의
노드가 앱에서 복제되면 그 식별자는 자동 저장하지 않습니다. select의
옵션 구성이 달라졌거나 입력 종류가 바뀌면 이전 값을 억지로 적용하지
않습니다. template 안이나 동적으로 만든 입력은 SDK로 보관합니다.

input 이벤트는 아직 보내지 않은 값을 브라우저에 보관합니다. change·
reset·submit 이벤트에서 저장하며, 화면의 `입력 저장`으로도 보낼 수
있습니다. 이미 저장 중이면 새 입력을 보관하고, 새 change가 있었다면
앞선 저장을 확인한 뒤 그 입력을 보냅니다. 원고·버전·화면을 떠날 때
저장 전 입력이 있으면 확인합니다.

HTML의 JavaScript에서는 다음 인터페이스를 사용합니다.

```js
const input = await window.MASC.inputs.read()
await window.MASC.inputs.write({ ...input, memo: '다음 회의에서 확인' })
document.addEventListener('masc:inputs-ready', event => {
  // 처음 읽었거나 사용자가 서버/복구 입력을 선택했을 때의 앱 입력.
  render(event.detail)
})
```

read는 JSON 객체의 복사본을 반환합니다. write는 JSON 객체를 받아
저장 응답까지 기다립니다. 유효하지 않은 JSON이나 앞선 SDK 저장이
진행 중인 경우에는 거절합니다. 일반 입력은 data.forms에, SDK 입력은
data.app에 저장합니다. 그 밖의 원래 JSON 키는 보존합니다.

## 저장 실패와 복원

저장 요청의 ID·조건·보낸 데이터는 응답을 확인할 때까지 바꾸지
않습니다. 실패하면 새 입력도 따로 보관합니다. `저장 상태 확인`은
GET만 보냅니다. 요청이 실제로 반영됐고 현재 데이터까지 일치하면
확인을 마칩니다. 반영되지 않았고 버전도 그대로면 사용자가 같은
요청을 다시 보낼 수 있습니다. 서버 값이 바뀌었으면 두 값을 보존하고
서버 입력을 쓸지, 현재 입력으로 저장할지 명시적으로 선택합니다.

복구본은 작업 공간·문서·게시 버전·인증 주체별로 구분합니다. 키마다
불변 revision을 사용하며 ACK나 삭제는 캡처한 정확한 복구본만
지웁니다. 브라우저 저장 용량이 모자라면 이전 durable 복사본을 남기고
새 값은 메모리에 보관합니다. 메모리에만 남은 입력은 화면과 종료
확인으로 알립니다. 다시 열었을 때 복구본은 자동 적용·전송하지 않고,
복원·내려받기·삭제를 제공합니다. 계정이나 작업 공간이 바뀌면 이전
iframe과 비동기 응답은 새 호출자의 권한으로 요청하거나 복구본을
삭제하지 않습니다.

iframe은 allow-scripts만 가진 opaque origin입니다. 부모는 실제
contentWindow와 렌더마다 새 capability를 대조합니다. 전달하는 것은
해당 문서 입력과 저장 결과뿐이며 bearer·사용자 이름·다른 문서 경로를
전달하지 않습니다. frame-src/form-action은 계속 none입니다. 외부 연결을
설정하지 않으면 connect-src도 none입니다. 빠른 미리보기는 외부 연결과
스크립트, 입력 저장 bridge를 실행하지 않습니다.

같은 iframe이 다시 로드되면 bootstrap마다 새 instance ID를 만듭니다.
부모는 ready에서 새 instance를 연결하고 그 문서의 입력 번호를 처음부터
받습니다. 기존 서버 요청은 바꾸지 않으며 저장 결과에는 요청 당시의
instance를 유지합니다. 이전 문서의 늦은 입력·ACK는 새 문서의 입력이나
SDK Promise에 적용하지 않습니다. 이 instance는 화면 수명만 구분하며
저장 요청의 문서·사용자·버전 권한을 대신하지 않습니다.


## 외부 데이터와 CDN 연결

읽기 화면의 `외부 데이터와 CDN 연결`에서 허용할 HTTP(S) 출처를 한 줄에
하나씩 입력합니다. 경로·쿼리·사용자 정보·와일드카드는 받지 않습니다.
도메인 대소문자와 기본 포트는 URL 파서로 정규화하고 중복은 합칩니다.
예를 들어 `https://API.example.com:443`은 `https://api.example.com`으로
저장됩니다. 허용 범위는 해당 출처 전체입니다. 다른 CDN이나 API로
리다이렉트하면 최종 출처도 허용해야 합니다. 원래 문서에 더 엄격한 CSP가
있거나 브라우저의 혼합 콘텐츠·CORS 정책에 걸리면 연결이 제한됩니다.

설정은 개인 입력의 최상위 `resource_origins` 배열에 보관합니다.
HTML의 입력 bridge와 `MASC.inputs`는 forms와 app만 바꾸므로 외부 출처를
추가할 수 없습니다. 같은 사용자·문서·게시 버전의 기존 JSON 조건부 저장을
사용하며 별도 저장소나 인증 전달용 프록시는 만들지 않습니다.

`연결 설정 저장`은 현재 입력과 설정을 함께 저장합니다. 확인된 서버 상태의
출처만 script-src, style-src, img-src, font-src, media-src, connect-src에
반영합니다. 저장 중이거나 응답을 잃었을 때 로컬 변경만으로 연결 권한을
넓히지 않습니다. 확인된 설정이 바뀌면 기존 iframe에 편집 중지를 요청합니다.
자식은 입력 화면을 inert로 바꾸고 새 SDK 저장을 거절한 뒤 마지막 입력을
캡처해 돌려줍니다. 부모는 앞서 보낸 입력과 마지막 캡처를 보관한 뒤
새 capability와 CSP로 iframe을 다시 엽니다. 부모의 입력 세션과
진행 중인 요청은 유지합니다. 문서의 스크립트가 응답하지 않으면
저장된 설정과 현재 적용 중인 설정의 차이를 화면에 알립니다. 사용자는
`마지막 입력을 받지 않고 다시 열기`에서 미수신 입력 유실 가능성을
확인한 뒤 부모가 이미 보관한 입력으로 강제로 다시 열 수 있습니다.
시간이 지났다는 이유로 입력을 버리거나 자동으로 교체하지 않습니다.
그 사이에 들어온 새 입력도 새 iframe에 복원합니다. 출처 목록을 비우고 저장하면
기본 차단 상태로 돌아갑니다. 문서나 입력 사본의 복원은 연결 설정 저장과
같은 조건부 저장·명시적 충돌 선택을 따릅니다.

API 호출에는 브라우저의 CORS 규칙이 그대로 적용됩니다. sandbox의 origin은
opaque이므로 서버는 `Origin: null`을 받을 수 있습니다. 브라우저가 허용하지
않는 CORS를 MASC 서버가 대신 우회하지 않습니다. 로그인 토큰이나 부모의
HTTP 권한을 iframe에 넘기지 않습니다. 인증이 필요한 외부 API는 그 API가
제공하는 브라우저용 인증 방식을 별도로 사용해야 합니다.
