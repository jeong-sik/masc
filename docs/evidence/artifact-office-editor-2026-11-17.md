# 표·차트 화면 편집 통합 검증

확인: 2026-11-17. Task `task-3698`.
너비 보존 층 위에 화면 편집과 선택 범위 일괄 계산을 합쳤다.
기준 main은 `277c8f55816d`다.

## 화면에서 확인한 동작

HTML 원고는 글·셀 편집으로 열린다.
셀을 눌러 글을 고르고 `원고에 반영`을 눌러 적용했다.
세로 병합 셀의 강조 글자와 빈 셀을 고쳤다.
`<계약 & 검토>`는 HTML 태그로 바뀌지 않고 글자로 남았다.

차트 4종의 제목·항목·계열 이름과 값을 고쳤다.
세로 막대는 음수 `-42.5`, 나머지는 `42.5`로 고쳤다.
빈 값은 `7.25`로, 기존 0은 빈 값으로 바꿨다.
`abc`, `1e`, `-`는 각 차트에서 거부하고 원래 값을 유지했다.
계열 표시 형식 `0.00`도 두 출력에 남았다.

입력만 한 글은 게시하지 않았다.
원본 편집으로 전환한 뒤 미반영 입력을 내려받았다.
다운로드 내용은 입력과 같았다.
원본을 바꾼 뒤 이전 선택에 적용하면 거부했다.
취소를 확인하기 전에는 입력을 보관했다.
원고 소유자가 바뀌는 경우는 별도 컴포넌트 검사로 확인했다.

## 속도 측정

공동 편집 화면은 선택 범위마다 문서 전체를 읽고 있었다.
이제 동기 작업 한 번에서 문서를 읽고 모든 선택 범위를 만든다.
문서 원문이나 별도 편집 상태를 캐시에 저장하지 않는다.

Node 26.3.0에서 같은 합성 입력을 사용했다.
각각 준비 1회 후 5회 중앙값을 비교했다.
단일 선택 API와 일괄 API의 결과도 따로 대조했다.

| 입력 | 기존 선택 계산 | 일괄 선택 계산 |
|---|---:|---:|
| 400셀·4058바이트 | 25.71ms | 1.41ms |
| 1600셀·16058바이트 | 133.93ms | 3.40ms |
| 400셀·1052634바이트 | 460.72ms | 1.54ms |

큰 입력은 이미지 크기의 문자열을 붙인 합성 원고다.
이미지 디코딩·브라우저 전체 시간·HWP 파싱 측정이 아니다.
HWPX 내보내기 반복 검색의 측정은 하위 검증 기록에 있다.

고정 Core 0.9.0의 별도 HWPX 재저장 결함은
[이슈 #52637](https://github.com/jeong-sik/masc/issues/52637)에 남겼다.
현재 직접 HWPX 가져오기·내보내기는 해당 경로를 거치지 않는다.
