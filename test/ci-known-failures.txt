# Test suites that `dune build @runtest` from the repository root runs and
# that do not pass. The alias covers test/, packages/agent_core/test,
# lib/exec/test and tools/; until 2026-09 the lane built @test/runtest, so
# the suites outside test/ have no measured baseline yet.
#
# A row is <dir>/<suite>: the directory whose dune file declares the suite,
# then the stanza name. A stanza in test/stanzas/*.inc is included by
# test/dune, so it is keyed under test/, where its executable is built. The
# directory is not decoration: test/dune and packages/agent_core/test/dune
# both declare test_session, test_trajectory, test_schema_surface_index and
# test_tool_input_validation, and test/dune shares test_workspace with
# test/multimodal/dune and test_keeper_event_queue with
# test/keeper_event_queue/dune.
#
# scripts/ci-run-test-suite.sh compares the suites that actually fail against
# this list and fails CI when the two differ in either direction: a suite that
# fails without being listed is a new break, and a suite listed here that
# passes is a fix that should take its line out. Neither is allowed to sit.
#
# This file exists because the alternative was worse. CI used to name the 894
# suites it wanted to run, one at a time, across 26 workflow steps and a
# 1,000-line shell script. A suite left out of that list was not run and not
# reported, so a hard cut could make a field required, rot the fixture, and
# leave no trace -- six suites reached 2026-08 that way and were repaired in
# #29880, #29883 and #29887 only because someone went looking. Naming what is
# broken is a shorter list than naming what works, and it says why.
#
# Only suites that produce a stable verdict belong here. A suite that hangs or
# answers differently on two runs has no verdict to record, and listing it
# turns this ratchet red on whichever runs disagree with the list; those come
# off the alias with an enabled_if in their own stanza instead, next to the
# reason. test_fusion_wake is the current one (#29064).
#
# Measured 2026-08-24 against 42e320b44b, one `dune build @test/runtest-<name>`
# per suite. The first pass gave test_tools_coverage a 180-second deadline it
# spent compiling; it runs in 7 seconds once built and fails one assertion of
# forty. A deadline that covers the build measures the build.
#
# Re-measured 2026-09-07: every row dispatched alone on main through
# test.yml's suite input, one run each, run ids on the rows. Four fail alone
# and four pass.
#
# A row that passes alone is not proven stale. The list is keyed to
# `dune build @runtest` from the root, and a suite can pass by itself and
# fail in the sweep -- shared fixtures, or a timing window that only closes
# under load. So the four are candidates, not removals.
#
# What settles it is the nightly. It went unsettled from 09-04 to 09-06 -- cut
# at the 90-minute suite deadline twice for different reasons (#32154, then
# #33807) -- and a cut produces no failure set, so this ratchet compared
# nothing and four rows that should have come off sat here.
#
# #33809 fixed the hang. The 09-07 run (34148793721, commit 45016f15) finished
# in 917s of its 5400s deadline and produced a set, and it named those four as
# passing. They are gone below. The same run also named 102 failing suites this
# file does not list: 89 under test/, 13 under packages/agent_core/test/,
# 220 failing cases in all. That number is #33782's to answer; this change is
# only the four the runner asked for by name.
