### Documentation

- `docs/spec/00-glossary.md`: the **Region** entry no longer says the `captured loop packet exceeds original source` bound fails for `extent` values `0` or below — `extent` is decoded as `UInt128`, so `0` is the only failing value — and now records that `extent`·`offset`·`sourceDivisor` that do not parse as integers are refused earlier with `invalid captured region integer`, which is not one of the six `UmpLoopPlan` rejection strings (#44897).
