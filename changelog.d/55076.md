### Fixed

- A Keeper's chat store no longer fences with `SQLITE_IOERR_LOCK` (3850) on `BEGIN IMMEDIATE` when an in-process inspection reads it at the same moment. With the macOS system SQLite (3.54.0), a `READONLY` connection holding the shared lock made another connection's write lock in the same process fail with `EBADF`. The chat store inspections, the MSX checkpoint receipt reads and the native task and child content journal reads now open the file read-write with `PRAGMA query_only=1` (#55076).
