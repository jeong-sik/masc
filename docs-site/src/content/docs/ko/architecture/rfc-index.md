MASC 아키텍처는 코드베이스 내 `docs/rfc/`에 보관된 약 270건의 내부 RFC와 실측 기록을 통해 점진적으로 확정됐습니다. 주요 결정 영역은 다음과 같습니다.

---

## 1. 실행 격리 및 승인 경계

* **샌드박스 프로파일**: 셸 명령을 `docker`, `microvm`, `remote_ssh` 중 하나로 격리합니다. 프로파일 없는 키퍼는 실행이 거부됩니다.
* **오퍼레이터 승인 (Gate)**: 파괴적 명령은 턴을 멈추고 승인 대기열에 올립니다. 승인 절차이지 샌드박스는 아닙니다.

---

## 2. 작업 선점과 조율

* **낙관적 선점 (CAS)**: 작업 전이는 `expected_version` 가드로 보호됩니다. 버전이 어긋난 전이는 거절되고, 한 에이전트가 선점한 작업은 다른 에이전트가 가져올 수 없습니다. 이 보호는 작업 소유권까지이며, 소스 파일의 동시 수정을 막지는 않습니다.
* **게시판 (Board)**: 사람과 에이전트가 상태·지침·증거를 주고받는 비동기 채널입니다.

---

## 3. 다중 모델 심의 (Fusion)

* **비동기 외주 심의**: 같은 프롬프트를 N개 모델에 fan-out하고 심판 모델이 구조화 종합합니다. 실측 트레이드오프(정답률 +3.7pp, 비용 약 4배·지연 약 7배 — RFC-0252가 인용) 때문에 기본 루프에서 배제하고 비동기 자문 도구(`masc_fusion`)로 분리했습니다. 자세한 내용은 [Fusion 문서](/ko/architecture/fusion/)를 보세요.

---

## 4. 장기 기억 (Memory OS)

* **두 저장소**: 키퍼마다 일반 사실 저장소와 원천 결속 저장소(무효화 기록 포함)를 둡니다.
* **사용 기반 강화 (RFC-0418)**: 정체된 재관측 카운터를 걷어내고, 회수(retrieval)·인용(citation)·개정(revision) 사건을 전용 사이드카에 기록합니다.
* **librarian 선별**: 기억 정리는 수치 점수나 감쇠 곡선 없이 librarian 레인의 선별(유지 또는 사유를 붙인 제거)로 합니다. 자세한 내용은 [Memory OS 문서](/ko/architecture/memory-os/)를 보세요.

---

## 5. 성능 관측

* **스케줄러 지연 프로브**: 100ms 주기의 프로브 파이버가 깨어남 지연을 1분짜리 링에 기록하고, p50과 1초 이상 stall을 `/health` 진단에 노출합니다(`lib/core/scheduler_lag.ml`).
* **차등 터미널 렌더링**: 행 접두사 사전 계산과 버퍼 재활용으로 바뀐 부분만 다시 그립니다.
* **조건부 재검증 (304)**: 대시보드 응답에 약한 ETag를 실어 보내고, `If-None-Match`가 일치하면 본문 없이 304만 돌려줘 고빈도 폴링의 전송량을 줄입니다.
