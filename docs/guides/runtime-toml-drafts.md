# Dashboard runtime.toml 초안

Monitor → Runtime → runtime.toml 또는 Settings의 Runtime 편집기에서 작성한
원문과 구조화된 설정 변경은 작업공간의 편집 세션에 보관한다. 다른 화면으로 이동하거나
편집기를 닫고 다시 열면 원문, 선택한 섹션, 파일 revision, 충돌 비교 원문과 아직 유효하지
않은 모델 컨텍스트 입력도 복구한다. 구조화된 폼의 **추가**를 누르기 전 새 provider/model
입력과 새 binding 선택은 아직 폼 내부에만 있으며 이 보존 범위에 포함하지 않는다.

세션은 브라우저 탭의 메모리에 있다. 페이지 새로고침이나 브라우저 종료 후 복구는
제공하지 않는다. 편집 화면 밖에서도 미저장 초안·진행 중 저장·결과가 불확실한 저장이
남아 있으면 브라우저에 페이지 이탈 확인을 요청한다.

저장 요청은 원래 세션에서 끝난다. 요청 중 화면을 떠나도 저장 결과와 revision을
잃지 않으며, 원문 저장 도중 추가한 편집은 별도의 미저장 변경으로 남는다.
routing·Lane 후보·Keeper 배정 변경을 적용하는 동안은 원문 편집을 잠근다. 이전 설정을
담은 원문이 방금 적용한 변경을 다음 저장에서 되돌리지 않도록 한다.
파일 저장 결과를 먼저 표시하고 설정 재개·화면 갱신 결과를 이어서 확인한다.
파일 저장, 실행 설정 적용, 실제 모델 검증은 서로 다른 결과다.

작업공간이 바뀌면 다른 작업공간의 초안을 표시하거나 전송하지 않는다. 복귀 시 현재
파일을 다시 읽어 경로와 revision이 같으면 보관한 초안으로 바로 편집을 이어간다.
파일이 바뀌었다면 **현재 revision 채택 · 초안 유지** 또는 **현재 원문으로 초안 교체**를
선택한다. 읽기만으로 저장 기준이나 초안을 덮어쓰지 않는다. 다음 저장도 CAS를 적용한다.
응답을 기다리던 중 작업공간 연결이 바뀌면 이전 비교 원문을 무효화하고 새 읽기를 요구한다.
이미 전송한 저장이 취소됐다고 단정하지 않는다. 아직 인증을 준비하는 요청은 실제 전송
직전에 같은 작업공간인지 확인한다.

현재 파일 경로가 달라진 경우 기존 초안과 경로를 유지하고 저장을 막는다. 초안을 복사해
보관하거나 **새로고침**에서 명시적으로 폐기한 뒤 새 파일을 읽는다. **되돌리기**는 마지막
편집 기준 원문으로 돌아가며 저장 요청을 보내지 않는다.

Lane 후보 표는 파일 재조회·저장 결과·설정 재개 완료에 따라 다시 읽는다. 이전 요청의
늦은 결과가 새 표를 덮지 않는다. 이 보장은 편집 세션과 편집기 안의 표를 대상으로 하며,
Dashboard 전체의 공유 runtime 캐시 격리나 운영 서버 검증을 의미하지 않는다.

공유 catalog와 resolved 목록의 별도 동작은
[작업공간별 Runtime 조회](runtime-workspace-readings.md)를 따른다.
