### Fixed

- Kimi Coding `k3.1-pro` and `k3.1-pro-highspeed` no longer accept reasoning effort `none`. The plan rejects a thinking-disabled request with HTTP 400, so an explicit disable is now refused before the request is sent. `kimi-for-coding-highspeed` no longer accepts `low`, `high` or `max`, since the plan does not let it adjust thinking effort; its disable still travels as `none` (#55536).
