### Fixed

- A repository whose clone or fetch failed drew only the word `error` in a nine-cell column, though the route writes the git failure message to the wire beside the word: the cause was on no screen at all. The status is now read as the closed type the store already keeps, with the cause travelling inside `Error`, and the selected row's context draws it under the Path and Keepers it already carries. The four status words live in one table beside that type, so a status added there cannot reach the wire unnamed; a word this build does not know, and an `error` that names no cause, are kept as they arrived rather than folded into one of the four (#38002).
