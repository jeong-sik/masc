### Documentation

- The glossary's **Composition** entry now addresses an async composition correctly: `keeper_composition_prepare` returns a durable draft reference whose `sha256` goes to `keeper_composition_run`, `keeper_composition_status` and `keeper_composition_cancel` take the durable `request_id`, and `composition_run_id` is the logical run id passed back only as `resume_run_id` with the same draft. The entry's third link pointed at `lib/keeper/keeper_composition_run_registry.mli`, a path that exists nowhere in the tree, and now points at the durable async request store and the composition dependency module (#44331).
