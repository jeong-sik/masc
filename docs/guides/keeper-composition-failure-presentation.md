# Structured composition failure diagnostics

The controlled provider trial found that selected failures repeated their data
inside `structured_content` and a rendered `content` diagnostic. The producer can
now select `Tool_output.Inline_with_structured_diagnostic` when its structured
data contains the complete domain diagnostic. This presentation preserves the
structured result and durable manifest reference. Failed inline results add the
canonical failure class, failed disposition and available next move once.

Selected named/async composition results and public composition runs declare this
presentation. The original message and full execution remain in durable artifacts;
cause, effect disposition, blocked nodes and independently available exports stay
model-visible. Descriptor ceilings and marker fallback still apply. Ordinary
producers with an opaque human message retain `Inline_with_reference`, which
carries that message. No text comparison decides which presentation a producer
owns, and neither presentation changes execution disposition or replays effects.

The strict metadata codec retains the declared presentation across persistence.
Status observations keep their own successful status-read contract. Their nested
failed result remains explicit in canonical data. The public run wrapper chooses
its structured diagnostic again after binding the original draft and run refs.

The focused executor corpus captures the previous selected presentation alongside
the new one from the same execution. Compare them with the provider-trial runner's
`--baseline-projection previous_selected`. Parser checks or a shorter local string
alone do not establish provider latency or reliable task completion; record actual
requests, usage and every failed/unfinished sample.
