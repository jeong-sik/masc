# keeper-librarian admission 통과선과 기준선, 2026-11-09

keeper-librarian Lane Add-on의 `admission` 출력을 Tinker에서 학습한 Inkling 2 Small LoRA가 맡을 수 있는지 판정하려 한다.
학습한 쪽이 평가를 고르지 못하도록, 학습 전에 평가 세트, 검사기, 통과선을 고정했다.
이 묶음은 그 고정과 기본 모델의 기준선을 남긴다.

## 고정한 것

`scripts/tinker/librarian/pass_lines.json` (sha256 `8f715ae56649da0ce57cad9ea3771ed34924ef41413c8d5274ef807cf77b8f02`)

- 요청 모양: MASC exact 레인처럼 admission 프롬프트 다음에 스키마 지시문을 보낸다.
  `reasoning_effort: "low"`, `max_tokens: 32768`이다.
  32,768은 배포할 때 체크포인트 슬롯에 선언할 출력 상한과 같은 값이다.
- E-real: 라이브가 답한 admission 기록 99건. 저장소에는 digest와 파일 sha256만 있다(`e_real_manifest.json`).
- E-synth: 생성기 평가 split(seed 20261109)으로 만든 150건 중 라벨 감사를 통과한 142건이다.
  요청 파일 sha256은 `e2bb1915d8c05f813ad32c619703044a867027ea0fbd04d54670ffa09e83a767`이다.
- 하네스 파일 16개와 `config/prompts/librarian.md`의 sha256. 한 바이트라도 바뀌면 `eval_admission.py`가 돌지 않는다.
- `train_sft.py`는 `pass_lines.json`의 sha256이 위 값일 때만 학습을 시작한다.

## 통과선과 기본 모델 값

기본 모델은 `thinkingmachines/Inkling-2-Small:peft:262144`다.
아래 기본 모델 값은 참고값이다.
G4와 G5는 판정 실행에서 후보와 같은 run으로 다시 잰 기본 모델과 비교한다.

| 통과선 | 기준 | 기본 모델 |
| --- | --- | --- |
| G1 E-real 유효율 | 0.95 이상 | 92/99 = 0.929 |
| G2 E-real에서 라이브가 지우지 않은 기억을 `dropped`로 지운 수 | 합쳐 2건 이하 | 0 |
| G3 E-synth 판정 정확도 | 0.95 이상 | 181/209 = 0.866 |
| G3 E-synth 삭제 정밀도 | 1.0 | 62/65 = 0.954 |
| G3 E-synth 심은 낡은 fact 삭제 재현율 | 0.9 이상 | 40/112 = 0.357 |
| G4 E-real 라이브 답 일치율의 기본 모델 대비 차이 | 0 이상 | (자기 자신과 비교하므로 0) |
| G5 E-real 응답 시간 중앙값의 기본 모델 대비 비율 | 1.0 이하 | (자기 자신과 비교하므로 1.0) |

- G2의 라이브 쪽 삭제는 `dropped`와 `absorbs`로 지운 기억을 합친 것이다.
  라이브가 지우지 않은 기억을 모델이 `absorbs`로 묶은 수는 따로 센다. 기본 모델은 5건이었고 통과선에는 넣지 않았다.
- G4는 후보와 기본 모델이 둘 다 유효하게 답한 항목에서만 센다.
  기본 모델의 E-real 일치율은 유효한 92건에서 116/144 = 0.806이다.
  라이브 답도 다른 모델이 낸 답이라 정답이 아니다. G4는 기본 모델보다 라이브 답에서 멀어지지 않았는지만 본다.
- G5는 같은 항목의 기본 모델 호출과 후보 호출이 1,800초 안에 나갔을 때만 판정한다.
  측정 호출 앞에 출력 1토큰 호출로 대상마다 prefix 캐시를 데운다.
  E-real 호출의 0.9 이상이 프롬프트의 0.9 이상을 캐시에서 읽어야 판정한다.
- 두 갈래가 다 통과하면 A(답만 학습)를 고른다.
  B(교사의 생각까지 학습)가 E-synth 정확도와 G4 차이에서 둘 다 0.03 이상 앞서면 B를 고른다.

기본 모델이 무효로 답한 사유:

- E-real 7건: 필수 키 빠짐, 입력에 없는 근거, 근거 없는 새 claim, 기억에 없는 `memory_claim`, JSON 중복 키, 새 claim의 `board` 형식이 각 1건이다.
  나머지 1건은 출력이 32,768토큰에서 잘렸다. 후보가 가장 많은 요청이다.
- E-synth 150건 중 9건: 근거 없는 변경 5건, 근거 없는 새 claim 3건, 기억에 없는 `memory_claim` 1건이다.

## E-synth 라벨 감사

생성 모델이 요청한 종류와 다른 후보를 쓸 수 있어서, 라벨을 사람 대신 독립 판정자에게 확인받았다.

- 판정자는 Claude 하위 에이전트 4개다. case를 나눠 맡았고, 한 case는 한 판정자만 봤다.
  판정자는 라벨도 모델 답도 보지 못했다.
- case는 97건이다.
  기본 모델이 유효하게 답했는데 라벨과 달랐던 67건은 모두 넣었다.
  나머지(라벨과 맞은 74건, 무효 9건)에서 seed 20261109로 30건을 뽑았다.
- 판정이 라벨과 다른 요청 8건을 뺐다.
  라벨은 새 사실인데 판정자가 기존 fact를 바꿔 말한 것으로 본 것이 5건이다.
  고침과 새 사실, 고침과 바꿔 말하기가 엇갈린 것이 3건이다.
- 심지 않은 fact를 지워야 한다거나 심은 낡은 fact를 남겨야 한다는 판정은 없었다. 그래서 기억 단위로 뺀 것은 없다.
- 불일치 67건 중 60건은 판정자가 라벨과 같았다. 기본 모델이 틀린 경우다.
- 뽑은 30건 중 1건이 라벨과 달랐다(0.033).
  판정하지 않고 남은 53건에도 비슷한 비율로 라벨 오류가 남아 있을 수 있다.

case별 결과는 `e-synth-audit.json`에 ID로만 있다.

## 확인하지 못한 것

- 기준선 실행은 캐시를 데우는 호출을 넣기 전에 했다.
  E-real은 99건 모두 캐시가 데워져 있었지만, E-synth는 0.61만 그랬다. 그래서 이 응답 시간은 G5 판정에 쓰지 않는다.
- 판정자 사이의 일치도는 재지 않았다. 한 case를 두 판정자가 보지 않았다.
- E-synth 요청 파일(약 13MB)은 저장소에 넣지 않았다. 운영자 컴퓨터의 `artifacts/`에 있고 sha256으로 고정했다.
  생성 호출 캐시(`calls.jsonl`)가 있으면 같은 파일을 다시 만들 수 있다. 캐시가 없으면 모델이 다른 글을 쓴다.
- E-real 원문과 답은 운영 저장소에만 있다. 같은 기록이 없는 곳에서는 E-real을 다시 잴 수 없다.
