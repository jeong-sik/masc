# Goal·Task·Board·Memory에서 먼저 읽을 정보

기준 소스는 main `3d1271ef26b82b604b8f88dd6c126947ee4578bd`와 기존 UI stack #50678이다. Task/Feature 기준 `a00f8aab53421929709620b84e0d946e93f841c8`에서 조사했고, 후속 Goal #50688 `df95aa344227e9fb0969a5e37c7619e127491979`의 요청·성공 조건 미리보기와 연결 작업 관측 범위 표시를 재사용한다. 아래는 소스 조사와 설계 판단이며 사용자 행동 실험·후보 실행 결과가 아니다.

## 참고한 원칙

- [Nielsen의 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/): 현재 상태를 보이게 하고, 익숙한 말과 같은 개념의 같은 표현을 사용하며, 중요한 정보의 가시성을 낮추는 불필요한 내용을 줄인다.
- [단계적 공개](https://www.nngroup.com/articles/progressive-disclosure/): 자주 쓰는 정보와 행동을 먼저 두고 드물게 필요한 상세를 쉽게 찾을 수 있는 다음 단계에 둔다. 단순화가 작업에 필요한 정보를 숨기면 이 원칙을 만족하지 못한다.

이 원칙을 MASC에 적용한 아래 정보 선택과 순서는 이번 설계 판단이다. 기존 승인·완료·조회 권한을 바꾸는 근거로 사용하지 않는다.

## 각 화면의 질문

| 화면 | 목록이 답할 질문 | 상세의 중심 |
| --- | --- | --- |
| 목표 | 무엇을 이루려 하며 어디에 멈춰 있나? | 목표·성공 조건, 현재 단계와 이유, 검증 근거, 가능한 다음 행동 |
| 작업 | 무슨 일을 누구에게 맡겼나? | 원래 요청, 담당·현재 상태, 검증 제출·판정, 연결 목표와 이력 |
| 게시판 | 무슨 글이고 누가 썼으며 대화가 끝났나? | 본문·종료 결론, 댓글, 작성자·출처, 첨부와 연결 대상 |
| 기억 | 누구의 어떤 기억을 읽고 있으며 관측에 문제가 있나? | 주장, 출처·무효화, 저장/관측 시점, 처리 대기와 읽기 상태 |

ID·절대 경로·세션/operation 식별자·내부 처리 수치는 원문과 진단에 남긴다. 목록의 제목과 상세 본문보다 먼저 자리를 차지하게 하지 않는다. 실패·부분 조회·이전 관측은 정상적인 빈 결과와 다르게 남긴다.

## 한영 혼용의 실제 경로

언어 설정은 이미 존재한다. `[tui].language`가 `state.ui_language`를 거쳐 `ui_text`를 고른다. 일부 상세 helper에는 언어 인자가 없고 영어 literal이 남아 있다. 다른 경로는 typed 상태를 화면 낱말 대신 wire 문자열로 출력한다. 키 바닥글도 기본 영어 투영을 사용하거나 한국어 label이 빠져 있다. 한국어 절 제목 뒤 영어 필드, 영어 화면 속 고정 한국어 안내가 함께 나온다.

번역 대상은 앱의 제목·상태·필드·도움말이다. 사용자가 쓴 제목/요청/댓글, 모델이 남긴 이유, ID·링크·파일 경로·API 값은 원문이다. 이 원문까지 바꾸거나 문자열을 해석해 상태를 추정하지 않는다.

## 소스에서 확인한 표시 결함

- 필터 밖 목표 링크의 상세 sidebar가 일치 항목 대신 첫 목표를 강조한다.
- 조사 시점의 목표 상세는 연결 작업 수의 부분/보존/미조회 범위를 생략했다. 이 문제는 후속 #50688에서 고쳤으므로 그 구현을 재사용한다.
- 좁은 기억 category strip이 저장소 읽기 실패를 0으로 바꾼다.
- 기억 전체 사실 창은 유지된 본문을 보여 주면서 갱신 실패 표시를 넘겨받지 않는다.

기존 수정 한 가지를 재사용하고 나머지 세 가지를 단순한 장식보다 먼저 고친다. 필터·목록 순서·권한·서버 lifecycle은 유지하고, 이미 관측한 선택/조회 상태를 화면이 정직하게 표현하도록 한다.
