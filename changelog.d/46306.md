### Fixed

- A DOS worker that starts, after a server restart or an image upgrade, restores the `autosave` slot before its first call instead of leaving guests a `no_machine` refusal that only a controller holder could answer. The controller starts free and goes to whoever moves next. With no `autosave`, or one that does not restore, the worker starts unloaded, the reason goes on the lane activity feed, and `autosave-prev` is never used as a fallback (#46306).
- `masc_dos_restore slot=autosave` no longer asks for `discard_previous_autosave`. The restored machine carries on the autosave's history: it replaces only `autosave` and leaves `autosave-prev` as uninterrupted play does, so nothing is discarded. Restoring a named slot still asks when both autosave files exist (#46306).

### Upgrade notes

- The `dos-machine` package is published as `0.2.2` with the image `masc-lane-dos-machine:0.2.2`, because the resume runs in the worker binary and a `0.2.1` image keeps starting unloaded. Run the `lane-addon-images.yml` workflow at the merged commit and load the image before restarting the server (#46306).
