# Production evaluator bounded probe

```sh
python3 verify_production_evaluation.py --repo /path/to/masc --output /path/to/new-output
```

Keep `probe_cases.ml` beside the script. Requires Python 3, OCaml 5.5.1, ocamlfind, Yojson, Digestif's OCaml implementation, and ppx_deriving_yojson. It does not invoke Dune or rebuild MASC caches. Both paths are required arguments. The script copies the dataset and source inputs before execution, records their SHA-256 and Git blob identities, and propagates compile or execution failure as a nonzero exit.

The final execution at commit `9ed280ba2a16b5f82e58b3201eaddb9b77560a6a` compiled and passed **63 assertions**. All 17 extracted source/dataset inputs matched that commit's Git blobs. The actual evaluator ML/MLI and actual runtime preparation/wrapper fragments locally enable warnings `+4+32+69` with `warnerror +a`; external ports and fixture scaffolding have narrower warning settings, recorded in the receipt. The compiler emitted no OCaml source warnings. Findlib emitted one warning about duplicate Digestif CMI directories; it is retained in `receipt/execution.json`.

Actual source executed:

- Entire evaluator ML/MLI, including dataset parsing, selected source computation, prompt construction, report serialization and orchestration.
- Entire captured-input codec and unread identity/validation module, with explicit external domain codec ports below them.
- Actual atom annotation, pinned classification and atom-opening digest fragments.
- Actual runtime preparation capture assignment and `infer_working_state` wrapper.
- Actual report type codecs generated by the source's PPX declarations and `judge_request_for`.

Explicit ports and limits:

- Snapshot/range authority, turn boundary position and snapshot capture/save/load/restore are typed fixture ports. This probe does not validate actual snapshot persistence, range authority, durable restoration, or snapshot codec correctness. It checks the evaluator's passed values, ordering, saved progress and use of the returned restoration.
- SDK `Checkpoint.message_to_json` delegates to the actual capture codec. Actual unread validation and SHA computation execute against that port; equality or rejection here does not prove the deployed checkpoint byte encoding.
- Memory fact, Goal and Task domain codecs are opaque JSON ports. Complete validation of those external payload schemas is outside the probe.
- Prompt rendering, preflight, lane resolution and provider execution are ports surrounding the actual preparation capture assignment and inference wrapper. The frozen-preparation case proves that the wrapper retains the provided preparation value, not that a real provider used a particular wire body.
- Generation and judge callbacks are injected effects. Provider request-wire observations are a unit port; no real provider or native runtime executes.

Checks cover top-level and case parsing, duplicate/invalid input refusal, unread and pinned selection, historical message offsets, empty all-hole selection, inference input isolation, durability fences, independent answer/judge failures, cancellation and immutable captured preparation. Assertions use passed requests, typed outcomes and actual serialized progress artifacts, rather than implementing another evaluator or source-selection algorithm.

The compile/run receipt, fragment coordinates, source identities and a saved-progress summary are in `receipt/`. Replaying the script regenerates the exact source copies, `probe.ml` and full `observations.json`; their redundant generated contents are not checked in. The full observations SHA256 is bound by `receipt/observations-summary.json`. An independent replay from this public script produced the same full observations digest and 63 passing assertions; its receipt is `receipt/independent-replay.json`. This is bounded source-fragment bytecode validation with explicit ports. It is not a full module dependency build, native MASC or provider execution, the authored native regression suite, real snapshot execution, Dune, or CI.
