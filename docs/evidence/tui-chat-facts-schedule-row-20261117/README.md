# 채팅 예약 묶음: 고치기 전후

RFC `tui-one-screen-grammar` §5.5 를 Keeper 채팅의 예약 묶음(대화와 입력 줄 사이)에 적용한
층의 전후 화면이다.

## 무엇을 찍었나

같은 서버(`localhost:8935`)에 TUI 두 개를 차례로 붙여 같은 Keeper(`code-reviewer`)의 채팅을
열고 창 폭 155·100·60열에서, 접힌 상태와 F9 로 펼친 상태를 찍었다. 찍은 날은
2026-11-17 01:1x KST 다.

- `before.txt`: main(`ea0b8d1fd284`)을 빌드한 `masc_tui.exe`
- `after.txt`: 이 층을 빌드한 `masc_tui.exe`

두 파일 모두 예약 묶음의 줄만 담았다.

## 보이는 차이

| | 전 | 후 |
|---|---|---|
| 155열 | `다음 예…` 에서 끊긴다 | 두 줄에 모든 항목 |
| 100열 | 일정 이름 중간(`5…`)에서 끊긴다. 예정 시각과 F9 가 없다 | 두 줄에 모든 항목 |
| 60열 | `다음 회차 보류: 이 …` 에서 끊긴다 | 네 줄에 모든 항목 |
| 펼친 항목(60열) | 한 줄에서 끊긴다 | 항목 아래로 들여 써서 이어진다 |
| 다음 예정 시각 | 서버 원문 `2026-11-16T15:46:58Z` (UTC) | 예정 시각과 같은 표기 `11-17 00:46` (운영자 시간대) |

## 한계

- 색은 담지 않았다. 전에는 줄 전체가 상태 색이었고, 후에는 상태 항목(최근 회차, 보류, 예정
  시각)만 상태 색이고 일정 이름과 키는 기본 글자색이다. 이 차이는 이 파일로 확인할 수 없다.
- 전과 후는 1분쯤 간격으로 찍었다. 전 화면 155열의 `(11-17 00:47 관측)` 은 그 순간 runner
  관측이 오래돼 붙은 것이고 후 화면을 찍을 때는 붙지 않았다. 코드 차이가 아니다.
- 일정이 하나뿐인 Keeper 다. 펼친 묶음이 일정 여러 개와 `+N개` 줄을 그리는 경우, 창 높이에
  눌려 `외 N` 으로 줄어드는 경우는 찍지 않았다.
- 뒤쪽 공백은 지웠다.
