### Added

- Each pull request at `GET /api/v1/repositories/pulls` now names the Keepers whose checkout of that repository is on its head branch (`keepers`, exact branch match) and counts the Keepers whose checkouts could not be read and so may be on it (`keepers_unread`). When the Keeper list itself cannot be read, both are `null` and `keepers_error` says why. A Keeper whose checkout discovery stopped early counts as unread. A Keeper whose sandbox guest is not running (a microvm not booted since the restart) is counted apart as `keepers_not_booted`, since its volume may still hold the branch; a shared-mount Keeper with no playground directory counts as neither. A pull request from a fork (`cross_repository: true`) joins no Keeper. Each repository also carries `keeper_checkouts` with its `observed_at` and every Keeper's branches and unread reasons. The pull requests are published as soon as GitHub answers; the Keeper join, one catalog read and one fleet inspection per 60-second refresh, is published over them afterwards and skipped when no open pull request was read (RFC-0465 §0.2, #38153).
