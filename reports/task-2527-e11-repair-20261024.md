# Lane Add-on web-search host boundary repair

This note records the repair of PR #45680, whose original head is
`71fc11a6c622a1fa76fb491d924be9df3e2859cd`. It does not certify the earlier
unpublished verification note or reuse its suite counts.

## Changed behavior

- `Lane_addon_runtime.run_host_cycle` checks the resolved package's
  `web_search` declaration before looking up or calling the provider runner.
  A package whose other host services opened the port still receives
  `not_allowed` when it did not declare web search.
- The producer supplies the search result body to the common delivery path.
  `Lane_addon_host_delivery.arguments` owns the single request/result wrapper
  and the same original body is retained when it exceeds the package frame.
- The test reset clears the injected search runner.

## Behavior verification scope

`test/test_lane_addon_host_cycle.ml` uses a real package TOML declaration,
configuration reconciliation, instance fiber, host cycle, result retention,
bounded continuations and public search result decoder. It replaces the worker
transport and provider runner with explicit fixtures. It does not make an
external search or establish deployment of this change.

The three added scenarios check:

1. An undeclared search on a port opened for Exact returns `not_allowed`
   with zero calls to the registered provider runner.
2. A declared search forwards the original query/limit once; the actual worker
   delivery decodes through `Lane_addon_search_result.result_of_json`, preserving
   provider identity, earlier provider errors and complete result data.
3. A result larger than the 4096-byte package frame reconstructs its complete
   original JSON and digest through `read_result` continuations. Relisting the
   original request restores the same marker without another provider call.

Verification target: changed runtime search producer -> common delivery/retention
consumer -> `test_lane_addon_host_cycle`'s `web search` group.
