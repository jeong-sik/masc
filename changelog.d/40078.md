### Performance

- A prompt resolution reuses the last parse of its markdown file when the file's bytes are unchanged, and a listing or validation of the prompt catalog reads each file once for all of its keys. Every resolution used to strip the frontmatter and split the whole file again, and a slot key split its whole group file. On a copy of the live prompt directory (263 keys, 140 of them in the 32 KB `keeper.md`), `Prompt_registry.list_prompts`, behind `GET /api/v1/prompts`, took 31.0 ms and now takes 0.80 ms; validating the catalog went from 28.9 ms to 0.81 ms; one `keeper.md` slot resolves in 33 µs instead of 173 µs (medians of 21 runs). The file is still read on every resolution, so an edit shows on the next one. (#40078)
