### Added

- An operator can pass a turn log line the Librarian reader stops on. `POST /api/v1/keepers/<k>/memory/act` takes `{"action":"skip_line","offset":<offset>}`, with the offset the writer row's input fault shows. It is accepted only when reading, run again from the stored position, stops on the line at that offset with no unit holding an item before it: a line that does not decode or is out of order. The commit log then gains a `Skip` line whose hole is `{"kind":"line_unreadable","offset":<offset>,"sha":"<sha256 hex>"}`, the ask that is out is cancelled, the size facts and the last ask's result are emptied, and the next ask starts. Any other offset, nothing unread, a unit with items in front, and a replaced file or a lost position (which `restart_reading` passes) are refused with the code `not_the_faulted_line`; a turn log that does not read is `turn_log_unread`. The act passes the line for reading only: while the turn log's own writer still meets a line it cannot decode in the file's tail, it appends nothing until the file is repaired. The act does not repair the file, so `validate-stores` keeps refusing the line until `turns.jsonl` is deleted with the server stopped and reading is restarted with `restart_reading` (#54303).

### Upgrade notes

- Older builds do not decode a `line_unreadable` skip line. As the last line of a commit log, such a line stops an older build's store at boot as `Log_unreadable`. An older build's `validate-stores` refuses it unless a `started` line follows it, which that build's Adopt writes (#54303).
