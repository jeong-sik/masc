# 채팅 턴 진행 줄: 고치기 전후

RFC `tui-one-screen-grammar` §5.5 를 Keeper 채팅의 턴 진행 줄(입력 줄 바로 위)에 적용한 층의
전후 화면이다.

## 무엇을 찍었나

같은 서버(`localhost:8935`)에 TUI 두 개를 차례로 붙여 턴이 도는 같은 Keeper 의 채팅을 열고
창 폭 155·100·60열에서 찍었다. 찍은 날은 2026-11-17 09:2x KST 다.

- `before.txt`: main(`ea0b8d1fd284`)을 빌드한 `masc_tui.exe`
- `after.txt`: 이 층을 빌드한 `masc_tui.exe`

두 파일 모두 대화 아래 구분선과 입력 줄(`>`) 사이의 줄만 담았다.

## 보이는 차이

| | 전 | 후 |
|---|---|---|
| 155열 | 도구 구성 중간(`McpMascKeeperSkill …`)에서 끊긴다. 걸린 시간이 없다 | 세 줄에 모든 항목 |
| 100열 | 런타임 ID 뒤가 없다. 도구 수, 도구 구성, 걸린 시간이 없다 | 네 줄에 모든 항목 |
| 60열 | `새 출력 없음 ·…` 에서 끊긴다. 런타임도 없다 | 일곱 줄에 모든 항목 |
| 이어지는 줄 | 없음 | 머리말 아래로 들여 쓴다 |
| 체크포인트 | 앞 항목에 쉼표로 붙는다 | 다른 항목처럼 ` · ` 로 나뉜 항목 |

## 한계

- 전과 후는 30초쯤 간격으로 찍었고 그 사이 턴이 계속 돌았다. 도구 수(24개 → 33개)와 걸린
  시간이 다른 것은 코드 차이가 아니다.
- 색은 담지 않았다. `capture-pane -e` 로 본 색: 머리말은 굵은 강조색(`1;96`), 단계 항목은
  강조색(`96`), 런타임은 `94`, 도구 수와 걸린 시간은 `95`, ` · ` 는 기본 글자색(팔레트 없는
  tmux 에서 흐린 글자가 그렇게 나온다).
- 기본 보기(Ctrl-F 를 누르지 않음)의 줄은 짧아서 전후 모두 한 줄이다.
- 창 높이에 눌려 `외 N` 으로 줄어드는 경우, 입력 중에 붙는 `Enter:…` 항목, 접힌 줄 수(`+N`)는
  찍지 않았다.
- 뒤쪽 공백은 지웠다.
