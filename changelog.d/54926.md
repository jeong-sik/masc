### Fixed

- An ACP Keeper (Mistral Vibe, Kimi, Antigravity ACP, Muse) is no longer failed for being quiet. `initialize`, `session/new`, `session/load`, `session/resume`, `session/set_*` and `session/prompt` wait for the agent's answer with no silence deadline; they end on the answer, the agent's exit, a cancel, or a protocol error. Before, a quiet `session/prompt` failed with `ACP timeout in session/prompt after 180.0s` and a slow `session/new` or `session/load` with a 30.0s timeout (#54926).
- A request that ends without an answer now says where the agent stopped: `ACP process exited: session/prompt: stdout EOF; last activity: the agent started its own tool call "bash" (in_progress) 212s ago; no MASC tool call running` (#54926).

### Changed

- Operators must delete `timeout-s` and `admission-timeout-s` from every `protocol = "acp"` provider table in `runtime.toml`. A config that still carries either key fails to load and names the key. The setup wizard no longer writes them, and a fusion preset's `timeout_s` now bounds a whole ACP panelist run (#54926).
- Delete the keys before starting the new build. While either key remains, `runtime.toml` as a whole fails to load and names the key. The previous build loads the file without them (it fell back to 180s and 30s), so editing the file first is safe (#54926).
- An agent that stays alive and silent now holds its turn until someone interrupts it: `Ctrl+X` in TUI Keeper Chat, or `POST /api/v1/keepers/turn/interrupt`. The interrupt sends `session/cancel`. A Keeper stop also ends a start that is still waiting for `initialize`, and closes that agent process (#54926).
- A fusion panel group that uses an ACP model is bounded only by its own `timeout_s`. Without one, a silent panelist holds the fusion run until the calling turn is interrupted (#54926).
