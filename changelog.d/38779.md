### Upgrade notes

- A `runtime.toml` whose exact-output lane `slots` name an HTTP runtime on a
  provider without `exact-body-timeout-s` no longer loads. Boot enters model
  setup (`config_invalid`) and a save through the dashboard or the raw config
  API is refused before anything is written; the message names the lane, the
  slot, the provider and the key. Add `exact-body-timeout-s` to every such
  provider before deploying. `cli_slots` are not affected, and neither is a
  deployment whose `AGENT_CORE_MODEL_CATALOG` names a replacement catalog,
  whose `[[targets]]` rows keep their own `body_timeout_s` (#38779).

### Fixed

- An exact-output slot without a whole-request deadline was accepted by
  configuration validation and then refused on every request, falling to
  `cli_slots` with a WARN line that read only
  `wire_admission_rejected:missing_deadline`. The configuration is now refused
  when it is read or saved, and a request that still reaches plan admission
  without a body deadline says which provider lacks it, which key to set, and
  that `connect-timeout-s` ends at the response headers. The evidence JSON
  keeps `"kind": "missing_deadline"` and adds `provider_id` and `detail`. The
  seed `runtime.toml` and the setup wizard now declare `exact-body-timeout-s`
  on every HTTP provider, because `--setup-lanes` can put any of them in an
  exact slot (#38779).
