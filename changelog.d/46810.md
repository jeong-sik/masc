### Fixed

- `tools/recipient_replay` counts a line with an audience kind it does not know, or a `targets` audience with no target, as a line it cannot read and exits 1. A recorded name that two Keepers list is counted as `lookup-failed` and no longer as prose. A Keeper settings folder with no `.toml` file, or a missing file or folder, stops the run with exit 2 and a message. (#46810)

### Internal

- `test_recipient_resolution` now fails for three wrong implementations it used to accept: `resolve` comparing recipients with structural equality instead of the caller's `equal`, `Candidate.of_string` rejecting a name that starts with a digit, and `Candidate.of_string` also accepting characters such as `~` and `%`. A sweep over all 256 bytes pins the name characters. The "too long" case is removed because its stand-in lookup has no length rule, so it checked nothing the "nobody declared" case does not. (#46810)

### Documentation

- `RFC-at-name-resolves-to-declared-recipient` now counts 41 Keeper settings, 36 of them with only their own name. It says that a name of 251 characters or more overflows the file name, that the failing lookup has one caller today (the broadcast, where it is a deferral and not a write error), and that the `Discoverable` candidate leaves out the post's author. Option B no longer says it needs no declaration. (#46810)
