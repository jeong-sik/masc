## 다음 순서와 방향

1. **직접 요청 지속성을 고친다.** 현재 편집자 operation이 terminal checkpoint 오류 뒤 running으로 남아 peer와 새 요청을 막는다. 정상 defer 시 exact checkpoint를 보존하고, 현재처럼 원본이 유실된 경우에는 복구 성공을 꾸미지 않고 권위 있는 실패로 정리해 다음 요청을 진행해야 한다. 이미 완료한 write·Board·peer 효과는 보존한다.
2. **전시 Goal 사람 확인을 기다리며 나머지 협업을 끝낸다.** Goal은 실제 5/5를 통과해 최종 확인 버튼까지 표시됐다. 사람 승인 없이는 완료로 전환하지 않는다. 편집자 직접 이미지 검수와 디자이너 원천 확인 요청은 별도로 남는다.
3. **공동 기억의 정확도를 높인다.** 실제 27B 제안을 편집자와 디자이너가 읽고 인계·정정·동료 검토·다음 계획에 사용했다. 최초 해석 오류와 아직 확인하지 않은 출처를 보존했고, 운영자 요청 흐름을 자발적 채택으로 세지 않는다.
4. **관측 정보를 정확히 설명한다.** Tools 사용/미사용의 분모, SQLite 집계와 별도 JSONL 상태, TUI Skill 사용 범위를 구별하는 수정이 진행 중이다. IDE/LSP/코드 주석·누적 이력은 후속 마일스톤으로 남긴다.
5. **지속성과 다른 과제로 넓힌다.** 자발적 Fusion·Owner 요청·위임·기억 사용, 다양한 비코드 시나리오, 모든 runtime의 10턴 및 1/2/4/24시간 연속성과 자동 failover는 아직 완료로 증명하지 못했다.
