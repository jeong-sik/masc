### Added

- A workspace whose `runtime.toml` has `[browser.live.bidi]` (`firefox`, `profile`, `port`, default 9222) has its Keeper Firefox and BiDi host started by the MASC server when the server starts. It starts only what is missing: no Firefox when the port already answers, no host while one holds the host lock, and no host without an installed launcher. Both run apart from the server, so a restart leaves them up; they write to `.masc/browser-lane/keeper-firefox.log` and `bidi-host.log`. `[browser.live] enabled = false` starts nothing. The dashboard's Browser activity editor reads the table and keeps it. Write the table only after deploying a server that reads it (#42125).
