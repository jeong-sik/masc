### Documentation

- Revise the Draft RFC that keeps Keeper row facts in memory by their
  writers: a reader fills an empty value without taking any lock and
  installs it by compare-and-set, a writer reads every value of its store
  before it changes the file and empties a value when another change came
  first, and the Owner meta read falls back to the file when no Owner holds
  a meta or a meta write ended uncertain. The write function is repaired
  before the first value moves, so that a failed append never reaches the
  file later and every append starts at a line start (#52980, #52974).
  This replaces the fill under the store lock that the first draft
  described. A fill reads through a function that reports failure and
  installs nothing when the read failed, so an unreadable store is not
  kept as "no rows". The row builds its meta from the Owner's value passed
  through the file's own encoder and decoder, which keeps the config
  fields at the values a file read returns today (#53007). Values hang on
  the store's registry entry beside its lock instead of a separately
  composed key, and the write repair states what it guarantees against a
  second process appending to the same file (#52975).
