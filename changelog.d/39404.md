### Fresh state required

- Pre-generation Antigravity managed HOMEs at
  `<base-path>/.masc/official-clients/antigravity/<owner_leaf>/` containing
  `.gemini/antigravity-cli/antigravity-oauth-token` but no `current.json` are
  refused as populated stores without a generation pointer. Stop affected
  Antigravity Keeper and Fusion clients before archiving the whole old managed
  HOME outside the active managed root. Preserve the configured external
  `oauth_source` credential file. With a valid selected source, the next
  admission seeds a fresh generation and session; archived native refresh,
  Keychain and conversation state are not adopted (#39404).

  Archive procedure (tested 2026-09-27 on a fixture tree; stop affected
  Antigravity Keeper and Fusion clients first, and keep the configured
  external `oauth_source` credential file in place):

  ```sh
  BASE=<base-path>  # the workspace base path whose .masc holds the stores
  ROOT="$BASE/.masc/official-clients/antigravity"
  BACKUP="$BASE/.masc/antigravity-archive-$(date +%Y%m%d-%H%M%S)"
  mkdir -p "$BACKUP"
  for store in "$ROOT"/*/; do
    [ -d "$store" ] || continue
    if [ -f "$store/.gemini/antigravity-cli/antigravity-oauth-token" ] \
        && [ ! -f "$store/current.json" ]; then
      mv "$store" "$BACKUP/" && echo "archived $store"
    fi
  done
  ls "$BACKUP"
  ```

  Only stores with a managed token and no `current.json` move; stores that
  already carry a generation pointer stay untouched, and the backup sits
  outside the active managed root.
