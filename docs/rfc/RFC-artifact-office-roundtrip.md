# 아티팩트에서 HWPX·DOCX의 표와 차트를 편집한다

상태: 구현 설계. MASC Task: `task-3689`.

## 문제와 결과

문서 안의 표를 이미지로 바꾸거나 차트를 생략하면 값을 고칠 수 없다.
사용자는 HWPX/DOCX 파일을 가져와 표 셀과 차트 데이터를 수정한 뒤 다시
문서로 내려받기를 요청했다. 새 아티팩트도 같은 형식으로 출력한다.

## 기존 저장과 편집을 유지한다

HTML 원문과 기존 공유 원고가 편집 내용의 정본이다. 문서 변환 때문에
별도의 수정 가능한 JSON 문서나 새 원장을 추가하지 않는다. 가져오기는
게시 전 원고를 만들고, 기존 제목·내용 확인을 거쳐 게시한다.

표는 HTML `table`의 셀, `rowspan`, `colspan`으로 표현한다. 차트는 명시적
`figure data-masc-chart="column|bar|line|pie"` 안의 `figcaption`과 데이터
표로 표현한다. 첫 행은 항목 이름과 계열 이름이고, 다음 행들은 항목과
숫자다. 빈 숫자 셀은 결측치다. 0으로 바꾸지 않는다.

차트의 저장된 숫자는 이 표에만 있다. SVG 미리보기와 Office의 차트
캐시·내장 워크북은 이 표에서 만드는 출력이다. 수정 후 모두 다시 만든다.
빈 셀도 포함한 문장 편집과 원문 편집으로 제목·항목·계열·숫자를 수정한다.
계열의 숫자 형식과 값 축의 숫자 형식, 결측치 표시(gap/zero/connect)는
데이터가 아닌 차트 서식 속성으로 보존한다. 누적·백분율 누적·보조축·조합·
날짜축처럼 이 모델이 표현하지 않는 차트는 가져올 때 명시적으로 거부한다.

## 변환 경계

1. DOCX/HWPX의 본문·표·차트를 읽고 HTML 원고를 만든다. 실행 코드와 외부
   자원을 읽거나 실행하지 않는다. XML namespace와 package 참조를 검사한다.
   압축 입력은 32 MiB, 파트 하나의 확장은 16 MiB, 문서 전체 확장은
   64 MiB까지 읽는다. 이 값은 브라우저 메모리 경계이며 작업 예산이 아니다.
   스트림의 확장 chunk를 누적하기 전에 검사한다. 파트 외부 경로, DTD,
   잘못된 XML과 중복 필수 요소는 거부한다.
   XML은 DOM으로 만들기 전에 `saxes`의 XML 1.0·namespace 검사로 읽는다.
   같은 namespace의 속성이 두 prefix로 겹쳐도 거부한다. DOM 생성기가
   속성을 먼저 덮어쓴 뒤에는 이 모호함을 검사할 수 없기 때문이다.
   기존 개발 의존성의 `saxes@6.0.0`을 직접 의존성으로 고정한다.
2. 지원하는 차트 종류는 column, bar, line, pie다. 종류를 추측하지 않는다.
   모르는 차트나 해석할 수 없는 원본 데이터는 오류로 돌려준다.
   캐시 점은 `idx/ptCount`로 읽어 빈 위치를 보존한다. 내장 워크북이
   연결돼 있으면 범주·계열·값이 캐시와 같은지 확인한다. 오래된 캐시나
   확인할 수 없는 참조는 오류다. 워크북 연결 자체가 없는 HWPX 차트는
   문서에 저장된 native 데이터를 읽는다.
3. DOCX는 기존 변환기에 `docx/charts`를 연결한다. HWPX 어댑터도 같은
   DrawingML 차트 생성기를 재사용하고 HWPX의 본문과 파트 연결을 만든다.
4. 출력은 현재 읽은 게시 버전에 묶는다. 인증·문서·작업 공간이 바뀌면
   이전 변환 결과로 다운로드하지 않는 기존 경계를 유지한다.
5. 가져오기 실패는 이전 원고를 없애지 않는다. 변환 차이와 지원하지 않는
   서식은 게시 전에 보여준다. 파일을 읽었다는 이유로 자동 게시하지 않는다.

## 보존 범위

검사 대상은 본문, 병합 표의 셀 위치·내용, 차트 종류·항목·계열·숫자다.
표준 데이터 구조로 문서 간 이동을 지원한다. 기관 양식의 글꼴, 페이지
나눔, 떠 있는 개체, 서명·매크로 등 전체 문서의 동일성을 약속하지 않는다.
원본 파일을 읽은 뒤에도 사용자의 원본 파일은 변경하지 않는다.

`.doc` 바이너리는 DOCX와 다른 형식이다. 기존 파일을 확장자만 바꿔 받지
않는다. 실제 변환기를 통합·검증하기 전에는 지원 형식으로 표시하지 않는다.

## 확인 방법

- 변환 코드와 독립된 문서 생성기 및 한글 문서에서 표·차트 입력을 만든다.
- DOCX/HWPX 출력 ZIP의 native 표·차트와 내장 데이터를 직접 읽는다.
- 가져오기 → 셀·차트 값 수정 → 재내보내기 → 재가져오기로 값을 비교한다.
- 결측치·0·음수·잘못된 숫자, 병합 셀, 깨진 참조, 지원하지 않는 차트와
  외부 데이터 참조를 확인한다. 실패를 빈 문서로 숨기지 않는다.
- 실제 파일 바이트, Dashboard 동작, 한글·Word의 열기·화면·인쇄는 각각
  별도로 기록한다. 자체 파서의 왕복만으로 Office 호환성을 선언하지 않는다.
