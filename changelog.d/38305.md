### Fixed

- A Keeper whose Librarian stands behind keeps turning instead of being refused every turn (RFC librarian-lifecycle §4.10, rules 1, 2, 3, 5, 6 and 7). A request that opened before this turn's boundary, at the Librarian point or past it, and is refused for size (`refusal_evicts`) is sent once more to the same candidate from the last completed turn boundary, before the tool-result marker resend. `choose_range_start` takes the start the provider last accepted, read from the newest response-observed turn record, and opens there while the Librarian point is behind it, never past this turn's boundary; the forecast passes the same record, so it shows the same start. Such a request reports the new origin `past_librarian_point`, and the refused range's held boundary reports `turn_start_after_librarian_refusal`; the TUI next-request band decodes and names both. `seed_refusal_sequence` is now `turn_boundary_resend_sequence` (#38305).
