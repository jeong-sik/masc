# TUI 화면을 끝까지 쓰기

2026-10-20 운영자가 "공간, 패딩, 가능한 Full Screen 으로 사용하도록" 요청했어요.
이 문서는 그 요청을 세 단계로 나누고, 각 단계의 근거와 바꿀 범위를 적어요.
코드는 단계마다 따로 PR 로 올려요.

## 지금 상태

220×60 터미널에서 실제 서버에 붙여 잰 값이에요(2026-10-20, Dashboard).

| 항목 | 값 |
|---|---|
| 본문 줄 | 56줄 중 14줄 사용 |
| 글자 폭 | 줄 평균 61칸, 최대 219칸(구분선) |
| Activity 패널 | 숨김(Dashboard 만 기본으로 숨김) |

Work, Usage, Board 는 잴 때 서버가 느려서 `not loaded yet` 로 찍혔어요. 이 화면들의
값은 아직 없어요.

화면 위아래의 빈 줄도 있어요. `box_top` 과 `box_bottom` 이 줄바꿈만 그려서,
화면마다 내용 없는 줄이 2개 있어요.

## 먼저 풀어야 할 충돌

`LAYOUT-LANGUAGE.md` 는 2026-10-07 밀도 선택을 "지금처럼 여유 있게"로 적어 뒀어요.
같은 문서에 "넓은 터미널은 내용에 공간을 더 줄 뿐, 패널이나 지표를 추가할 이유가
아니다"도 있었어요. 이번 요청은 이 중 두 번째와 부딪혀요.

- 여유(줄 사이 간격, 제목 위아래 간격)는 그대로 둬요.
- "넓은 터미널에서 패널을 추가하지 않는다" 규칙은 1단계에서 바꿨어요.
- 화면 위 빈 줄은 일부러 둔 간격이라서, 이번 요청으로도 없애지 않아요(아래 2단계 보류).

## 1단계: Dashboard 에도 Activity 패널

다른 화면은 narrow 패널로 시작하는데 Dashboard 만 숨겨져 있었어요. 기본값을 맞췄어요
(#44140). `Ctrl-L` 로 숨기면 그 선택이 따라와요.

## 2단계 (보류): 빈 줄 회수

바꾸려던 것: 전체 화면 위·아래의 빈 줄 2개를 없애고 본문이 쓰게 하는 것.
2026-10-20 코드를 읽어 보니 이득에 비해 위험이 커서 보류했어요.

- **위 빈 줄은 일부러 둔 간격이에요.** `pane_surface_header` 주석에 "띠와 제목 사이의 간격
  줄이고, 로스터 옆에서는 박스 윗변이 같은 줄에 온다"고 적혀 있어요. 사이드바 머리글이 이
  줄에 맞춰져 있어서, 없애면 제목과 머리글이 한 줄씩 어긋나요.
- **아래 빈 줄은 1줄이에요.** 60줄 터미널에서 1.7%예요.
- **숫자 5 가 세 가지 뜻으로 섞여 있어요.** 화면 틀 5줄, 겹창 테두리 5줄, 사이드바 구조
  (머리 3줄, 끝 1줄, 여유 1줄)가 우연히 모두 5 예요. `surface_chrome` 계약을 거치지 않고
  숫자 5 를 직접 쓰는 곳도 있어서(`render_config.ml` 의 `- 5`) grep 으로 다 찾을 수 없어요.
- **Code 와 Resources 화면은 `box_bottom` 과 `framed_bottom` 을 섞어 써요.** "혼자 있을 때와
  둘로 나뉠 때 줄 수가 같다"는 약속이 깨질 수 있어요.

다시 하려면 화면 틀 상수를 화면, 겹창, 사이드바 세 가지로 나눠서 모든 사용처가 어느 쪽인지
컴파일러가 강제하게 한 다음, 값을 바꿔요. 그 전에는 건드리지 않아요.

## 2단계: 카드 격자

운영자가 세 화면을 보여 주며 "보고 좀 배우자"고 했어요(2026-10-20). Usage 대시보드(번호가
붙은 카드를 2열로 늘어놓은 화면), Codex CLI, Claude Code 예요.

| 본 것 | masc 에 옮길 것 |
|---|---|
| Usage 대시보드는 카드마다 제목이 윗변에 들어가 있고 2열로 화면 폭을 끝까지 써요 | 독립된 읽기 여러 개를 보여 주는 화면은 카드 격자로 그린다. 이번 PR 에서 Dashboard 에 적용 |
| 카드 안에 여백이 넉넉한데도 화면이 비어 보이지 않아요. 모든 카드에 내용(차트)이 있어서예요 | 카드는 내용 높이에 맞추고, 두 열은 아래쪽을 같은 줄에 맞춘다. 빈 상자를 화면 끝까지 늘리지 않는다 |
| Codex 는 긴 출력을 `+114 lines (^t to expand)` 로 접고 줄 수와 키를 알려 줘요 | 카드 안에서 넘친 줄은 `+N more` 로 개수를 적는다. 키 안내는 아직 없다 |
| Codex 는 입력 줄과 선택에 배경 띠를 깔아요. 테두리가 없어요 | 선택은 이미 띠로 그린다. 바꿀 것 없음 |
| Usage 대시보드는 아래에 키 안내를 두 줄로 놓고 키는 굵게, 설명은 흐리게 써요 | 아직 안 옮겼다. 푸터는 한 줄이고 좁으면 `…` 로 잘린다 |

masc Usage 화면은 아직 옮기지 않았어요. 왼쪽 한 열 목록이라 220칸에서 오른쪽 절반이
비어요. 계정마다 5h, 7d 막대가 있어서 카드로 옮기기 가장 좋아요.

`LAYOUT-LANGUAGE.md` 는 "전체 화면 내용은 박스가 필요 없다"고 했어요. 한 화면이 독립된
읽기를 나란히 보여 줄 때만 카드를 쓰도록 예외를 적었어요.

### Dashboard 의 카드

터미널 안쪽 폭이 약 90칸 이상이고 줄이 충분할 때만 카드로 그려요. 아니면 예전 줄 모양
그대로예요. 카드가 줄을 더 쓰기 때문이에요(테두리 4줄과 간격 1줄, 예전은 제목 2줄과 빈 줄 1줄).

- 왼쪽: "Needs your decision", 그 아래 "Continue". 오른쪽: "Status"(Health, Work, Candle).
- 선택한 결정의 전체 문장을 카드 안에 줄바꿈해서 보여줘요. 목록 줄은 한 줄이라 길면 `…`
  로 잘렸어요.
- 결정 목록 창(`home_decision_window`)은 예전 모양과 같은 계산을 써요. 키 처리와 화면이 같은
  창을 보게 하려는 거예요. 창이 꽉 찰 만큼 결정이 많으면 카드가 줄을 못 구해서 예전 줄 모양으로
  돌아가요.

## 3단계: 다른 화면에 적용

Usage 를 카드 격자로 옮기고, 같은 카드를 쓰는 화면을 더 찾아요. 카드 틀(`Masc_tui_card`)은
이미 있으니 화면마다 어떤 읽기를 한 카드로 묶을지만 정하면 돼요.
