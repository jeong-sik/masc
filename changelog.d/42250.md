### Upgrade notes

- After deploying this, restart a running `masc-tui`. The connection list's `bidiHost` report gains a `keeper` field, and a TUI built before this reads the new report as one it cannot read, so its Browser Lane picker says only that until it restarts (#42250).

### Added

- The connection list's `bidiHost` report says who starts the Keeper Firefox and its BiDi host: `keeper` is `masc_starts` with the configured port, profile and MASC's last start record, or `lane_off`, `not_configured` or `not_known`. Where MASC starts them, the TUI's Browser Lane picker shows that MASC does, on which port and profile, in place of the attach command; after a host that left or was refused a session on MASC's port it says MASC restarts that Firefox only when MASC's record shows MASC started it, and that the operator quits any other first; and it shows MASC's last failed start under the same rule as `masc doctor`. With the live lane off it says MASC starts nothing, and with no `[browser.live.bidi]` that the table lets MASC start both (#42250).
