### Added

- The declaration a person's Keeper is created with is one reviewed value now (`Person_keeper_declaration`): `activation_mode = "on_demand"`, `tools.masc_enabled = false`, and the shipped default sandbox profile, image and network mode. It writes no file and changes no route; a test hands the rendered bytes to the loader the engine uses, so the values cannot drift from what the engine accepts (RFC a-persons-keeper-runs-on-the-engine, S2 / stack A3-2 slice 1) (#54257).

- A person's Keeper declaration can be written from a `base_path` alone (`Person_keeper_declaration.commit`), because the multi-account server holds no workspace state and cannot call the `Workspace.config` writer. The bytes are validated with the engine's loader before anything is written, the file is replaced atomically and read back, a retry of the same creation request answers `Already_present` instead of rewriting, a different declaration already on disk is refused unless the caller asks to replace it, and an engine name that is not a single path component is refused before the path is built. No route calls it yet (slice 2 of A3-2) (#54257).
