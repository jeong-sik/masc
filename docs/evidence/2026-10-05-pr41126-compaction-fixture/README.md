# UID-independent optional-compaction fixture

Published #41126 head 4fc810b43a2654107e35aa3d3d107234434e4ae9 was verified OPEN and fetched before work. Comment4179135310 correctly identifies that chmod0o500 does not prevent atomic writes as UID0. The repository's existing Fs_compat regression documents this. These actual executions ran as UID502; no sudo or root-container execution occurred.

An immutable per-Store optional callback, constructible only through For_testing.create, controls exactly the optional cold journal rewrite after normal durable journal/blob verification. The normal constructor retains the existing writer. No global hook or Sampling consumer signature is added. The fixture reopens a cold Store and calls the public Sampling.retained_receipts consumer. Its callback checks the exact journal path and that the compaction proposal preserves every original field except the inline duplicate, then returns a deterministic Error. Both repeated cold reads must reach that boundary while the durable journal retains its complete original outcome bytes.

Meaningful RED left the callback read but deliberately unwired at the real compaction boundary, using the original writer: two ordering cases failed with expected2 callback attempts vs actual0; nine remaining cases passed. This is explicit callback-not-reached RED, not an original permission failure reproduced as root. GREEN connects the scoped callback and passes all11 cases. Original 4MiB full-answer, canonical/fallback/missing placements, both reference orders, aggregate allowance, per-journal bound, failed verification charge and canonical inode assertions remain. The temporary unwired branch does not remain in final source.

This is focused receipt/fault-boundary proof, not root-container, full regression, provider, release or TerminalBench proof.
