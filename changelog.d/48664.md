### Documentation

- An RFC (Draft) proposes that each TUI domain module apply its own async answers: the module keeps its `msg` type, an `apply` that performs no IO and returns what is left to do, and the classifiers the protocol asks for, while request functions take a `deliver` for their own domain's answers. It measures how tied each domain is to `bin/masc_tui.ml` and plans Code as the first layer. No code changes (#48664).
