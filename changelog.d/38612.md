### Fixed

- A board posts or comments file the server could not read in full is no longer rewritten from memory. When `board_posts.jsonl` (or the comments file) held a row the loader could not decode, memory kept only the rows before it, and the next flush, post update or post delete replaced the file with that partial snapshot, deleting the damaged row and every row after it. Every posts and comments snapshot write now goes through one function per file that refuses, with an `Io_error` and a `persist_errors` count, while that file's last load failed; a refused flush stays scheduled, and a delete is refused before it changes memory. New posts and comments are still appended (#38612).
