# 콘솔 틀 — 다시 하는 로그아웃, 실패마다 새 알림, 머리줄 (2026-11-12)

L3c 가 콘솔 틀(#51635)을 처음 실제 정책 아래에서 그렸을 때 보인 것(`console/README.md` 의 "콘솔 틀에서 보인 것")과 로그아웃 흐름을 고친 층의 기록이에요. 재는 값과 브라우저는 위 폴더 README 의 "방법" 절과 같아요.

## 방법

- 바이너리. L3c 의 `5a767ce08174` 에서 빌드했어요(sha256 앞 12자리 `4840339f479d`). 이 층은 서버 소스를 바꾸지 않아요.
- bundle 둘. 같은 바이너리로 임시 다계정 설치를 띄우고 `MASC_ASSETS_DIR` 만 바꿨어요. `index.html` 은 둘 다 760 B 예요.
  - 전: L3c 체크아웃의 `assets/dashboard/`. 콘솔 script 26,211 B, sheet 333 B.
  - 후: 이 층의 소스로 빌드한 것. 콘솔 script 28,368 B, sheet 546 B.
- 콘솔 상태(`harness/console-layer.sh`). L3c 와 같은 방법에 상태 하나를 더했어요. 세션 경로와 whoami 가 서로 다른 사람을 답하는 경우예요(`console_account_changed`). 수치는 `before-measure.json`, `after-measure.json` 이에요.
- 틀과 흐름(`harness/console-frame.sh` → `harness/console-frame.mjs`). console-layer.sh 가 저장한 실제 서버의 답 위에서, 대역(`harness/console-mock.mjs`)이 세션 경로만 답해요. 수치는 `before-frame.json`, `after-frame.json` 이에요.
  - 대역에 더한 것: 다른 탭에서 다시 로그인한 것처럼 세션의 CSRF token 을 바꾸기(`/__rotate`), 다른 사람의 세션으로 바꾸기(`/__rotate?user=…`), 세션 경로의 답을 붙잡아 두기(`/__hold`, `/__release`), whoami 만 다른 사람을 답하기(`account_changed`).
  - 대역의 로그아웃은 세션의 token 이 아니면 403 을 줘요. 문장은 서버의 것(`lib/auth/authz_browser_request.ml`)과 같아요.
  - 머리줄은 폭 1548, 1280, 320px 에서 쟀어요. 1280px 에서는 브라우저 기본 글자 크기를 20px, 24px 로 바꿔서도 쟀어요(`Page.setFontSizes`). 세션을 읽는 동안(답을 붙잡아 둔 채)과 로그인한 뒤를 각각 읽어요.
  - 단추는 focus 를 둔 뒤 Enter 로 눌러요. 누르고 500ms 뒤에 읽어요. 알림이 새 요소인지는 앞서 읽은 알림에 표시를 남겨 확인해요. 누른 뒤 머리줄에 로그아웃 단추가 없으면 다시 누르지 않아요.
- 측정 스크립트에서 바꾼 것(`harness/ux-measure3.mjs`). 콘솔이 준비됐다고 보는 때를 "status 줄이 없어졌을 때"에서 "누를 단추가 그려졌을 때"로 바꿨어요. 이 층의 콘솔은 화면마다 status 줄을 하나 둬요. 옛 판정은 실패 화면을 끝없이 기다려요.
- 운영 중인 설치는 쓰지 않았어요. 화면의 id 는 전부 지어낸 값이에요.

다시 재려면 `axe.min.js`(axe-core 4.14.0)를 `harness/` 안에 두고 아래를 돌려요. `UX_SPACE` 는 브라우저 작업 공간의 이름이에요. 첫 줄은 포트 셋, 둘째 줄은 하나를 써요.

```sh
UX_SPACE="<작업 공간>" sh harness/console-layer.sh <masc 바이너리> <label> <출력 폴더> <빈 포트> <assets>
UX_SPACE="<작업 공간>" sh harness/console-frame.sh <출력 폴더>/run/files <label> <출력 폴더> <빈 포트>
```

## 로그아웃과 다시 읽기

| 흐름 | 전 | 후 |
|---|---|---|
| 서버가 로그아웃을 두 번 거절(503) | 두 번째 알림의 문구가 첫 알림과 같아요. 요청은 로그아웃 둘이에요. | 두 번째 알림 끝에 "2번 시도했어요." 가 붙어요. 거절될 때마다 세션을 다시 읽어요. 요청은 로그아웃, 세션, 로그아웃, 세션이에요. |
| 다른 탭에서 같은 사람이 다시 로그인한 뒤 로그아웃 | 옛 token 으로 보내 403 이에요. 다시 눌러도 옛 token 이라 또 403 이에요. 로그아웃할 수 없어요. | 403 뒤 세션을 다시 읽고 새 token 으로 한 번 더 보내요. 로그아웃되고 로그인 화면(`/`)으로 가요. |
| 다른 사람이 로그인한 뒤 로그아웃 | 위와 같아요(403 둘). | 403 뒤 세션을 다시 읽어요. 다른 사람이면 더 보내지 않고 화면에 남아요. "다른 탭에서 계정이 바뀌었어요" 알림과 "지금 계정 불러오기" 단추가 보이고, 로그아웃 단추는 없어져요. 다른 사람의 세션은 끝내지 않아요. 요청은 로그아웃, 세션이에요. |
| 세션 읽기가 두 번 실패(503) | 두 번째 알림이 첫 알림과 같은 요소이고 문구도 같아요. | 두 번째 알림은 새 요소이고 "2번 시도했어요." 가 붙어요. |

- 로그아웃 알림은 전후 모두 누를 때마다 새 요소예요. 보내는 동안 알림을 내렸다가 다시 그리기 때문이에요. 후에는 실패 횟수를 알림의 key 로도 써서, 그리는 때와 상관없이 새 요소가 돼요.
- 알림이 새 요소면 화면 낭독기는 `role=alert` 를 다시 읽어요. 소리로 확인하지는 않았어요.
- focus. 첫 읽기가 끝나면 전후 모두 `<body>` 에 있어요(사람이 아직 아무것도 누르지 않았어요). 로그아웃이나 다시 시도를 누른 뒤에는 누른 단추에 남아요. 후에 누른 단추가 화면에서 사라지면(다른 사람의 세션을 찾았을 때) 제목 "내 계정" 으로 가요.
- 캡처: `after-sign_out_refused_twice.png`(두 번째 거절 뒤).

## 시험이 붙드는 것

`dashboard/src/accounts/console.test.ts`(vitest, happy-dom, jest-axe)가 상태 전이와 접근성 규칙을 봐요. 각 시험은 대역이 답을 정해 두지 않은 요청이 없었는지도 확인해요. 브라우저 측정에 없는 경우도 봐요: 로그아웃에 답이 없거나 답을 읽을 수 없으면 세션과 화면을 그대로 두고 알려요. 로그인 화면으로 가지 않아요.

- 못 잡은 둘은 문구와 배치예요. 이 저장소는 화면 문구·배치를 시험으로 붙들지 않아요. 위 브라우저 측정이 봐요(알림 문구, 링크 높이 23 → 44px).
- 로그아웃 실패 알림의 key 를 뺀 것은 브라우저에서는 차이가 없어요. 보내는 동안 알림을 내렸다가, 답이 오기 전에 그 화면을 그리기 때문이에요. 시험의 대역은 화면을 그리기 전에 답해요. 그러면 key 가 없을 때 예전 알림이 남아요. key 는 그리는 때와 상관없이 새 알림을 만들어서 남겼고, 이 사본은 잡혀야 하는 쪽으로 분류했어요.

## 확인하지 않은 것

- 화면 낭독기로 듣는 소리. 알림을 새 요소로 만드는 것까지만 봤어요.
- 실제 서버의 CSRF 거절. 대역이 서버의 문장으로 흉내 냈어요.
- 답이 없거나 읽을 수 없는 로그아웃을 브라우저에서 보기. 시험만 봤어요.
- 실제 GitHub 로그인 뒤의 콘솔. 시험용 OAuth App 이 있어야 해요.
- 브라우저 확대(zoom). 기본 글자 크기만 바꿨어요.
- 다른 브라우저 엔진(WebKit, Gecko).
