### Fixed

- The `/login` account email is display data again: a record that cannot be
  written no longer refuses a native sign-in with 503; it is logged, the
  earlier record is removed, and a record directory setup refuses to write
  reads as unreadable, so an earlier email never shows as current (#39657).
- One email row the TUI cannot read, or an inventory without a readable email
  list, no longer blanks the `/login` provider list: that row says it could
  not be read, and rows for no listed provider are counted in the notice
  (#39657).
- The installer's sign-ins for a declared Codex, Claude Code or Muse Code
  account home keep the account's email record the way `/login` does: the
  account reads as unfinished while the client runs and names its email once
  the client exits successfully (#39657).
- A login email record written by another schema version reads as absent
  instead of unreadable (#39657).

### Changed

- `masc runtime-muse-login` is now `masc runtime-account-login --client
  codex|claude|muse`, and the installer runs it for every declared account
  home; the child gets the environment `/login` gives that client (#39657).
