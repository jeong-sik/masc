## 다음 순서와 방향

1. **현재 전시 출판을 끝까지 연결한다.** 파일 전달·해시 확인·Board의 장애 보고는 실측했다. 다음은 공식 클라이언트 이미지 분석과 PDF 원본 검사다. PDF 수정은 PR #35398, head 4c31b4b4ce로 올라갔고 대상 CI #34688239966을 시작했다. 실제 Poppler 검사에서 원본 3페이지와 기존 PNG 바이트가 일치했지만 OCaml 통합과 실제 Goal 재검증은 아직 남았다. 공식 클라이언트 이미지 분석은 별도 worktree에서 구현 중이다. 원래 Goal의 5개 기준을 유지한다.
2. **검증과 사람 확인을 분리한다.** 새 CI 바이너리에서 원래 PDF를 읽고 판정해야 한다. 현재 브라우저는 실제 `실행 중 / 검증 · 반증됨`, PDF 실패 사유와 run ID를 보여준다. 사람 확인 버튼은 없으며, 아직 완료를 요청할 단계가 아니다.
3. **실제 공동 기억을 후속 작업에 쓴다.** 27B의 24출처 제안을 검토·정정하고 Keeper가 실제 작업에 재사용하는지 확인한다. 초안 저장과 재시작 보존만으로 기억 완성을 선언하지 않는다.
4. **같은 작업을 UI까지 연결한다.** 통계·설정·Tools 원문·파일·diff·기억을 이 협업 실행과 대조한다. 화면 구현, fixture 검사, 실제 API 검사, 배포를 구별한다. IDE/LSP/코드 주석·누적 이력은 별도 후속 마일스톤으로 남긴다.
5. **한 시나리오를 닫은 뒤 넓힌다.** 자발적 Fusion·Owner 요청·위임·기억 사용, 다른 비코드 시나리오, 모든 runtime의 10턴 및 1/2/4/24시간 연속성과 자동 failover는 아직 증명하지 못했다.

현재 우선순위는 전시 출판의 남은 두 검증 경로다. 독립적인 UI 개선은 보존하고, 이번 완료 판정의 범위를 늘리지 않는다. CI를 기다리는 동안 다음 독립 작업을 진행한다.
