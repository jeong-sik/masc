# Direct operation Gate continuation

A direct Keeper tool can create a durable Gate request while the model continues independent work in that attempt. At the actual yield boundary this change parks the original operation against the exact retained checkpoint and the producer's typed approval identity. The Owner releases its slot. A pending approval does not make the operation claimable.

The existing approval store supplies approval or denial. Before requeueing, the continuation validates the original operation scope and retained input history against the current canonical checkpoint. It restores only the original execution scope, preserving newer conversation and other scopes. If the current history cannot establish that binding, the request remains pending for reconciliation; the host does not roll back the Keeper's context.

Approved host replay uses the existing one-shot grant and durable artifact receipt. That evidence is admitted to the canonical checkpoint before the model continues. Denial is admitted as authoritative input without executing the effect. The original user input, task, attachments and continuation channel remain owned by the same operation. Pending attempts write tool evidence only; the final assistant provenance slot remains available for the resumed answer.

## Validation boundary

The added production-fixture cases exercise WebSearch's real typed Gate producer, the durable approval store, Owner claims, original input retention, newer canonical history, approved replay evidence admission and authoritative denial. Existing direct-operation tests cover Owner restart and transcript final-slot separation. No local build was run. Source parsing and `git diff --check` are source checks, not compilation or behavior proof. CI and installed-runtime proof remain pending.

Ask continuation is a separate pending slice. This change does not establish that a model completed the original task, and does not claim deployed Gate continuity until an exact candidate is exercised.
