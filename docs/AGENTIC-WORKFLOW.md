# MASC 에이전틱 개발 워크플로

2026-09-30 운영자 지시. MASC 저장소와 그 작업용 checkout/worktree에 적용한다.
다른 프로젝트의 PR·CI 정책에는 적용하지 않는다.
`docs/constitution.xml`의 `execution_protocol`과 이 문서가 개발 절차의 정본이다.

1. **Stacked PR만 작성한다.** 스택의 최하단 PR은 기준 브랜치를 base로,
   상위 PR은 바로 아래 PR의 head 브랜치를 base로 둔다. 변경 범위와 스택 순서를 명시한다.
2. **자동 CI를 돌리지 않는다.** PR 생성·push·Ready 전환·일정 실행을 이유로
   CI를 시작하지 않는다. 에이전트가 수동 dispatch로 매 PR의 자동 CI를 재현해서도 안 된다.
3. **CI 게이트는 최소한으로 유지한다.** 필요한 검사는 명시적으로 실행하고,
   기능 작업이 CI 감시·반복 조회·재실행을 기다리게 만들지 않는다.
4. **기능·논리·코드 청결도·여러 관점의 코드 리뷰를 한다.** 실제 diff와 호출 경로,
   상태·실패 처리·경계를 검토한다. 리뷰어를 붙이는 것으로 작성자의 직접 검토를 대체하지 않는다.
5. **미해결 P0·P1·P2가 없으면 APPROVE한다.** 판정은 검토한 정확한 head에 묶고,
   발견 사항·대응·남은 검증 범위를 기록한다. CI를 돌리지 않았다는 이유로 소스 리뷰 승인을 미루지 않는다.
6. **P3는 모아서 처리한다.** 후속 목록에 남기고 주제별로 묶어 별도 스택에서 정리한다.
   P3만으로 승인과 기능 진행을 막지 않는다. 심각도는 실제 영향에 대한 리뷰 판단으로 정한다.
7. **Release/Tag 단계 전에는 명시적으로 선택한 최소 검사만 실행한다.** 짧고 가벼운
   검사를 우선 고른다. “2분 정도”는 검사 규모를 설명하는 예시이며 강제 종료 시간이나
   성공·실패 판정 기준이 아니다. 검사 결과는 실제 완료 상태로 판단한다.
8. **스택 최하단 PR에서 Core 빌드만 확인한다.** 일반 PR마다 전체 빌드·테스트·lint·
   Dashboard·TLA·컨테이너·PTY를 반복하지 않는다. 상위 PR의 기본 게이트는 코드 리뷰다.
9. **Release/Tag PR (`release/vX.Y.Z`)에서 Full CI Cycle을 실행한다.** 누적 변경의 전체 빌드,
   테스트와 관련 통합·런타임 검증을 릴리스 후보에서 수행한다.
10. **기능 진행과 CI 청결도 개선을 분리한다.** 기능은 기능 스택에서 이어가고,
    느린 검사·중복 검사·불안정한 fixture·CI 인프라는 별도 CI 개선 스택에서 처리한다.
11. **휴리스틱·숫자 맞추기 CI를 만들지 않는다.** 문구·줄 수·파일 수·임의 점수·
    바이트 수·특정 함수 이름의 존재로 정상 변경을 막지 않는다. 컴파일·타입·실제 기능 실패와
    권위 있는 프로토콜·보안·자원 계약을 확인하는 검증을 사용한다.

리뷰 APPROVE, Core 빌드 성공, Full CI 성공, 실제 기능 동작은 서로 다른 증거다.
실행하지 않은 검사에 성공 판정이나 run ID를 만들지 않는다. 상위 PR의 소스 승인으로
누적 코드가 실행 검증됐다고 주장하지 않는다. P3를 숨기거나 근거 없이 낮은 심각도로 바꾸지 않는다.

승인은 병합·배포 허가와 별개다. 실제 병합은 맡겨진 범위와 현재 적용된 저장소 보호 설정을
따른다. 기존 guard·required-check 설정이 이 정책과 충돌하면 CI 개선 스택에서 맞춘다.
충돌 때문에 매 PR에 긴 CI를 다시 시작하거나 관리자 우회를 하지 않는다.

이 문서는 작업 지침이다. GitHub Actions trigger·branch protection·guard 구현의
실제 상태는 해당 설정과 소스에서 별도로 확인한다.
