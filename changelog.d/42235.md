### Added

- Each start of the Keeper Firefox and its BiDi host that ends, at a server start or for a Keeper's hover or drag, is written to `.masc/browser-lane/keeper-firefox-start.json` with when it ended, the port and profile it was for, and what was started or why no connection was listed. Where `runtime.toml` has `[browser.live.bidi]` and the live lane is on, `masc doctor`, the connection list, a Keeper's rejection and the setup status now say that MASC starts what is not running of the Keeper Firefox and its host at the next server start or the next hover or drag, in place of the operator's steps, and name the last start's failure for that port and profile when it is newer than what the host record says since. With `[browser.live] enabled = false` they say first that MASC starts nothing; with no table they add that writing one makes MASC start both. `masc doctor` uses `runtime.toml`'s browser tables only when the whole file loads (#42235).
