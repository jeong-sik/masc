### Added

- `masc doctor` has a `browser_bidi_host` line that says what the BiDi browser host's own record says: whether a host runs and is attached, when and why the last one ended, whether Firefox may still hold its session, and how one is attached. It reads the record from disk, so it answers with no server running. A workspace with no browser lane installed and no record has no such line (#41971).
- `GET /api/v1/dashboard/browser-lane/clients` returns `bidiHost` beside `clients`: the host's `state`, its `record`, the command that starts a host as `attach` (`launcher` and `arguments`), and the same sentence as `message`. A server also says whether its own client list has the host the record names (#41971).
- A Keeper whose hover or drag is refused as `live_transport_unsupported` with no BiDi connection to offer gets the same `bidiHost` in the answer, to pass on to the operator (#41971).
