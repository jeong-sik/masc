# Logging-consistency allowlist (consumed by scripts/ci/check-logging-consistency.sh)
#
# Each non-comment, non-blank line is a path PREFIX. A logging violation is
# suppressed when its file path starts with one of these prefixes. Use a
# trailing "/" to allowlist a whole directory; use a full filename to
# allowlist one file.
#
# Allowlisting is for logging that CANNOT route through the canonical
# Log.<Module>.{info,warn,error,debug,routine} surface. Every entry below has a
# stated reason. Do not add entries to silence a migrate-able call site — fix
# the call site instead. See docs/LOGGING.md.

# --- The Log system itself ---
# log.ml emits the structured records; it cannot log through itself. Its
# Printf.eprintf calls are the terminal stderr sink + operator warnings for
# unparsable env vars / file-sink rotation failures.
lib/masc_log/

# --- Pre-runtime / low-level filesystem fallback ---
# fs_compat runs below the logging stack (masc_log depends on fs_compat, not the
# reverse). Its eprintf are last-resort diagnostics when even the ring buffer
# may be unavailable.
lib/fs_compat/

# --- Server boot guards + FATAL handlers + CLI subcommands (bin/main_eio.ml) ---
# eprintf here are either (a) pre-Log-init base-path guards ("[FATAL] --base-path
# points to the server's own source repo", "[FATAL] Server refused to start"),
# (b) FATAL exception handlers for Out_of_memory / Stack_overflow that must not
# allocate through the logging stack, or (c) the `login` / `init` CLI
# subcommands whose stderr/stdout is user-facing CLI output, not server logs.
# The legacy_stderr "[FATAL] Another MASC server ... already running" lines are
# the RFC-0079 raw-passthrough bridge (embedded [FATAL] prefix; migrating would
# double-prefix the operator-visible message).
bin/main_eio.ml

# --- Standalone CLI tools (not the server runtime) ---
# These are one-shot CLI binaries; their stdout/stderr is the tool's user
# interface, not structured server logging.
bin/masc_trace.ml
bin/masc_tui_loader.ml
bin/masc_cost.ml

# --- RFC-0079 legacy raw-stderr bridge (embedded [LEVEL] prefix) ---
# Log.legacy_stderr / Log.legacy_traceln deliberately emit a raw, unprefixed
# stderr line AND mirror it into the ring with a Legacy_stderr / Legacy_traceln
# source tag (read back by dashboard/src/api/schemas/logs.ts). Every call site
# embeds its own [FATAL] / [WARN] / [DEBUG] marker in the message body, so
# migrating to Log.<Module>.<lvl> would (a) double-prefix the message and
# (b) drop the Legacy_* source classification. They stay as the documented
# bridge. (lib/server/server_startup_takeover.ml is allowlisted whole because
# its only non-canonical logging is these legacy_stderr lines.)
lib/server/server_startup_takeover.ml
lib/backend/backend.ml
lib/workspace/workspace_query.ml
lib/mcp_server_eio_resource.ml

# --- Dynamic component (runtime variable) ---
# Log.warn ~ctx:context / Log.info ~ctx:context use a runtime-computed component
# string; there is no static module that preserves the per-call value. Migrating
# would drop the dynamic component from operator output.
lib/config_dir_resolver/config_dir_resolver.ml

# --- Runtime-computed component on Log.emit ---
# agent_core_log_bridge.ml uses Log.emit with ~module_name:("agent_core:" ^
# record.module_name) — the component is built at runtime from a per-record
# value, so no static module preserves it. The top-level Log.emit is required
# here to carry the dynamic component string.
# (keeper_event_bridge.ml previously appeared here for ~module_name:"agent_core:event";
#  that is a static literal and is now the Agent_core_event module — a module name
#  string may contain a colon even though the OCaml identifier cannot.)

# --- Operator CLI harnesses (bin/) ---
# These binaries are run by a person at a terminal and their stdout/stderr is
# the answer to the command, not a server record. fusion_run prints four arms
# side by side "so a human can judge"; the probe CLI is the operator entry
# point to the RFC-0374 probe lane; checkpoint purge and the preflight helper
# are offline one-shots. Routing any of it through the structured sink would
# move the output away from the person who asked for it.
bin/fusion_run.ml
bin/keeper_capability_probe_cli.ml
bin/masc_lane_cli_probe.ml
bin/masc_checkpoint_purge.ml
bin/deployment_preflight_helper.ml
# masc_lane_cli_probe measures a declared cli_slots runtime against a lane's
# real requirement; its usage/unknown-lane/init-failure diagnostics and
# per-trial verdicts are the measurement the operator asked for, not server
# records.
bin/masc_lane_cli_probe.ml
# masc_http_probe times the TUI's HTTP client with no TUI around it
# (RFC-0429 §3.0). Its per-trial readings and its usage diagnostics are the
# measurement the operator asked for; sending them to the log file would
# hide them from the terminal that ran the probe.
bin/masc_http_probe.ml

# --- Before the screen, and before the log ---
# masc_tui writes to stderr while deciding where stderr goes; saying it
# through the sink it is still redirecting is a mirror drawing over itself.
# main_stdio_eio's one eprintf is a pre-init FATAL on the stdio transport,
# where stdout is the protocol and cannot carry diagnostics.
bin/masc_tui.ml
bin/main_stdio_eio.ml

# --- Below the logging stack ---
# runtime_log_sink is where Log.emit lands; it cannot emit through itself.
# fd_accountant reports file-descriptor exhaustion, the condition that stops
# the sink from opening anything. server_base_path_guard refuses a bad
# --base-path before Log is initialised.
lib/runtime_log_sink.ml
lib/fd_accountant/
lib/server/server_base_path_guard.ml

# --- Not in this process ---
# exec_shim is a static binary that runs on the remote endpoint. There is no
# masc logging stack there; stderr is what the frame carries back.
lib/exec_shim/exec_shim.ml

# --- gh subcommand output, in a module that is otherwise server code ---
# print_observation and run_cli_{login,status,logout} print what `masc keeper
# github ...` was asked for. The rest of this 1,200-line module runs inside
# the server, and a prefix entry cannot say "only the last hundred lines", so
# this exemption is wider than the four functions that earn it. Splitting the
# subcommands into their own module is the fix; see the follow-up issue.
lib/keeper/keeper_github_identity.ml
