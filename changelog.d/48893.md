### Fixed

- The MCP GET, AG-UI and presence SSE streams and the `tools/call` POST SSE
  stream now wait for each frame to reach the socket. A client that stops
  reading is closed once its queue fills or a frame waits 90 seconds; before,
  its stream stayed open and the unread bytes kept growing in memory. A close
  from another domain (the queue overflow hook, the maintenance sweep,
  shutdown) no longer touches the HTTP writer; the connection's own fiber
  closes it. The prime and replay frames go out from that fiber too, so the
  request handler no longer waits on a client that reads nothing (#48893).
- When the server runtime is unavailable, these GET streams answer 200 and
  end at once instead of staying open with nothing to send (#48893).

### Removed

- The `event: evicted` frame write in `stop_sse_session_evict`, which never
  reached a client because the evicted connection had already been stopped.
  The eviction lifecycle events are unchanged (#48870, #48893).
