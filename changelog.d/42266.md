### Added

- The fenced late-approval journal gets a defined exit: `POST /api/v1/keepers/hitl/late-approval-restore` re-runs the boot rebind-and-restore without restarting the server, the health `keeper_hitl_gate` section reports `late_approval_journal_bytes`/`rows`, and a fenced-ack answer names the matching repair instead of "append failed" (#42266).
  Usage:
  - What it does: a failed journal read/append fences all late-answer writes and acks so no answer is recorded whose commit receipt is unknown; the restore endpoint is the way out that keeps the server running.
  - Turn it on: nothing to enable — the endpoint and the health fields ship with the server (CanAdmin token required).
  - When it runs: only when an operator calls it. The server never restores on its own, and the journal fence never lifts by retrying an ask. A successful restore answers `200 {"ok": true}`; `503 journal_unavailable` means storage is still unreadable; `503 journal_corrupt` means a corrupt row still fails validation and the journal file must be moved aside first.
  - Try it: `curl -X POST -H "Authorization: Bearer $MASC_ADMIN_TOKEN" http://127.0.0.1:8080/api/v1/keepers/hitl/late-approval-restore`
  - Turn it off / revert: nothing to turn off; the endpoint is safe to call any time. Reverting the feature is reverting #42266.
  - Experiment marker: none — production default path, no opt-in flag.
  - Full procedure (corrupt-row move-aside steps and what is lost): `docs/design/2026-10-07-hitl-approval-visibility-durability-design.md` §D4a.
