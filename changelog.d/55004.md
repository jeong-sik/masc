### Fresh state required

- A Keeper's `<base-path>/.masc/config/keepers/<keeper>.compaction.db` and `<keeper>.canonical-turns.db` written by an earlier build are refused as `Schema_not_current`: both stores now record compaction coverage by Keeper turn atom and carry a layout version, and nothing is converted. While such a file remains, that Keeper commits no compaction epoch, logs a warning at each compaction attempt and each time its tool list is built, its history is not cut after an anchor, and the tool-blob sweep stops with an error on the old `.compaction.db`; the server keeps running. For fresh state, stop the server and delete both files with any `-wal`, `-shm` and `-journal` beside them, for every Keeper. This discards the Keeper's compaction anchors, archived atoms and cross-runtime handoff rows; checkpoint history is untouched, and the next compaction starts at epoch 1. An ACP Keeper's first rollover or overflow retry after the deletion summarizes the checkpoint history's turns before the rows committed since, and the fresh session starts from that summary and the most recent rows. `validate-stores` does not scan these stores. This change performs no installed-state removal (#55004).

### Performance

- Reading a Keeper's history after its compaction anchor, which runs each time the tool list is built, reads message metadata once instead of serializing and SHA-256 hashing every atom after the anchor's index (#55004).

### Fixed

- A compaction anchor committed from the list the ACP runtime rebuilds from canonical turns now cuts the checkpoint history after the covered turn; before, it never matched and nothing was cut (#55004).
- Committing the same eviction again, or a later prefix that reaches atoms already archived past the boundary, adds no epoch and archives no atom twice (#55004).
- A compaction summary takes only turns past the furthest point either kind of list has summarized, so an ACP Keeper's summary no longer repeats earlier turns or names an older request as the latest. A turn whose canonical row is missing, or still carries its ACP turn id, can appear in it twice; when every row the summary holds still carries its ACP turn id, an older request can still be named the latest (#55026) (#55004).
- An ACP context-overflow retry compacts the same list a rollover does, the one its fresh session starts from; before, it always compacted the message history (#55004).
- Before any compaction summary applies to an ACP Keeper, such as after the fresh state above, a rollover or overflow retry first summarizes the message history's turns before the first turn with a canonical row, then compacts the rows as it does once a summary applies. When no row's turn is in the history, it summarizes all of the history, and the fresh session starts from that summary and every row. Before, those turns were neither summarized nor sent, and with no row the most recent quarter of the history was lost too (#55004).

### Removed

- The microcompaction and `compact_and_project` pipeline, which no runtime path called (#55004).
