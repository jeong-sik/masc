### Changed

- A comment records the `audience` its write boundary derived, the way a post does, and the Keeper board scan replays it instead of reading the comment text again. `Board.comment` has an optional `audience`, `comment_to_yojson` writes it when present, and the persisted-row decoder accepts it. A comment written before this change has none, and the scan treats it as `Audience_not_recorded`. `Keeper_board_audience.of_comment_text` and `Invalid_board_audience` are removed. A build from before this change rejects a comment row that has an `audience` as an invalid persisted row. (#46841)

### Documentation

- `RFC-at-name-resolves-to-declared-recipient` D4 says a comment records its audience and the scan reads no comment text. (#46841)
