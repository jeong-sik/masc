# 좁고 낮은 창의 슬래시 메뉴: 고치기 전후

채팅 아래 정보 묶음이 줄을 넘겨 쓰게 된 뒤(RFC `tui-one-screen-grammar` §5.5), 60x24 창에서
`/` 메뉴가 후보를 두 개만 보였다. 묶음이 대화 세 줄만 남기고 줄을 다 가져갔기 때문이다. 이
층은 메뉴가 열려 있는 동안 메뉴가 쓸 줄을 먼저 남긴다.

## 무엇을 찍었나

같은 서버(`localhost:8935`)에 TUI 두 개를 차례로 붙여 같은 Keeper 의 채팅을 60열 24줄 창에서
열었다. 메뉴가 닫힌 화면을 찍고, `/` 를 쳐서 메뉴가 열린 화면을 찍었다. 찍은 뒤 `/` 는
지웠고 아무것도 보내지 않았다. 찍은 날은 2026-11-17 10:1x KST 다.

- `before.txt`: 아래층(턴 진행 줄 층)을 빌드한 `masc_tui.exe`
- `after.txt`: 이 층을 빌드한 `masc_tui.exe`

대화 본문은 뺐고 그 자리에 줄 수만 적었다(`(대화 4줄)`). 위쪽 제목 줄들도 뺐다.

## 보이는 차이

| | 전 | 후 |
|---|---|---|
| 메뉴 후보(49개 중) | 2개 | 8개(메뉴 한 쪽 전부) |
| 메뉴가 열린 동안 키퍼 상태 묶음 | 여섯 줄 그대로 | 한 줄, 끝에 `외 11` |
| 메뉴가 열린 동안 예약 줄 | 그대로 | 없음 |
| 메뉴가 열린 동안 대화 | 4줄 | 4줄 |
| 메뉴를 닫은 뒤 | — | 묶음이 여섯 줄로 돌아온다(닫힌 화면과 같다) |

## 한계

- 이 Keeper 는 예약이 없어 예약 줄이 `Job · 관측된 예약 없음 · F9` 한 줄이다. 예약 묶음이
  여러 줄일 때와, 창이 더 낮아 키퍼 상태 묶음이 예약 줄의 첫 줄까지 가져가던 경우는 찍지
  않았다. 줄을 나누는 순서는 `test/test_tui_message_layout.ml` 의 「rows around the
  composer」 세 경우가 확인한다.
- 창이 메뉴 한 쪽(8줄)과 대화 세 줄을 함께 담지 못할 만큼 낮으면 후보는 여전히 8개보다
  적다. 그 높이에서는 고치기 전에도 그랬다.
- 색은 담지 않았다. 뒤쪽 공백은 지웠다.

## 다시 만들기

`docs/evidence/tui-chat-facts-keeper-status-block-20261117/README.md` 의 순서로 채팅을 연
뒤:

```bash
tmux -L cap resize-window -t cap -x 60 -y 24
tmux -L cap send-keys -t cap /        # 메뉴 열기
tmux -L cap capture-pane -t cap -p
tmux -L cap send-keys -t cap BSpace   # 초안 지우기
```
