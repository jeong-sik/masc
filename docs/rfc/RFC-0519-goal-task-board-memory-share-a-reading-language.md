# RFC-0519: 목표·작업·게시판·기억은 같은 읽기 순서와 언어를 쓴다

사용자 요청: 네 화면의 목록·상세를 미니멀하게 정리하고, 필요한 정보와 한영 혼용을 바로잡는다. [소스 조사와 참고 원칙](../research/2026-11-09-goal-task-board-memory-reading.md)을 구현 단위보다 먼저 남긴다. wire·저장 형식·서버 lifecycle은 바꾸지 않는다. 기존 Task #50671과 Goal #50688의 요청·성공 조건 미리보기 및 연결 작업 관측 범위는 재구현하지 않고 UI stack #50678 위에서 잇는다.

## 1. 공통 읽기 순서

목록은 항목을 고르는 곳이다. 제목/주장, 현재 상태, 담당/작성자 또는 Keeper를 먼저 둔다. 현재 필터·정렬과 조회 실패/부분 범위는 표시하되 정상 조회를 설명하는 문장, 선택 제목의 반복, 내부 ID 열은 줄인다.

상세는 내용을 판단하는 곳이다. 원래 내용·현재 상태와 이유·근거·다음 행동을 앞에 둔다. 같은 제목과 상태를 여러 구획에서 반복하지 않는다. 식별자·출처 주소·절대 시각·기술 진단은 본문 뒤나 기존 상세 경로에 둔다. 경고·확인 대상·변경 결과는 접어서 숨기지 않는다. 부가 정보에 접근할 기존 스크롤/키 경로는 남긴다.

화면마다 동작이 다른 키를 억지로 같게 만들지 않는다. 이미 있는 선택 identity, 목록 순서, 현재 펼침/스크롤 의도를 지킨다. 넓은 창과 좁은 창의 높이 산정·페이지 이동·그림은 같은 projection을 사용한다. 셀 폭은 display width로 센다.

## 2. 언어

기존 한국어/영어 설정을 따른다. 한국어 크롬의 표준 낱말은 목표·작업·게시판·기억, 상태·담당·작성자·근거·기록·다음 행동, 조회 중·미조회·조회 실패·일부 관측·이전 관측이다. 각각의 도메인 상태를 이 일반 낱말로 합치지 않는다. 예를 들어 작업의 검증 대기와 목표의 최종 확인 대기는 다르다.

앱이 만든 라벨·typed 상태 표시·키 도움말은 선택한 한 언어로 표시한다. 원문과 ID·링크·경로·프로그램 이름은 번역하지 않는다. wire/오류 문자열을 검색해서 화면 상태를 결정하지 않는다. 새 언어 설정이나 범용 번역 framework는 만들지 않는다. worker에서 준비한 문서는 언어를 입력 identity에 포함해, 언어 전환 뒤 이전 언어 결과를 새 결과로 사용하지 않는다.

## 3. 화면별 적용

- 목표: 기존 요청·성공 조건 미리보기를 유지하고 다음 행동과 판정 이유를 ID보다 먼저 둔다. 상세는 성공 조건과 판정 근거를 기술 메타데이터·Candle 내역보다 먼저 읽게 한다. 필터 밖 링크는 다른 목표를 강조하지 않는다. 연결 작업 수는 작업 관측 범위를 따른다.
- 작업: 기존 요청 중심 목록을 유지한다. 상세는 원래 요청과 현재 상태를 먼저 두고 session/operation/cycles 같은 진단은 뒤로 옮긴다. 준비 문서와 이력·키 도움말 모두 언어 설정을 받는다.
- 게시판: 선택 제목·ID·구분선 반복을 줄이고 본문과 댓글 공간을 늘린다. 종료 결론과 읽기 실패는 남긴다. post kind를 공개 범위로 추정하지 않는다.
- 기억: 사실의 주장을 장식 열보다 먼저 확보한다. 좁은 폭에서는 경로·긴 category를 먼저 줄인다. category 수는 알려진 빈 저장소의 0과 읽기 실패를 구별하고, 전체 사실 창에도 갱신 실패와 이전 관측을 전달한다. 나이·저장 시각·출처 무효화·미읽은 턴·브리핑 상태는 서로 다른 값이다.

## 4. 보존할 권한과 증거

목표 완료 확인은 현재 증거의 마지막 물리 행을 실제 제시한 frame 이후에만 가능하다. 마지막 행을 봤다는 관측을 모든 행을 읽었다는 증명으로 바꾸지 않는다. 증거·workspace·server instance·credential 결속과 Candle 명시적 이동을 유지한다.

Task ID와 원본 요청, Board post/comment focus와 서버 접근 권한, Memory의 선택 Keeper·ordinary/source별 실패·현재/이전 snapshot 구분을 유지한다. 표시 축약이 새로운 조회·변경 권한을 주지 않는다.

## 5. 구현과 검증

문서와 구현 층을 나눈다. 구현은 공통 언어/키, 목표·작업, 게시판·기억으로 ownership을 나누어 진행한다. 공개 helper 인자와 그 호출부는 같은 층에 묶어 중간 PR도 타입이 맞게 유지한다. 각 변경을 독립 소스 검토한다. typed 선택·조회 범위·문서 identity를 검증하며 화면 문구·배치·행 순서 assertion은 만들지 않는다. 로컬 Dune와 CI 시점은 헌법을 따른다. 실제 후보 화면 대조와 소스 미리보기를 구분하고, 수행하지 않은 빌드·전체 회귀·설치·배포를 성공이라고 부르지 않는다.
