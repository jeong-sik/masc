### Performance

- The verification dashboard (`/api/v1/verification/requests`, `/api/v1/verification/summary` and the proof compose) keeps each request's listing row for the version of its file, so a listing stats every request file but reads and parses only the ones that changed since the last listing, plus any it could not read last time. On the live store of 1,938 requests (69 MB), a listing after the first took 733 ms (median of nine), most of it JSON parsing on the server's main domain, and now takes 4.5 ms; the kept rows hold 7.4 MB (#39938).

### Fixed

- A verification request whose row cannot be built, such as one whose creation time `gmtime` cannot represent, is listed as unreadable with the reason instead of failing the whole listing with a 500. The summary counts it as unreadable, and the awaiting-operator view names it as unresolved, as it already did for a request the schema cannot read (#39938).
