# TUI 채팅 위계 재설계 — 디자인

- 날짜: 2026-09-17
- 상태: 방향 승인됨 (사용자 "go"), 구현 계획 전
- 참고 자료 둘:
  1. Kimi Code 에이전트 패널 스크린샷 — 그룹 헤더 한 줄만 bold, 트리 가지(`│ ─`)로 소속,
     메타데이터는 dim, 상태어만 끝에 의미 색
  2. [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design) —
     "삭제가 최선", accent 1–2개, 목표 밀도 4/10, "같은 상자의 반복은 위계를 지운다"

## 1. 문제

채팅 화면에서 위계가 읽히지 않는다. PTY 실측(100x30, `chat_clarity` fixture) 기준:

```
── 2026-08-22 · 06:00 ────────────────────────────────   ← 화면 최고 휘도 (cyan+bold)
   ╭ 06:41 ◆ SKILL   │ 전달됨, 도구 씀 · ci-red-attribution · 1 action
   │                 │ ↳ masc_fusion · observed action
   │                 │ proof · turn=… · use=… ·
   │                 │ runtime=… · rev=…
   ╰       ■ TOOLS   │ ✗ masc_fusion · 1200ms
   ╭ 22:34 ▶ YOU       ship the release                  ← 말인데 default 색, 묻힘
   ╰       ● alpha     reply-ship the release
```

원인은 코드에 있다:

- `Chat_theme.body` (`bin/masc_tui_ansi.ml:486`)가 말(User/Inbound/Keeper)·일(Tool)·
  배경 소식(Journal)·명령 응답(Local) 본문을 전부 `Ansi.reset`으로 그린다.
  **말·일·증거가 같은 무게**라 위계 레버가 배지 색뿐이다.
- 날짜 레일이 bright cyan+bold 전폭으로 화면에서 가장 밝은 슬롯을 쓴다 — 크롬이
  콘텐츠보다 시끄럽다.
- 배지 색이 4–5종(cyan·green·magenta·blue) 경쟁한다 — accent 가 많아 신호가 지워진다.
- 스킬 1건에 proof·runtime·rev 증거 4줄. 위 8월 블록 5줄의 실제 정보는
  "스킬 하나 씀, 도구 하나 실패"다.

## 2. 원칙 — 세 축을 분리한다

지금은 색이 누구(파란 키퍼)·상태(초록 성공)·위계(밝은 날짜 레일)를 뒤섞어 말한다.

- **모양 = 무엇인가** — 마크·레일. 기존 기호 체계 그대로, 새 기호 0개.
- **색 = 누구인가 / 어떤 상태인가** — 화자 색, ok/warn/bad. 유지.
- **밝기 = 위계** — 회수해서 위계 전용으로. 밝은 것은 화면에 1–2개뿐.

`NO_COLOR` 규칙은 그대로 지켜진다: 정체성은 언제나 마크가 답하고, 밝기는 위계만 말한다.

## 3. 위계 표

| L | 내용 | 지금 | 이후 |
|---|---|---|---|
| 0 | 지금 진행 중인 일 | 레일 표시만 | 화면 유일의 bright accent. 새 색을 도입하지 않고 기존 진행 표시의 색을 유지한 채 무게(bright/bold)만 올린다. 끝나면 접히며 accent 도 사라짐 |
| 1 | 말 (▶ ◀ ●) | 본문 `reset` | **본문 full fg 유지** — 프로즈는 터미널 전경이라는 기존 결정이 맞다. 나머지를 낮춰서 상대적으로 뜨게 한다 |
| 2 | 시간 골격 (날짜 레일·시계) | 날짜 cyan+bold 전폭 | **recede** (`Theme.recede`, 대비 바닥 3.0 유지). hairline 자체는 스크롤 방향타로 남긴다 |
| 3 | 일 (도구·스킬·생각) | 본문 `reset`, 배지 초록/마젠타, 항목당 1줄+증거 | **턴당 한 줄로 접힘**, 본문 dim, 배지는 상태색(ok/warn/bad)만 남기고 레인 색(마젠타 등)은 폐기. §4 |
| 4 | 배경 소식 (저널·남의 방송) | 본문 `reset`, ◈ cyan, diff fence 노출 | 본문 dim, ◈ 배지도 recede(모양이 정체성을 답). 요약 투영은 기존 `Memory_summary` 장치를 쓰고 새 접힘 장치를 만들지 않는다. diff 는 `/memory`·Ctrl-N 뒤 |
| 5 | 증거 (proof·runtime·rev·↳ observed action) | 기본 밀도에서 4줄 | 기본에서 없음. **기존 Ctrl-D 축이 펼침** |
| 6 | 크롬 (탭·브레드크럼·풋터) | 현재 탭 cyan + 브레드크럼 bold | 현재 탭만 색, 나머지 recede |

## 4. 접힘 디자인 (핵심 변경)

**끝난 일은 한 줄, 실패는 선다, 진행 중은 펼친다.**

1. **성공한 일은 턴당 한 줄로 체인**한다:

   ```
   ├ ◆ ci-red-attribution · 씀, 1 action · ■ fusion · 0.8s
   ```

   전체 dim. 항목마다 마크가 인라인으로 붙어 레인 정체성을 답한다. 폭을 넘기면
   기존 본문 wrap 과 같은 방식으로 `│` 레일 아래 다음 줄로 넘긴다.

2. **실패한 일은 체인에서 빼서 독립 줄에 둔다**:

   ```
   ├ ■ ✗ masc_fusion · 1.2s
   ```

   `✗` 가 화면 유일의 red 로 혼자 선다. 성공이 배경으로 가라앉는 만큼 실패가 도드라진다.

3. **진행 중인 일은 펼쳐진 채** 유지하고, 화면 유일의 bright accent 를 준다.
   완료되는 순간 접혀 한 줄이 된다 — 일하는 동안은 보이다가, 끝나면 각주가 된다.

4. **proof·runtime·rev·↳ observed action·diff fence 는 기본 밀도에서 그리지 않는다.**
   펼침은 기존 Ctrl-D 축(`msg_tool_visibility`, `bin/masc_tui.ml:1574`)을 쓴다.
   새 키나 새 모드를 만들지 않는다.

5. **`SKILL`/`TOOLS` 라벨 단어를 지운다.** `◆`/`■` 마크가 이미 레인을 말한다.
   "같은 값을 반복해서 그리지 않는다"(이어서 말하면 이름을 지운다)는 기존 규칙의
   연장이다. 라벨 칸이 비는 만큼 접힌 줄에 이름이 더 들어간다.

6. **스킬의 "전달돼서 쓰였다" 사실은 남는다.** `bin/masc_tui_render_chat.ml:1191`
   주석의 제약: 옛날에 스킬을 접었더니 "전달만 됨 vs 실제로 쓰임"이 키 한 번 뒤로
   숨어 운영자가 스킬이 일했는지 알 수 없었다. 접힌 줄은 `◆`(썼음 마크) +
   상태어(`씀`) + `1 action` 으로 그 사실을 유지한다. 이름만 남기는 접힘은 금지.

레일 기호는 기존 표로 다 말할 수 있다: 턴 안의 접힌 일 줄은 `├`(Rail_does),
턴 전체가 일 하나인 접힌 줄은 `╶`(Rail_stands).

### Before → After (실측 캡처와 같은 내용)

```
[before — 5줄]                                [after — 2줄]
╭ 06:41 ◆ SKILL   │ 전달됨, 도구 씀 · …        ╶ ◆ ci-red-attribution · 씀, 1 action
│                 │ ↳ masc_fusion · …          ╶ ■ ✗ masc_fusion · 1.2s
│                 │ proof · turn=… · use=…
│                 │ runtime=… · rev=…
╰       ■ TOOLS   │ ✗ masc_fusion · 1200ms
```

라이브 턴의 생애:

```
╭ 22:36 ▶ YOU       방금 올린 거 CI 왜 빨개?
├ 22:36 ■ gh run view · running…        ← 펼쳐짐, 유일한 bright
(완료 후)
╭ 22:36 ▶ YOU       방금 올린 거 CI 왜 빨개?
├       ╶ ■ gh run view · 2.1s          ← 접힘, dim
╰ 22:37 ● alpha     lint 하나 죽었어. 고칠까?
```

## 5. 바뀌지 않는 것

- 마크 표, 레일 의미 체계 (한 기호 한 질문), 채운/빈 짝 규칙
- 왼쪽 여백 순서와 칸 폭 (레일 5 + 시계 6 + 마크/라벨 10 + 인용 막대 + 본문)
- 좁은 폭에서 레일부터 버리는 순서
- Ctrl-F 밀도 3단계, Ctrl-D 펼침 축, 컴포저·풋터 키 힌트
- 다른 페인 (Board·Lanes·Overview·Memory 등)

## 6. 가장자리 경우

- **좁은 폭**: 기존 규칙대로 레일을 먼저 버린다. 접힌 줄의 최소 생존은 마크+이름.
- **NO_COLOR**: 접힌 체인에서도 항목마다 마크가 인라인으로 붙어 색 없이 레인이
  구분된다. 실패는 `✗` 모양이 답한다.
- **긴 이름**: 기존 `fit_middle` 규칙을 그대로 쓴다. 마크는 줄이는 범위 밖.
- **턴 중간에 끼어드는 저널·남의 broadcast**: 기존 규칙(괄호를 끊지 않고 지나감)을
  따른다. 접힌 일 줄도 같은 취급.
- **라이브→완료 전환**: 줄 수가 줄며 뷰포트가 점프하지 않는지 PTY 실측으로 확인한다.
- **히스토리(과거 로드분)**: 항상 접힌 상태로 렌더한다.
- **상태어 한 단어 유지**: 접힌 체인은 `씀, 1 action` 처럼 상태어를 남긴다
  (마크만 믿고 다 지우는 과감한 안은 채택하지 않음 — 1191 주석의 실패 모드로
  되돌아갈 위험).

## 7. 검증

- `tui-pty-scenario` 스킬로 실측한다. 코드를 읽어 판정하지 않는다. 확인할 장면:
  기본 화면 / 라이브 턴 진행→완료 접힘 / 실패 독립 줄 / `NO_COLOR` / 좁은 폭.
- `SKILL`·`TOOLS` 라벨 삭제와 문구 변화로 `test/*.py` 의 needle(기다리는 바이트열)을
  같이 고친다. 렌더 파일만 고친 PR 의 초록은 산책의 증거가 아니다.
- 렌더 폭이 바뀌면 Linux 에서 해당 가족을 돌린다 (`gh workflow run test.yml -f suite=…`).
- 증거: 전후 PTY 캡처(보이는 텍스트 + SGR 요약)를 PR 에 첨부한다 (constitution 의
  evidence 요구).

## 9. 성공 조건

- 같은 내용의 화면에서 말(대화)이 가장 먼저 읽힌다 — 전후 캡처 비교로 판정한다.
- 8월 히스토리 블록 같은 경우가 5줄 → ≤2줄로 준다.

- `NO_COLOR` 에서 모든 상태를 식별할 수 있다.
- needle 갱신 후 기존 PTY 스위트가 통과한다.
